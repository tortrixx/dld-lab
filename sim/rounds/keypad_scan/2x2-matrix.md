# keypad_scan · 2×2 极性交叉矩阵（r03~r06 汇总）

> 本文件是 r03~r06 四轮的**总说明**：四格如何一一对应、每格结论、以及本版修掉的
> 「假绿」问题（独立审计 `docs/审查-B1仿真断言-2026-09-24.md` §7 P0-1）。
> 机读记录见 `r03.json ~ r06.json`；每轮人读表见 `r03.md ~ r06.md`。

## 1. 为什么要有这张矩阵（修掉的假绿）

上一版 `sim/tb_keypad_scan.py` 把**板子模型绑死在代码假设上**：

```python
IDLE = 1 - KP_ACTIVE      # ← 缺陷：板子"行空闲电平"跟着 RTL 的 KP_ACTIVE 走
```

于是"高有效"那一轮（`KP_ACTIVE='1'`）把未按下的行驱成 **0** —— 那是**下拉板**，
而真实板是**上拉**（无键时行读到 `'1'`，见 `ERRORS.md` **ERR-0035**）。
**"高有效 RTL + 上拉真实板"这个真正会误报的组合从来没被跑到**，
"两种极性都测"给了虚假信心。

本版把两件事**彻底解耦**：

| 变量 | 含义 | 来源 |
|---|---|---|
| `KP_ACTIVE` | **代码假设**的"按下"电平（只经 `RTL_PATCHES` 翻 RTL 常量） | `docs/04` §3.3 / ERR-0035 |
| `board_idle` | **板子模型**：行空闲电平（`kp_row=0xF` 上拉 / `0x0` 下拉） | ERR-0035 实测 |

## 2. 四格 ↔ 轮次

| # | 轮次 | `KP_ACTIVE`（代码假设） | 板子模型（行空闲） | 文档预测 | **实测结论** |
|---|---|---|---|---|---|
| 1 | **r03** | `'0'` 低有效（当前默认） | **高**（上拉，**真实板**） | 不得误报 | ✅ **不误报**；真实按键正常（键号 2、消抖 83.75ms、脉宽 1 clk） |
| 2 | **r04** | `'0'` 低有效 | 低（下拉板） | 不得误报 | ❌ **实测误报！** 幻影键号 = **4**（与文档预测不符 —— 见 §4） |
| 3 | **r05** | `'1'` 高有效（**旧错法**） | **高**（上拉，**真实板**） | **必须复现 ERR-0035** | ⭐ **如期复现**：幻影键号 = **4 =「开始」** |
| 4 | **r06** | `'1'` 高有效 | 低（下拉板） | 不误报 | ✅ **不误报**；真实按键正常 |

> **匹配/失配**：行空闲电平 **==** 代码假设的"按下"电平 ⇒ 无键也会被读成"按下" ⇒ **必误报**。
> 对角格（1、4）匹配 → 不误报；反对角格（2、3）失配 → 误报。
> **这正是 2×2 交叉的意义**：它把"两种极性"与"两种板子"真正叉开，
> 而不是像上一版那样只测同一条对角线。

## 3. 第 3 格（r05）—— ERR-0035 复现（本任务的关键）

- **现象**：无键窗口内 `o_key_code` **持续非 0**（非 0 次数 = 309/312），
  **第 1 个轮末（tick 3）即锁存键号 `0x04`**；整段（含后续"按键"阶段）恒为 4。
- **幻影键号 = 4**，核对 `rtl/game_fsm.vhd:155` `when "00100" => s_act_start` ——
  **键 4 就是「开始」**。这解释了整机为何被踢出自检态
  （`game_fsm` 全局边「任意状态按开始 → `S_PREVIEW`」，ERR-0035 步骤 4/5）。
- **`o_key_press` 在误报时的行为**：**全程恰好 1 个脉冲**，出现在**第 21 个轮末
  （3350 ns = 21 轮 × 4ms ≈ 84ms）**，宽度 **1 个 clk**；首个脉冲后 `r_down` 闸门封门，
  **不再重复**（并非"周期性脉冲" —— 幻影键号是**持续**的，脉冲却只有一次）。
- **传导**：一次「开始」脉冲即可触发 `game_fsm` 全局边 → 自检态被踢出。
  所以"只有 1 个脉冲"也足以造成现场事故。

## 4. ⚠️ 第 2 格（r04）—— 文档预测被实测推翻（新发现）

- **任务表 / `docs/04` §3.3 预测**：低有效对"上拉板"与"下拉板"**两种都成立** → 第 2 格不得误报。
- **实测**：低有效 RTL 在**下拉板**（行空闲 = 0）上**同样误报**，幻影键号同样是 **4**，
  `o_key_press` 行为与第 3 格完全一致（1 个脉冲 @3350ns）。
- **根因**（纯逻辑，不依赖 RTL 常量）：RTL 判据是 `i_kp_row(r) = KP_ACTIVE`。
  下拉板无键时行 = **0**，而 `KP_ACTIVE = '0'` ⇒ **每行都被读成"按下"**。
  低有效只在"行空闲电平 ≠ 按下电平"（即上拉板）时才能区分按下与否 ——
  `docs/04` §3.3 说的"靠'选中列低、其余列高'区分"，但 **RTL 只读行、不读列**，
  所以对下拉板并不成立。
- **结论**：低有效**并非**对两种板子都成立；它**恰好**对真实板（上拉）成立。
  本格断言按"任务表/文档预测"写成"不得误报"，因此**如实判红**——
  这不是 RTL 缺陷（真实板是上拉，RTL 正确），而是**文档论断需要订正**。

## 5. "真实按键"断言结果（匹配板：r03 / r06）

| 断言 | r03（低有效+上拉） | r06（高有效+下拉） |
|---|---|---|
| 按住 KEY2 → 第 1 个轮末 `o_key_code = 2`、按住期恒 2 | ✅ | ✅ |
| `o_key_press` 恰 1 个脉冲，落在第 21 个轮末、距按下沿 80~87ms | ✅ 83.75ms | ✅ 83.75ms |
| 脉冲宽度 = 恰好 1 个 clk（`CLAUDE.md` §10.1） | ✅ | ✅ |
| 松开后 `o_key_code` 归 0、无新脉冲 | ✅ | ✅ |

## 6. 复现方式

```bash
# 轮次号自动递增：同一命令连跑 4 次即得 r03~r06（格号由轮次号推出）
python scripts/sim.py run keypad_scan     # → r03 格1
python scripts/sim.py run keypad_scan     # → r04 格2
python scripts/sim.py run keypad_scan     # → r05 格3
python scripts/sim.py run keypad_scan     # → r06 格4

# 或显式指定格号（调试用）
KP_CELL=3 python scripts/sim.py run keypad_scan
```
