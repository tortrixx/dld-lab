## 1. 文档约定

### 1.1 每个模块的固定小节

本文档对 12 个 RTL 模块逐个给出：

| 小节 | 内容 |
|---|---|

### 1.2 编码规范（全项目统一）

```vhdl
-- 库：只用 IEEE 标准库，禁用 std_logic_unsigned / std_logic_arith
library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.NUMERIC_STD.ALL;
use work.puzzle_pkg.ALL;

entity xxx is
    port (
        clk    : in  std_logic;
        rst    : in  std_logic;
        i_data : in  std_logic_vector(7 downto 0);
        o_data : out std_logic_vector(7 downto 0)
    );
end entity;

architecture rtl of xxx is
    signal r_cnt : unsigned(7 downto 0);   -- 寄存器用 r_ 前缀
    signal s_next : unsigned(7 downto 0);  -- 组合中间量用 s_ 前缀
begin
    -- 时序进程：全设计只有这一种时钟进程写法
    process (clk)
    begin
        if rising_edge(clk) then
            if rst = '1' then
                r_cnt <= (others => '0');
            elsif i_en = '1' then
                r_cnt <= s_next;
            end if;
        end if;
    end process;
end architecture;
```

**硬性规则**：

| # | 规则 | 理由 |
|---|---|---|
| 1 | **一个文件一个实体**，文件名 = 实体名 = `.vhd` 小写 | 老师照框图抽查 |
| 2 | 时序进程**只用 `rising_edge(clk)`**，不用 `clk'event and clk='1'` | 后者在 VHDL-93 中对 `std_logic` 有歧义 |
| 3 | 组合进程**所有分支必须赋值**，或开头给默认值 | 防 latch |
| 4 | **禁用 `std_logic_unsigned` / `std_logic_arith`** | 非标准库，Quartus 9.1 下与 `numeric_std` 冲突 |
| 5 | 端口用 `i_` / `o_` 前缀；信号 `s_`；寄存器 `r_`；常量全大写 | 一眼分清方向与是否寄存 |
| 6 | **注释全中文**，每个文件头部写：职责 / 框图位置 / 对应需求编号 | 评分项⑧ |
| 7 | 实体名**不得与 Quartus 原语重名**（`exp` `abs` `add` `sub` `mult` `div` `lpm_*` `alt*`） | 见 `ERRORS.md` ERR-0001 |

## 2. `puzzle_pkg` —— 全局常量与掩码运算包

### 2.1 职责

全局常量、掩码运算纯函数、位序约定。**不是实体，是 VHDL 包。**

> ⚠️ **本包不含任何信号与进程**，只有 `constant` 与 `function`。
> 所有函数都是**纯组合**（无信号赋值、无 wait），可被综合器展开为逻辑。

### 2.2 为什么要有这个包

项目中至少有 3 个模块（`puzzle_ctrl` / `disp_format` / 仿真脚本）需要知道
"位 0 对应点阵哪个物理像素"。如果每个模块各自解释一遍，**只要有一处理解不同，
点阵就会出现镜像或上下颠倒**，而且这种 bug 在上板前完全看不出来。

把这个约定**收敛到唯一一个文件**，是全项目最重要的一条可维护性措施。

### 2.3 位序的三次一致性检查 ⭐

| 层次 | 表现 |
|---|---|
| **硬件** | COLR0 接点阵**最左列**（手册：22、21、16、15、14、13、12、11 脚） |
| **本包** | 位号 = `8×行 + 列`（即 `bit(0,0) = 0`），**bit0 = 第 0 行第 0 列 = 物理左上角**<br>（2026-09-18 起正文直接写算式：`bitidx()` 已随 §5.0 的 7 个无调用点声明一并删除） |
| **驱动** | `dot_matrix_scan` 把 `mask(8*r+7 downto 8*r)` **直接**赋给 `dot_colr` |
| **结果** | 三层天然对齐，**全链路零次位序翻转** |

### 2.4 函数实现要点

```vhdl
-- 逐行右移一列：★ 绝不能写成 m sll 1 之类的整体移位
function shift_right_col(m : std_logic_vector(63 downto 0))
    return std_logic_vector is
    variable v : std_logic_vector(63 downto 0);
begin
    for r in 0 to 7 loop
        -- 取第 r 行低 7 位，后面补 '0'（补在最右，即列号最大处）
        v(8*r+7 downto 8*r) := m(8*r+6 downto 8*r) & '0';
    end loop;
    return v;
end function;
```

> **反例**：若写成 `m(62 downto 0) & '0'`（整体左移 1 位），
> 第 r 行最右列（bit `8r+7`）会被移到 bit `8r+8`，
> 也就是**变成了第 r+1 行的最左列**——像素"穿墙"到下一行开头。
> 这正是要求 7 要防的边界错误。

**`popcount` 的实现**（用于调试与自检，不参与主逻辑）：

```vhdl
function popcount(m : std_logic_vector(63 downto 0)) return integer is
    variable n : integer range 0 to 64 := 0;   -- ★ 必须带 range，否则综合成 32 位
begin
    for i in 0 to 63 loop
        if m(i) = '1' then n := n + 1; end if;
    end loop;
    return n;
end function;
```

> ⚠️ **位号换算一律按位切片写，且"凡整数必带 `range`"**（2026-09-18 审查补，报告 `puzzle_pkg-3`）：
> `bitidx(r,c) = 8*r + c`、`row_of(idx) = idx/8`、`col_of(idx) = idx mod 8`、
> `row_mask(m,r) = m(8*r+7 downto 8*r)` 是**约定**（`docs/01` §5.0），
> 实现时直接写**位切片/位选**（`m(8*r+7 downto 8*r)`、`1 sll c`），
> **不要落成整数除、模网络** —— `CLAUDE.md` §10.2 ④："本项目应当完全不出现 `*` `/` `mod`"。
> 若将来真要新增一个**参与算术的子程序，形参必须带 `range`**（硬约束 9）：
> 正例见 §10.4 的 `place(rel, ar, ac)`，其中 `ar, ac : integer range 0 to 7` ——
> 裸 `integer` 的形参会让加法器展开成 **32 位**，在 EPM1270（1270 个 LE）上是最贵的一类浪费。
> （本节早先的骨架与 `docs/01` §5.0 的原声明都漏了这条约束，2026-09-18 一并订正。）

### 2.6 分频与时间常量

```vhdl
-- ★ 串行级联：只有第 1 级面对 50MHz，其余各级只数"上一级来了几个脉冲"
constant CLK_HZ    : integer := 50_000_000;         -- ★ 板上时钟档位必须为 7
constant CNT_8K    : integer := CLK_HZ / 8_000 - 1; -- 50MHz→8kHz，分频比 6250
constant CNT_1K    : integer := 8_000 / 1_000 - 1;  -- 8kHz→1kHz，  分频比 8
constant CNT_100   : integer := 1_000 / 100   - 1;  -- 1kHz→100Hz， 分频比 10
constant CNT_2HZ   : integer := 100   / 2     - 1;  -- 100Hz→2Hz，  分频比 50
constant CNT_1HZ   : integer := 100   / 1     - 1;  -- 100Hz→1Hz，  分频比 100
constant CNT_POR   : integer := CLK_HZ / 100  - 1;  -- 上电复位 10ms（直数 clk）

constant T_PREVIEW : integer := 5;    -- 预览秒数（要求 4）
constant T_LEVEL1  : integer := 30;   -- 第一关限时（要求 5）
constant T_LEVEL2  : integer := 40;   -- 第二关限时
constant T_SELFTEST: integer := 2;    -- 开机自检秒数（要求 1）

-- 消抖：数的是"扫描轮次"，一轮 = 4 个 i_tick = 4ms（1kHz）→ 20 轮 = 80ms（§4.3）
constant DEBOUNCE_MAX : integer := 19;    -- 计到 19 即 20 轮（计数器从 0 起算）

-- 按键复位消抖：数的是 tick_1k（1ms/拍）→ 20 拍 = 20ms（§3.4）
constant T_BTN_MS    : integer := 20;     -- 复位键消抖时长（ms）
constant DEBOUNCE_BTN: integer := T_BTN_MS - 1;   -- 计到 19 即 20 拍

-- 方向键连发：两个数都数 i_tick_100，即每 100ms 减 1（§12.7）
constant REPEAT_DELAY  : integer := 5;    -- 按住 5 × 100ms = 500ms 后开始连发
constant REPEAT_PERIOD : integer := 1;    -- 之后每 1 × 100ms = 100ms 重复一次

-- 随机源：LFSR 复位初值，★ 8 位全非零，绝不能是全 0（§9.4 的"吸收态"）
constant SEED_DEFAULT : std_logic_vector(7 downto 0) := x"01";

-- 自检闪烁：tick_100 数 25 个得 4Hz，再翻转得 2Hz 方波（§12.2）
constant CNT_BLINK  : integer := 24;    -- 计 0~24 共 25 拍（2026-09-18 审查补：消除 §12.2 的魔法数字 24）
```

> ⚠️ **上面这三个常量是 2026-09-17 补进本节单点定义的** ——
> 它们此前**只在 `docs/02` §4.4 / §12.7 / §9.4 的代码里被引用，却全项目没有定义处**
> （与 §10.5 那批"未定义符号"是同一类问题，靠逐符号核对才查出来）。
> **凡是代码里出现的全大写符号，都必须能在本节找到定义** —— 这是本节存在的意义。

> ⭐ **只有 `CNT_8K` 的除数带 `CLK_HZ`。** 后四级数的是"上一级来了几个脉冲"，

> ⚠️ **本节是上面这 18 个常量的唯一定义处** ——

### 2.8 仿真验证点

`puzzle_pkg` 无端口，无法直接仿真。验证方式：

1. **综合即验证**：语法错误在 `quartus_map` 阶段暴露 —— ⚠️ **包不是实体，本身进不了 `.vwf`**，
   所以 `puzzle_pkg` 在评分项③（仿真波形）里**没有独立素材**，
   它的正确性只能靠下面的交叉验证 ＋ 引用它的模块的波形间接体现；
2. **函数级验证**：⚠️ **2026-09-18 审查订正** —— 本节原先写"由 `puzzle_ctrl` 的仿真间接覆盖"，
   但**本包的函数一个都没有被调用**：真正做掩码平移的是 `puzzle_ctrl` 自己的 `place()`
   （§10.4，逐格自算位号、越界丢弃），它**不调用包函数**。包里仅存的 2 个函数
   （`shift_right_col` / `popcount`）只用于**离线核对与自检**，不进任何数据通路，
   它们的正确性由下面第 3 条覆盖；
3. **等价性验证**：`scripts/verify_tiling.py` 用 Python 独立实现了同一套位序约定，
   两者对同一图案给出相同掩码 → **交叉验证通过**（Python 侧输出与本文档 §2.5 逐位相同）。
   `docs/01` §5.0 的位号换算约定（`bitidx(r,c) = 8*r + c`）也在这套交叉验证里被逐点核对
   （脚本的 `cells_to_mask` / `mask_to_rows` 正是按同一约定实现的）。

## 3. `clk_gen` —— 时钟分频与复位产生

### 3.1 职责

时钟分频、节拍使能、**复位产生（上电复位 ＋ 按键复位）**

> ⭐ **本模块是"复位"这件大事的唯一落点**，三个复位来源都在这里汇成一根 `o_rst`：
> `btn_rst`（按键，课件 PDF p45 强制）· `por_rst`（上电初值）· `(not sys_en)`（SW7 关断）。
> **其余 10 个实体都只收 `o_rst`，各自不再判断复位来源** —— 单一真值源。

### 3.2 端口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `clk` | in | 1 | 50MHz |
| `sys_en` | in | 1 | SW7，高 = 系统开 |
| `i_btn_rst` | in | 1 | **BTN0 复位键**，按下 = 1（课件 PDF p45（一）强制） |
| `o_rst` | out | 1 | 同步复位，高有效（**三源或**） |
| `o_tick_8k` | out | 1 | 8kHz 单周期使能 |
| `o_tick_1k` | out | 1 | 1kHz 单周期使能 |
| `o_tick_100` | out | 1 | 100Hz 单周期使能 |
| `o_tick_2hz` | out | 1 | 2Hz 单周期使能 |
| `o_tick_1hz` | out | 1 | 1Hz 单周期使能 |

> **权威定义在 `docs/01` §5.1**，此处与之逐条一致。

### 3.3 内部结构

**5 级串行级联计数器 ＋ 1 个上电复位计数器 ＋ 1 条按键复位通路**，无状态机。

**为什么是级联而不是五个并行**：五个计数器若都从 50MHz 直接分频，
即使每个都加了 `range` 约束也要 **99 位**；串行级联只要 **33 位**（详见 §3.5）。

```
                                     ┌───────────┬─100─▶ div_1hz ──▶ tick_1hz   (7 位)
                                     │           │
clk ──6250─▶ div_8k ──▶ tick_8k ──8─▶ div_1k ──▶ tick_1k ──10─▶ div_100 ──▶ tick_100
             (13 位)                (3 位)                       (4 位)
                                                                     │
                                                                     └─50──▶ div_2hz ──▶ tick_2hz   (6 位)

clk ──▶ por_cnt 0→CNT_POR ──▶ r_por_rst（上电期间高）──────────────────┐
                                                                       │
i_btn_rst ──▶ 2 级同步器 ──▶ btn_cnt 0→DEBOUNCE_BTN ──▶ r_btn_rst ─────┼──▶ o_rst
              (r_btn_s0/s1)   （由 r_tick_1k 使能，20ms）              │
                                                                       │
sys_en ─────────────────────▶ (not sys_en) ──────────────────────────┘
```

> **为什么按键要专门走一条通路**：`i_btn_rst` 是**异步输入**（人对 `clk` 而言），
> 且是**机械触点**（有抖动）。两级同步解决前者、消抖计数解决后者。
> **20ms 的时基取自本模块自己的 `r_tick_1k`** —— 不额外造分频器。

> **级联带来的额外好处**：低頻节拍与高频节拍**天然对齐**（`tick_1hz` 必定发生在
> `tick_100` 那一拍上），不像并行方案那样各自相位独立。
> 本项目不依赖这个性质，但调试时波形更好读。

### 3.4 关键逻辑

**第 1 级**从 50MHz 直接分频；**第 2~5 级**结构完全同构，
每级只数"上一级来了几个脉冲"：

```vhdl
-- ---------- 第 1 级：唯一直接面对 50MHz 的计数器 ----------
process (clk)
begin
    if rising_edge(clk) then
        r_tick_8k <= '0';                    -- 默认拉低
        if r_div_8k = CNT_8K then
            r_div_8k  <= 0;
            r_tick_8k <= '1';                -- 只高 1 个时钟周期
        else
            r_div_8k  <= r_div_8k + 1;
        end if;
    end if;
end process;

-- ---------- 第 2~5 级：把 r_tick_8k 换成上一级的 tick 即可 ----------
process (clk)
begin
    if rising_edge(clk) then
        r_tick_1k <= '0';
        if r_tick_8k = '1' then              -- ★ 使能来自上一级，不是 clk
            if r_div_1k = CNT_1K then
                r_div_1k  <= 0;
                r_tick_1k <= '1';
            else
                r_div_1k  <= r_div_1k + 1;
            end if;
        end if;
    end if;
end process;
```

**计数器声明（全部带 `range`，见 `CLAUDE.md` §10.2 ①）**：

```vhdl
-- ★ 6 个 CNT_* 常量（8K/1K/100/2HZ/1HZ/POR）在 puzzle_pkg 中单点定义，见 §2.6。
--   本模块只声明计数器，不定义任何常量。
signal r_div_8k  : integer range 0 to CNT_8K;       -- 0~6249（= CNT_8K），13 位
signal r_div_1k  : integer range 0 to CNT_1K;       -- 0~7，   3 位
signal r_div_100 : integer range 0 to CNT_100;      -- 0~9，   4 位
signal r_div_2hz : integer range 0 to CNT_2HZ;      -- 0~49，  6 位
signal r_div_1hz : integer range 0 to CNT_1HZ;      -- 0~99，  7 位

-- ★ 2026-09-18 审查补：原骨架缺以下声明与输出赋值
signal r_por_cnt : integer range 0 to CNT_POR;      -- 0~499999，19 位
signal r_por_rst : std_logic;
signal r_tick_8k, r_tick_1k, r_tick_100, r_tick_2hz, r_tick_1hz : std_logic;

-- 输出赋值（5 条并行赋值，端口 = 内部寄存器）
o_tick_8k  <= r_tick_8k;   o_tick_1k  <= r_tick_1k;
o_tick_100 <= r_tick_100;  o_tick_2hz <= r_tick_2hz;  o_tick_1hz <= r_tick_1hz;
```

> **为什么这里不再抄一遍常量值**：抄一遍就是第二份副本。详见 §2.6 末尾的说明 ——
> 原先这两处的 CNT 值**算出来不一样**（本节是级联版、§2.6 曾是并行版），
> 正是"同一常量两处定义"造成的。**级联版是对的**，`CLAUDE.md` §10.2 ② 有完整推导。

**上电复位**：

```vhdl
process (clk)
begin
    if rising_edge(clk) then
        if r_por_cnt = CNT_POR then
            r_por_rst <= '0';          -- 计满后释放，且不再回到 '1'
        else
            r_por_cnt <= r_por_cnt + 1;
            r_por_rst <= '1';
        end if;
    end if;
end process;
```

**按键复位**（课件 PDF p45（一）强制要求；两级处理缺一不可）：

```vhdl
-- ★ 2026-09-18 补：课件 p45「复位必须用按键来实现」+ p54「按键要注意防抖处理」
signal r_btn_s0  : std_logic;                          -- 同步器第 1 级
signal r_btn_s1  : std_logic;                          -- 同步器第 2 级
signal r_btn_cnt : integer range 0 to DEBOUNCE_BTN;    -- 0~19，5 位
signal r_btn_rst : std_logic;

process (clk)
begin
    if rising_edge(clk) then
        -- ① 两级同步：把异步的按键收进 clk 域
        r_btn_s0 <= i_btn_rst;
        r_btn_s1 <= r_btn_s0;

        -- ② 消抖 20ms：数 r_tick_1k（1ms/拍）
        if r_btn_s1 = '0' then
            r_btn_cnt <= 0;                 -- 松开：立即清零、立即释放
            r_btn_rst <= '0';
        elsif r_tick_1k = '1' then
            if r_btn_cnt = DEBOUNCE_BTN then
                r_btn_rst <= '1';           -- 稳定按住 20ms 才认定
            else
                r_btn_cnt <= r_btn_cnt + 1;
            end if;
        end if;
    end if;
end process;
```

> ⚠️ **本进程不得以 `o_rst` 为条件** —— 与"上电复位计数器不依赖 `o_rst`"是同一个坑。
> 若写成"`o_rst` 有效时停止计数"，按住复位键就**永远退不出复位**。
>
> **为什么"松开立即释放"而不是对称消抖**：复位要的是**快速、干净地结束**。
> 松开瞬间就释放，得到的是"至少 20ms 宽"的复位脉冲 ——
> 既保证了所有寄存器都被有效复位，又不会让人感觉按键迟钝。
> **对称消抖（松开也延 20ms）只是白白多按 20ms，没有收益。**

**三源合并**：

```vhdl
o_rst <= r_btn_rst or r_por_rst or (not sys_en);
```

### 3.5 设计要点

| 要点 | 说明 |
|---|---|
| **单周期使能，不是分频时钟** | 输出的是"这一拍有效"的脉冲，**不驱动任何触发器的时钟端** |
| **上电复位计数器不依赖 `o_rst`** | 若写成"`o_rst` 有效时计数器停"，则永远退不出复位 |
| **`sys_en` 直接进复位，不做消抖** | 要求 1 是"**立即**熄灭"，消抖会引入 20ms 延迟，反而违背要求 |
| **`i_btn_rst` 却要做消抖** ⭐ | **判据是"器件类型"**：SW7 是**拨动开关**、BTN0 是**机械按键**。课件 p54 要求"按键要注意防抖处理"、手册附图16 要求"按键需设计防抖动电路" |
| **按键通路不额外造分频器** | 20ms 时基直接取本模块已有的 `r_tick_1k`（1ms/拍），数 20 拍即得 |
| **按键消抖计数器不依赖 `o_rst`** | 与上电计数器同一个坑：若被复位停住，就**永远退不出复位** |
| **复位是"同步形式"** ⭐ | `o_rst` 只在 `rising_edge(clk)` 内被各模块采样（**不接任何触发器的异步复位端**）→ **对每一只触发器而言，复位值只在时钟沿装载**。<br>⚠️ **但"同步"这个词只对三源里的两源成立** —— 第三源 `(not sys_en)` 是拨动开关的**组合直通**；本行措辞被订正过两次，**别退回绝对表述**：见下方注①注②。 |
| **POR 依赖寄存器上电初值为 0** | 若 `r_por_cnt` 上电恰好是 `CNT_POR`，`por_rst` 会立即释放（2026-09-18 审查注：MAX II 寄存器上电清零，该情形实际不会发生，仅作完备性备注；更保守的写法是改成减计数到 0 释放） |
| **串行级联，不是五个并行** | 并行（加 `range`）需 **99 位**，级联只要 **33 位**，省 **66 位**；裸 `integer` 并行是 160 位，级联省 **127 位** |
| **级联不引入多时钟域** | 上级 `tick` 只做**使能**（`if r_tick_8k = '1'`），**不接任何触发器的时钟端** —— 全设计仍是单时钟域 |

> ⚠️ **注①：上面「复位」那一行的措辞被订正过两次，别再退回绝对表述**（2026-09-18 审查）：
> 最早写作"**异步断言、同步释放**" —— **是用词错误**：那描述的是
> `if rst = '1' then … elsif rising_edge(clk)` 的异步复位写法，本设计**没有**这种写法
> （`rtl` 里不会有任何异步复位分支）。
> 随后又改成"**断言与释放都发生在时钟沿**" —— 这句**对两源成立、对第三源不成立**：
> `r_btn_rst` / `r_por_rst` 都是寄存器输出，只在 `rising_edge(clk)` 内变化；
> `(not sys_en)` 不是（见注②）。

> ⚠️ **注②：第三源 `(not sys_en)` 是拨动开关的组合直通，没有同步器**（报告 `clk_gen-01`）。
> 它与 `clk` 之间**没有任何同步级**，拉低/拉高相对时钟沿**完全异步**（且 SW7 拨动过程本身有抖动）。
> **本版裁决：如实标注，不加同步器** —— 理由：
> ① `o_rst` 只作各模块**时钟沿内的条件**使用、**不是异步复位端**，因此**不引入亚稳态**；
> ② 最坏情形是开关沿撞进某只触发器的建立/保持窗口时，它当拍**漏采**复位值、
>    多保持一拍复位 —— 而此刻全设计本来就停在复位态附近，**本设计的结构使这一项几乎没有可观察后果**
>    （⚠️ 属"功能仿真查不出、上板偶发"一类，**未经上板证实**，如实记录在此）；
> ③ 答辩口径：三源中的两项（按键、上电）在时钟沿上，第三项是开关直通。
>
> **若将来要根治**：给 `sys_en` 加 2 级同步器再并入复位方程 ——
> 要求 1 的"即时熄灭"走**顶层输出级组合门控**、不经过 `o_rst`（§14.2），
> 所以加同步器**不会让熄灭变慢**（代价只是 2 个触发器）。

| 2 | 数 `o_tick_1k` 的上升沿个数，跑 1ms | 恰好 1 个 |
| 3 | 数 `o_tick_1hz` 上升沿，跑 1s | 恰好 1 个 |

| 8 | 把 `i_btn_rst` 拉高仅 10ms 后拉低 | `o_rst` **始终为 '0'** ← 验证消抖真的在起作用（短脉冲被滤掉） |
| 9 | `i_btn_rst` 全程 = 1，一直跑 | `o_rst` 恒为 '1'，**且 `r_por_cnt` 照常计数到顶** ← 验证"消抖计数器不被 `o_rst` 停住"（否则永远退不出复位） |

> ⚠️ **仿真时长与 `.vwf` 规模的权衡**：50ms @ 50MHz = 250 万个时钟周期，
> 内置仿真器跑不动。**实际做法**：把 `CLK_HZ` 在仿真时改小，
> 用比例关系验证分频比正确，而不是验证绝对时间。
> ⚠️ **`CLK_HZ` 有合法下限 8000**（2026-09-18 审查修正，原例值 1000 非法）：
> `CNT_8K = CLK_HZ / 8000 - 1`，`CLK_HZ = 1000` 时得到 `-1`，`range 0 to -1` 报错。

> （2026-09-18 审查 `sim-02`，原写"各级分频比 1:1 退化"是错的）。

## 4. `keypad_scan` —— 键盘扫描与消抖

### 4.1 职责

4×4 矩阵键盘扫描、消抖、边沿检测

### 4.2 端口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `clk` `rst` | in | 1 | |
| `i_tick` | in | 1 | 1kHz |
| `i_kp_row` | in | 4 | 行输入，**按下 = '1'** |
| `o_kp_col` | out | 4 | 列扫描，**逐列为 '1'** |
| `o_key_code` | out | **5** | 键号 1~16；0 = 无键。**非 0 即"有键稳定按住"** |
| `o_key_press` | out | 1 | 单次按下脉冲，宽度 1 个 `i_tick` |

> ⚠️ **原先这里有一个 `o_key_down`（1 位，稳定按下电平）端口，2026-09-17 删除。**
> 两个理由：
> ① **它是冗余的** —— `o_key_code /= 0` 已经完整表达了"有键按住"，
>    另出一根线就是同一事实的第二份副本；
> ② **它自己和自己对不上** —— 本表写 1 位，而 `§12.2` 的 `game_fsm` 却按 **4 位**收
>    （`i_key_down`），两边位宽矛盾。
>
> 删掉后 `game_fsm` 的连发判定改用 `i_key_code /= 0`（§12.7）。
> 本模块内部**仍有**一个 `r_down` 信号做"松手才允许下一次"的闸门，
> 但它是**内部信号，不出端口**（§4.4）。

### 4.3 内部结构

**两级状态机：扫描相 + 消抖计数**

```
扫描相（4 个 i_tick 一轮）：
   col=0001 → 读 row → col=0010 → 读 row → col=0100 → 读 row → col=1000 → 读 row → 回到 0001

消抖（每个稳定键）：
   连续读到同一个键号 → 第 1 轮建立 r_stable（不计）、随后 19 轮累加、第 21 个轮末出脉冲
```

> ⭐ **消抖时长 = 20 轮 × 4 个 `i_tick` = 80 个 `i_tick` = 80ms**（`i_tick` 是 1kHz）。
> **一轮 = 4ms，20 轮 = 80ms** —— 这两个数字必须一起说，只说一个就会出错：
>
> ⚠️ **2026-09-18 审查订正：从"按下沿"到"脉冲沿"是 80~87ms，不是恰好 80ms**（报告 `keypad_scan-03`）。
> 按 §4.4 的代码数拍：第 1 个轮末只把键号写进 `r_stable`（`r_cnt <= 0`，**不计数**），
> 之后 19 个轮末各 +1（`r_cnt` 累到 `DEBOUNCE_MAX`=19），**第 21 个轮末才置 `o_key_press`**。
> 两处余量都要算：① 按下后要等到**本键所在列的那一相**才被读到（0~4ms）；
> ② 这一相到**本轮的轮末**还有 0~3ms —— 合计 **80~87ms**。
> 因此**短于 21 个轮末的按下不会产生任何 `o_key_press`**（代价与取舍见 §4.5 的对应行）。
>
> `01-系统设计.md` §5.2 曾把它写成"20ms 消抖"（"20 轮"和"20ms"自相矛盾），
> 2026-09-17 核对时统一为 **80ms**。
>
> **为什么是 20 轮而不是 5 轮（20ms 也够消抖）**：
> 机械按键的抖动典型值 5~10ms，20ms 只有 2~3 倍余量；且**本模块的"轮"是 4ms 的粗粒度**，
> 取 5 轮等于要求抖动**在 20ms 内彻底结束**，板子陈旧时可能不够。
> 20 轮（80ms）对方向键连发的手感影响很小 —— 连发本来就要等 500ms，
> 首发的 80ms 延迟淹没在其中。**保守取值，代价可接受。**

### 4.4 关键逻辑

```vhdl
-- 扫描相推进（★ r_phase 必须是 unsigned：裸 std_logic_vector 没有 +1）
signal r_phase : unsigned(1 downto 0);

process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_phase <= (others => '0');
        elsif i_tick = '1' then
            r_phase <= r_phase + 1;              -- 自然回绕 0→1→2→3→0
        end if;
    end if;
end process;

-- 列输出：一次只拉高一列
with r_phase select
    o_kp_col <= "0001" when "00",
                "0010" when "01",
                "0100" when "10",
                "1000" when others;
```

**消抖与边沿检测**（⭐ 2026-09-18 审查**整段重写**）：

> ⚠️ **重写原因（P0 级缺陷）**：原方案"每个 `i_tick` 用当前相的读数 `s_raw` 直接和
> `r_stable` 比较"。但按住一个键时，**一轮 4 个相里只有该键所在的那一相读到键号，
> 其余 3 个相 `s_raw = 0`** —— 每个"无键相"都会把 `r_stable` 清 0、`r_cnt` 归零，
> 消抖计数器每轮最多累到 2，**永远到不了 `DEBOUNCE_MAX`**：
> `o_key_press` 不出、`o_key_code` 在"键号/0"之间抖动，
> `game_fsm` 依赖的"按住持续有效"（连发）与"单次脉冲"两条契约**同时失效**。
>
> **正确做法的关键认知**：消抖的比较单位是**"一轮读到的键"**，不是"一相读到的键"。
> 因此先把 4 相**锁存成一个"轮键号"**，整轮结束（相 3 → 相 0 的回绕点）再做一次判定。

```vhdl
-- ★ 一轮 = 4 个相；r_round_key 把"本轮任一相读到的键"锁存到整轮结束
signal r_round_key : integer range 0 to 16;   -- 本轮读到的键号（0 = 整轮无键）
signal r_stable    : integer range 0 to 16;   -- 消抖后的稳定键号（0 = 无键）
signal r_cnt       : integer range 0 to DEBOUNCE_MAX;  -- ★ 数"轮"，常量在 §2.6
signal r_down      : std_logic;               -- ★ 内部闸门，不是端口

process (clk)
    variable v_raw   : integer range 0 to 16;   -- 本相读到的原始键号
    variable v_round : integer range 0 to 16;   -- 含本相在内的本轮键号
begin
    if rising_edge(clk) then
        -- ★ 每个 clk 都先清零 —— 这是"脉冲宽度恰好 1 个 clk"的实现要点。
        --   2026-09-18 审查修正：此句原先写在 elsif i_tick = '1' 分支**之内**，
        --   而信号在非 tick 拍会**保持原值** → 脉冲实际宽 1ms（= 1 个 i_tick），
        --   下游按"单周期脉冲"消费时会被当成数万拍（ERR-0020 / 报告 INT-1）。
        --   契约：脉冲类信号宽度 = 1 个 clk，见 CLAUDE.md §10.1。
        o_key_press <= '0';

        if rst = '1' then
            r_round_key <= 0;
            r_stable    <= 0;
            r_cnt       <= 0;
            r_down      <= '0';
        elsif i_tick = '1' then
            -- ① 读当前相的原始键号（行号换算 KEY号 = (3-ROW)*4 + COL + 1；
            --    同列多键时行号大者优先 —— 单键应用，见 §4.5）
            v_raw := 0;
            for r in 0 to 3 loop
                if i_kp_row(r) = '1' then
                    v_raw := (3 - r) * 4 + to_integer(r_phase) + 1;
                end if;
            end loop;

            -- ② 本轮键号：任一相有键即覆盖（含本相）
            v_round := r_round_key;
            if v_raw /= 0 then
                v_round := v_raw;
            end if;

            if r_phase = 3 then
                -- ③ 整轮结束：用 v_round 做一次消抖判定
                -- ⚠️ 这里**不再给 r_phase 赋值**（2026-09-18 审查修正）。
                --    本进程只**读** r_phase 作"轮末"判据；相推进由上面那个进程负责，
                --    它的 `r_phase + 1` 在 2 位 unsigned 上本来就是 0→1→2→3→0。
                --    原先此处多写一句 `r_phase <= (others => '0');`，
                --    与上面的进程构成**多重驱动**（Quartus 报 multi-driver，编译不过）
                --    —— ERR-0020 / 报告 keypad_scan-01。
                r_round_key <= 0;                     -- 新一轮从"无键"开始
                if v_round = r_stable then
                    if r_cnt < DEBOUNCE_MAX then
                        r_cnt <= r_cnt + 1;           -- 连续读到同一键，累加一轮
                    else
                        -- 连续 20 轮一致 → 消抖完成
                        if r_stable /= 0 and r_down = '0' then
                            o_key_press <= '1';       -- 新按下 → 出一个脉冲
                        end if;
                        if r_stable /= 0 then
                            r_down <= '1';            -- 闸门：按住期间封门
                        else
                            r_down <= '0';            -- 整轮无键持续 20 轮 → 开门
                        end if;
                    end if;
                else
                    r_stable <= v_round;              -- 轮键号变了，重新计数
                    r_cnt    <= 0;
                end if;
            else
                r_round_key <= v_round;               -- 本轮继续累积
            end if;
        end if;
    end if;
end process;

-- ★ 稳定键号在端口边界转一次：下游用 "o_key_code /= 0" 判"有没有键按住"
o_key_code <= std_logic_vector(to_unsigned(r_stable, 5));
```

> **行为核对**（对应 §4.6 验证点）：
> - **按住 KEY2**：每轮相 1 读到 2，`v_round = 2` 每轮一致 → **第 21 个轮末**出 1 个脉冲（第 1 个轮只建立 `r_stable`、不计数；时长账见 §4.3），
>   `r_down` 封门；按住期间 `r_stable` 恒 2，`o_key_code` **不抖动**（验证点 5 ✓）；
> - **松手**：下一轮 `v_round = 0` ≠ `r_stable` → `r_stable` 立即归 0（`o_key_code` 约 4ms 内归零），
>   连续 20 轮无键后 `r_down` 开门，允许下一次按下（验证点 5 ✓）；
> - **抖动**：20 轮（80ms）内的键号抖动使 `r_cnt` 反复归零，`o_key_press` 只在稳定后出 1 个（验证点 3 ✓）。

> ⚠️ **`r_stable` / `r_round_key` 是 `integer range 0 to 16`，不是 `std_logic_vector`**（2026-09-17 修正）：
> 键号公式 `(3 - r) * 4 + ... + 1` 是**整数表达式**，
> 赋给 `std_logic_vector` 是**类型错**（必须写 `std_logic_vector(to_unsigned(..., 5))`，
> 每处都要包一层，读起来很吵）。**在端口边界做一次转换**最省事：
>
> ```vhdl
> o_key_code <= std_logic_vector(to_unsigned(r_stable, 5));   -- 唯一的转换点
> ```
>
> ⚠️ **位宽必须是 5，不是 4** —— 这处原先写错了：
> `KEY号 = (3-ROW)*4 + COL + 1`，取到 `(3-0)*4 + 3 + 1 = 16`，
> **`16` 是 5 位，4 位装不下 16**。虽然 §4.3 的映射表里 `KEY16`（ROW0/COL3）没有功能，
> 但**位宽不能靠"那个键用不到"来定** —— 真按下它时会截断成 0，
> 表现成"按下 KEY16 被当成没按键"。**本表已改为 5 位**（`docs/01` §5.2 / §5.10 同步）。

### 4.5 设计要点

| 要点 | 说明 |
|---|---|
| **消抖计的是"扫描轮次"而不是"i_tick 个数"** ⭐ | 同一个键只在它所在的那一相被读到，必须**先把 4 相锁存成"轮键号"再做整轮判定**（`r_round_key`，§4.4 ③）。若按相直接比较，无键相会把计数器清零，消抖永远完不成（2026-09-18 审查发现的 P0 缺陷，已重写） |
| **释放分两步** | 松手后**下一轮** `r_stable` 即归 0（`o_key_code` 约 4ms 内归零，连发立即停止）；`r_down` 则要**连续 20 轮无键**才开门（防抖动期误判为新按下） |
| **短按（不足 21 个轮末，按住约 84ms 以内）不产生 `o_key_press`** ⚠️ | 消抖的语义是"第 1 轮建立键号、再累满 19 轮、第 21 个轮末触发"（§4.3/§4.4 ③）→ 短按**出不了脉冲**，于是开始/选择/确认与方向键"首步"全部失灵（`game_fsm` 只认 `i_key_press`，§12.2）。按住期间 `o_key_code` 仍是有效键号，但它不负责"新按下"。**人手快速点按约 50~70ms，操作时需按住约 0.1 秒** —— 这是"用 80ms 消抖换稳定"的固有代价、**不是缺陷**；⚠️ 2026-09-18 审查补：§4.3 原先的取舍论证只算了"首发的 80ms 延迟淹没在 500ms 连发里"，**没算"短按被丢弃"这一维**，现一并写明（报告 `keypad_scan-03`） |
| **`o_key_press` 在"松手后才允许下一次"** | 用**内部信号** `r_down` 做闸门，防止长按连发（连发在 `game_fsm` 侧另做）。**闸门不必出端口** |
| **同列多键：行号大者优先** | `for r in 0 to 3` 循环里后赋值胜出。本设计是单键游戏，多键同按属误操作，报一个键即可，不做仲裁 |
| **3 键以上的"幽灵键"不处理** | 无二极管矩阵的固有限制（同时按三角形的 3 键会幻影出第 4 键）。课程项目可接受；自检时避免多键同按即可 |
| **本模块不知道"哪个键是方向键"** | 它只输出**键号**。布局 → 动作的译码属于**游戏规则**，放在 `game_fsm`（§12.2）。本模块是纯**器件驱动**类（`01-系统设计.md` §1.1.2） |
| **`i_kp_row` 直接使用，不加同步器** | 按键是**人手速度**（毫秒级），远慢于时钟，不需要跨时钟域处理；80ms 消抖本身已经过滤了抖动 |
| **键号 0 保留为"无键"** | 键号编码 1~16，0 做哨兵值，判断"有没有键"只需一个比较 |
| **按下 = '1'** | 板上有 4.7k 下拉，未按下时读到 '0'。**若实测相反，只需改这一处比较**——这是 §8.2 自检阶段要确认的 7 项之一 |

### 4.6 仿真验证点

| # | 激励 | 期望 |
|---|---|---|
| 1 | 全程无键 | `o_key_code` 恒 0，`o_key_press` 恒 0 |
| 2 | 在 COL=1、ROW=3 处按下并保持（模拟 KEY2） | 4 个相后 `o_key_code` = 2；消抖完成后出 1 个 `o_key_press` 脉冲 |
| 3 | 模拟 5ms 抖动的按下 | `o_key_press` **只出 1 个脉冲**（验证消抖生效） |
| 4 | 遍历 16 个键 | 键号依次为 1..16，且与 `KEY号 = (3-ROW)*4+COL+1` 一致 |
| 5 | 长按 1 秒不松手 | `o_key_code` 恒为键号非 0，`o_key_press` **只有 1 个脉冲** |
| 6 | 按下后**保持 ≥ 88ms**（保证覆盖 21 个轮末）再松手 | `o_key_press` 的上升沿**出现在第 21 个轮末**、距按下沿 **80~87ms**。⚠️ 2026-09-18 审查订正：原写"距按下沿 80ms（20 轮 × 4ms）"，按 §4.4 的代码**永远做不出来** —— 第 1 轮只建立 `r_stable`、不计数；且"80ms 一到就松手"时第 21 轮已读不到键，脉冲根本不出现（报告 `keypad_scan-03`） |
| **7** ⭐ | **数 `o_key_press` 为高的 `clk` 拍数** | **恰好 1 拍** —— 这是跨模块契约（`CLAUDE.md` §10.1）唯一的可数验证点。⚠️ **2026-09-18 审查新增**：原设计此处为 **1ms（50000 拍）**，下游按单周期消费会把一次按键当成数万次（ERR-0020 / 报告 `INT-1`）|

> **验证点 4 是要求 6/7/8 的基础**：键号映射错了，方向键就会上下颠倒。
> **验证点 7 是「脉冲宽度契约」的基础**：宽度错了不报错、不崩溃，只是下游行为完全不对 ——
> 属于"跑得起来但功能错"的一类，**只有数拍数才发现**。

## 5. `seg_scan` —— 数码管动态扫描

### 5.1 职责

8 位数码管动态扫描 + BCD→段码译码

### 5.2 端口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `clk` `rst` | in | 1 | |
| `i_tick` | in | 1 | **8kHz**（2026-09-18 由 1kHz 改：两相消隐下 1kHz 的刷新率只有 62.5Hz，见 §5.6） |
| `i_disp_val` | in | 32 | 8 位 BCD，`(4k+3 downto 4k)` → DISP`k` |
| `i_blank` | in | 8 | 熄灭掩码，`i_blank(k)='1'` → DISP`k` 熄灭 |
| `o_seg` | out | 8 | 段码 **高有效**，(0)=AA … (6)=AG，(7)=AP |
| `o_cat` | out | 8 | 位选 **低有效**，(0)=DISP0（**最右**） |

### 5.3 内部结构

**3 位位选计数器 + 2 相消隐状态机**

```
  ┌────────────────────────────────────────────────────────┐
  │ 相 0 (BLANK)：o_seg <= x"00"（全灭段码）                 │
  │      ↓ 下一个 i_tick                                     │
  │ 相 1 (SHOW) ：切换 o_cat 到新的位；o_seg <= 该位的段码    │
  │      ↓ 下一个 i_tick                                     │
  │ 位计数器 +1，回到相 0                                    │
  └────────────────────────────────────────────────────────┘
```

### 5.4 BCD → 段码译码表

```
 段位：  AA AB AC AD AE AF AG   AP(小数点)
  bit ：  0  1  2  3  4  5  6    7

  数字 0 : "00111111" = 0x3F     数字 5 : "01101101" = 0x6D
  数字 1 : "00000110" = 0x06     数字 6 : "01111101" = 0x7D
  数字 2 : "01011011" = 0x5B     数字 7 : "00000111" = 0x07
  数字 3 : "01001111" = 0x4F     数字 8 : "01111111" = 0x7F
  数字 4 : "01100110" = 0x66     数字 9 : "01101111" = 0x6F
  全灭   : "00000000" = 0x00
```

### 5.5 关键逻辑

**① 段码译码函数**（★ 2026-09-18 审查补 —— 原先**只被调用、没有定义**，
全项目找不到 `seg_decode` 的签名与函数体，照抄编译不过：ERR-0020 / 报告 `seg_scan-01`）：

```vhdl
-- BCD → 7 段段码（共阴极、高有效；段位与编码见 §5.4 的表）
-- 放在本模块的 architecture 声明区（与 signal 同级），是**模块私有**的纯函数
function seg_decode(b : std_logic_vector(3 downto 0))
    return std_logic_vector is
begin
    case b is
        when "0000" => return x"3F";   -- 0
        when "0001" => return x"06";   -- 1
        when "0010" => return x"5B";   -- 2
        when "0011" => return x"4F";   -- 3
        when "0100" => return x"66";   -- 4
        when "0101" => return x"6D";   -- 5
        when "0110" => return x"7D";   -- 6
        when "0111" => return x"07";   -- 7
        when "1000" => return x"7F";   -- 8
        when "1001" => return x"6F";   -- 9
        when others => return x"00";   -- ★ 必须有：防 latch；非法 BCD 一律全灭
    end case;
end function;
```

> 十个码值**逐条照抄 §5.4 的表**，没有另算 —— 那张表是唯一真值源。
> `when others` 不只是防 latch，还兜住了 `disp_format` 可能送来的非法 BCD。

**② 信号声明**（★ 补全声明，2026-09-18 审查：原骨架缺声明，`to_integer(r_digit)` 要求 `unsigned`）：

```vhdl
signal r_digit    : unsigned(2 downto 0);   -- 位选计数器 0~7
signal r_blank_ph : std_logic;              -- 消隐/显示两相
```

```vhdl
-- 位计数器
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_digit <= "000";
            r_blank_ph <= '0';
        elsif i_tick = '1' then
            r_blank_ph <= not r_blank_ph;      -- 在消隐/显示两相间翻转
            if r_blank_ph = '1' then           -- 显示相结束时进位
                r_digit <= r_digit + 1;
            end if;
        end if;
    end if;
end process;

-- 消隐相：段码全灭，位选保持不动（避免切换瞬间的鬼影留在上一位）
-- 显示相：同一时钟沿切位选 + 给出该位段码（段码在上一拍消隐相已被拉全 0）
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then                      -- ★ 复位到全灭（2026-09-18 补）
            o_seg <= (others => '0');
            o_cat <= (others => '1');          -- 位选低有效 → 全 1 = 全灭
        elsif r_blank_ph = '0' then            -- 消隐相
            o_seg <= (others => '0');
        else                                     -- 显示相
            o_cat <= not (std_logic_vector(to_unsigned(1, 8) sll to_integer(r_digit)));
            if i_blank(to_integer(r_digit)) = '1' then
                o_seg <= (others => '0');
            else
                o_seg <= seg_decode(i_disp_val(4*to_integer(r_digit)+3
                                               downto 4*to_integer(r_digit)));
            end if;
        end if;
    end if;
end process;
```

> **注意**：`1 sll n` 得到的是"第 n 位为 1"，再取反就是**低有效**的位选。
> `o_cat(0)` 对应 DISP0（最右），与手册的 `CAT0→DISP0` 一致。
> **AP 段（小数点，`o_seg(7)`）保留未用**——倒计时与关卡号都不需要小数点。

### 5.6 设计要点

| 要点 | 说明 |
|---|---|
| **两相扫描（消隐 + 显示）** | 若直接把新位选和段码一起换，段码在切换瞬间会短暂出现在**上一位**上，形成鬼影。消除靠的是**切换前整整一拍 `o_seg` = 0（消隐相）**，**不是相内的先后次序**（同一时钟沿的赋值不存在先后）—— "先灭→再切→再亮"是三相叙事的残留，照它写会让每帧多 8 拍、刷新率掉到 333Hz，与 §5.6 的 500Hz 账目对不上 |
| **刷新率** ⭐ | **每位 2 个 `i_tick`，8 位一帧**。`i_tick` = 8kHz 时：每位 0.25ms、一帧 2ms → **500Hz**，远高于人眼闪烁阈值。⚠️ 2026-09-18 审查：原设计 `i_tick` = 1kHz，**两相消隐下一帧 16ms、刷新率只有 62.5Hz**（勉强高于 60Hz 阈值且亮度减半），与 §4.2 原先按"1 相 1ms"算出的 125Hz 自相矛盾，已改为 8kHz |
| **`i_blank` 与显示值分离** | 有些位要显示"0"、有些位要熄灭——用独立的掩码而不是用 BCD 的某个保留值表示"熄灭"，语义清晰 |
| **`seg_decode` 用 `case` 实现，必须有 `when others`** | 防 latch；输入是 BCD，`others` 分支返回全灭 |

> ⚠️ **上板若偏暗的备选方案（2026-09-18 审查补）**：两相消隐使每位占空**恒为 1/16**
> —— 改 `tick_8k` 提高的是刷新率、**不是亮度**。若实验室目视发现可读性不足，可把
> **BLANK 相从 1 个 `i_tick` 缩短为若干个 `clk`**（保留"切换前熄灭"的窗口即可），
> 占空随之接近 1/8；改后需同步更新本表"刷新率"一行与 §5.7 验证点 5 的周期判据。
> **这是备选项、不是默认设计**：500Hz 已由仿真证明，亮度只能上板定夺。

### 5.7 仿真验证点

| # | 激励 | 期望 |
|---|---|---|
| 1 | `i_disp_val` = `x"11111111"`（8 个 BCD 半字节全为 1，即 8 位数码管都显示 "1"），`i_blank` = 0，跑 20ms | 8 个 `o_cat` 位依次为低；每次只有 1 位低；`o_seg` 轮流为 0x06 |
| 2 | `i_disp_val` 逐位设为 0~9 | 段码依次等于 §5.4 表格中的值 |
| 3 | `i_blank(3)` = 1 | DISP3 被选中时 `o_seg` = 0x00，其余位不受影响 |
| 4 | 抓取"位选切换"瞬间 | **切换前后各有一拍 `o_seg` = 0x00**（消隐生效，无鬼影） |
| 5 | 数一位的周期 | 恰好 2 个 `i_tick` |

> ⚠️ **验证点 1 的激励原先写「`i_disp_val` = 全 1」（2026-09-18 审查订正）**：本项目"全 1"的
> 既有用法是**全比特为 1**（如 `o_cat <= (others => '1')` = 全灭），照字面写 `(others => '1')`
> 得到的是 8 个 0xF —— **非法 BCD**，`seg_decode` 走 `when others` 返回全灭，`o_seg` 恒为 0x00，
> 与期望的 0x06 自相矛盾。要写的是 `x"11111111"`（每个半字节 = 1）。表格措辞会原样传进
> `sim/tb_seg_scan.py`，所以在此写死。

> **验证点 4 是要求 2 的核心证据**，波形图要放进实验报告。

## 6. `dot_matrix_scan` —— 点阵动态扫描

### 6.1 职责

8×8 双色点阵动态扫描（含消隐防鬼影）

### 6.2 端口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `clk` `rst` | in | 1 | |
| `i_tick` | in | 1 | **8kHz**（同 §5.2 的修正） |
| `i_px_red` | in | 64 | 红色像素掩码 |
| `i_px_green` | in | 64 | 绿色像素掩码 |
| `o_dot_row` | out | 8 | 行，**低有效** |
| `o_dot_colr` | out | 8 | 红列，**高有效** |
| `o_dot_colg` | out | 8 | 绿列，**高有效** |

### 6.3 内部结构

**3 位行计数器 + 2 相消隐，与 `seg_scan` 结构对称。**

```
  ┌──────────────────────────────────────────────────────────┐
  │ 相 0 (BLANK)：o_dot_row <= "11111111"（全行拉高 = 全灭）    │
  │      ↓ 下一个 i_tick                                       │
  │ 相 1 (SHOW) ：o_dot_row  ← 仅第 r 行为低                    │
  │              o_dot_colr ← i_px_red  (8r+7 downto 8r)      │
  │              o_dot_colg ← i_px_green(8r+7 downto 8r)      │
  │      ↓ 下一个 i_tick                                       │
  │ r +1，回到相 0                                             │
  └──────────────────────────────────────────────────────────┘
```

### 6.4 关键逻辑

> ⚠️ **本节在 2026-09-18 审查中整段重写**（ERR-0020 / 报告 `dot_matrix_scan-1`）。
> 原稿只有三行**并发赋值**，`r_row` 没有声明、没有相位机、没有复位值 ——
> **按它写出来的 `o_dot_row` 永远产生不出消隐**，而且 `r_row` 是"没出生地"的信号。
> 现按 **§5.5（`seg_scan`）的对称写法**补全 —— 两模块本就声明为"结构对称"。

**信号声明**：

```vhdl
signal r_row      : unsigned(2 downto 0);   -- 行计数器 0~7（★ 必须是 unsigned：裸
                                            --   std_logic_vector 没有 +1）
signal r_blank_ph : std_logic;              -- 消隐/显示两相
```

```vhdl
-- 行计数器 + 相位机（与 §5.5 的 seg_scan 完全对称）
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_row      <= "000";
            r_blank_ph <= '0';
        elsif i_tick = '1' then
            r_blank_ph <= not r_blank_ph;   -- 在消隐/显示两相间翻转
            if r_blank_ph = '1' then        -- 显示相结束时进位
                r_row <= r_row + 1;         -- 3 位 unsigned 自然回绕 7→0
            end if;
        end if;
    end if;
end process;

-- 消隐相：整屏全灭（行全高 = 无行选中）
-- 显示相：先切行，再给列 —— ★ 全项目唯一一处"掩码 → 引脚"的映射，
--          位序在此处天然对齐，无需任何翻转（§4.3）
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then                       -- ★ 复位到全灭（与 seg_scan 对称）
            o_dot_row  <= (others => '1');      -- 行低有效 → 全 1 = 全灭
            o_dot_colr <= (others => '0');
            o_dot_colg <= (others => '0');
        elsif r_blank_ph = '0' then             -- 消隐相：全灭
            o_dot_row  <= (others => '1');
            o_dot_colr <= (others => '0');
            o_dot_colg <= (others => '0');
        else                                     -- 显示相
            o_dot_row  <= not (std_logic_vector(to_unsigned(1, 8) sll to_integer(r_row)));
            o_dot_colr <= i_px_red  (8*to_integer(r_row)+7 downto 8*to_integer(r_row));
            o_dot_colg <= i_px_green(8*to_integer(r_row)+7 downto 8*to_integer(r_row));
        end if;
    end if;
end process;
```

> **为什么消隐相要把列也清零**：消隐相行是全高的，本来就不亮；
> 但**切换行的瞬间**若列还停在上一位的值，某些驱动能力强的板上会留下"鬼影"。
> 列同时清零是**第二道保险**，代价是 16 个与门（可忽略）。
>
> ⚠️ **节拍是 `tick_8k` 不是 `tick_1k`**（2026-09-18 刷新率修正）：
> 每行 2 个 `i_tick`（消隐 1 + 显示 1），一帧 16 拍，刷新率 = 8kHz / 16 = **500Hz**。

**颜色合成**（由 `puzzle_ctrl` 完成，此处只做说明）：

| 红掩码 | 绿掩码 | 结果 |
|---|---|---|
| 1 | 0 | 红 |
| 0 | 1 | 绿 |
| 1 | 1 | 黄 |
| 0 | 0 | 灭 |

> **为什么用两个独立的 64 位掩码而不是一个 2 位/像素的颜色数组**：
> VHDL-93 里 `array (0 to 63) of std_logic_vector(1 downto 0)` 的端口声明与
> 综合支持都不如扁平向量顺手；两个 `std_logic_vector(63 downto 0)` 可以
> 直接做逐位与/或运算，代码更短、综合结果更可预测。

### 6.5 设计要点

| 要点 | 说明 |
|---|---|
| **消隐必须做，且必须在行切换前** | 点阵的行驱动与列驱动若同时切换，上一行的列数据会短暂出现在新行上 → 一行亮点"串"到另一行。**可选加固**：BLANK 相把列也预载下一行数据（列在行选变低前已稳定），进一步消除"新行+旧列"的纳秒级串扰（2026-09-18 审查建议，同步时序下通常不可见） |
| **行用 `sll`，不用 `case`** | `1 sll r` 一行搞定，综合器会展开成译码器 |
| **刷新率** ⭐ | 每行 2 个 `i_tick`，8 行一帧。`i_tick` = 8kHz 时：每行 0.25ms、一帧 2ms → **500Hz**（原设计 1kHz 下两相消隐实为 62.5Hz，2026-09-18 审查修正，同 §5.6） |
| **`i_px_red`/`i_px_green` 是组合输入，在显示相被采样进输出寄存器** | 上游 `puzzle_ctrl` / `disp_format` 的像素输出**是组合量**（§10.3"像素掩码不存储"、§11.3 的纯组合进程），**不是"寄存的"**；本模块按 §6.4 的进程在显示相采样、消隐相清零 —— **只多一级延迟，不改变时序正确性**。<br>⚠️ 2026-09-18 审查：原写"直接穿透到输出"且理由说"上游已寄存"，既与 §6.4 的寄存输出矛盾、也与 §10.5/§11.3 的事实不符 |
| **共阴/共阳** | 本板行低有效、列高有效。**若上板实测相反，只需把两处 `not` 调整**（本模块的**行** `not` 一处 + `seg_scan` 的**位选** `not` 一处）——自检阶段确认。⚠️ 2026-09-18 审查 `hw-05`：原先"两处"易被读成"都在本模块"，实际要动的是两个模块各一处 |

### 6.6 仿真验证点

| # | 激励 | 期望 |
|---|---|---|
| 1 | `i_px_red` = 单点（行 0 列 0） | 扫描到 r=0 时 `o_dot_colr` = "00000001"，`o_dot_row` = "11111110" |
| 2 | `i_px_red` = 单点（行 7 列 7） | 扫描到 r=7 时 `o_dot_colr` = "10000000"，`o_dot_row` = "01111111" |
| 3 | **`i_px_red` = 满行（某行 8 位全 1）** | **只有该行对应的 `o_dot_colr` 是 0xFF，且该行被选中时其余行都不会亮** ← **要求 7 边界验证** |
| 4 | 红绿掩码均置某些位 | 两路输出独立、互不干扰 |
| 5 | 抓切换瞬间 | 行切换前后各一拍 `o_dot_row` = 0xFF（消隐生效） |
| 6 | 抓 `r_row` 从 0 回到 0 的整帧 | 单行的 SHOW 相恰好 1 个 `i_tick`（含消隐共 2 拍）；相邻两次 `r_row`=0 之间恰好 **16** 个 `i_tick`（8kHz 下 = 2ms → **500Hz**）← **验证 §6.5 的刷新率账目** |

> ⭐ **验证点 6 是 2026-09-18 审查补的**：`i_tick` 由 1kHz 改 8kHz 的**唯一目的**就是把刷新率
> 从 62.5Hz 拉到 500Hz，而原 5 条只查"值"与"相位"—— **`i_tick` 误接成 `tick_1k` 或某一级
> 分频配错，这 5 条一条都不会报错**（相位仍对、值仍对，只是全慢了 8 倍）。同族模块 `seg_scan`
> 的 §5.7 有对称的第 5 条（"数一位的周期"），点阵此前没有对称的一条。

> **验证点 3 就是"像素不得跨行回绕"的直接证据**：
> 把最右列的像素点亮，观察它会出现在**同一行的最右**，而**不会跑到下一行的最左**。

process (i_sel)

```

## 8. `piece_rom` —— 零片形状查找表

### 8.1 职责

零片形状查找表（相对掩码 + 宽高）

### 8.2 端口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `i_pattern_sel` | in | 3 | 图案选择（**与 `pattern_rom.i_sel` 同源**，来自 `game_fsm.o_pattern_sel`）：`"000"` = 第一关矩形、`"001"` = 第二关向上箭头、`"010"` = 第二关向下箭头 |

| `o_height` | out | 4×3 | 4 块的包围盒高度（`dim_arr_t`） |

| `o_count` | out | 3 | 本关零片数（3 或 4） |

> ⭐ **2026-09-18 审查修正：`i_level`（1 位）改为 `i_pattern_sel`（3 位）。**
> 原设计里第二关图案在"向上/向下箭头"间随机，但零片只有向上箭头一套 ——
> 若随机选中向下箭头，**零片与目标不匹配，穷举证明 0 种铺法，玩家永远无法通关**
> （`verify_tiling.py` 交叉验证：L2 零片铺 L2B 目标解数 = 0）。
> 改为与 `pattern_rom` 同一个选择字后，**零片永远跟着图案走**，结构上杜绝这种错配。
> 该选择字在 `S_PLAYING` 期间恒定（`game_fsm` 只在开局/进关时改变），
> 与原先 `i_level` 的稳定性等价。

> ⚠️ **接口在 2026-09-17 由"给序号查一块"改为"一次输出 4 块"**，
> 并删掉了 `i_idx` 与 `o_valid`。原因见 `01-系统设计.md` §5.6 的完整说明，摘要：
>
> | 改动 | 为什么 |
> |---|---|
> | `i_idx` 由输入改为内部展开 | 顶层要例化全部子模块（`CLAUDE.md` §10.3），若 `piece_rom` 只能查一块，`puzzle_ctrl` 就得自己例化 4 份 —— 框图上会多出一个**藏在 `puzzle_ctrl` 里的方框** |
> | 删 `o_valid` | "本关有几块"由 `o_count` 唯一表达。再出一个 `o_valid` 是**同一事实的第二份副本**，两者不一致时 `puzzle_ctrl` 会读到垃圾 |
>
> **代价**：`o_rel_mask` 从 64 位变 256 位。但每位只是在几套常量间做选择，
> 而**各套相同的位置（绝大多数是 '0'）会被综合器折叠**，实际 LE 增量很小。

### 8.4 关键逻辑与设计要点

```vhdl
-- 纯组合查表：零片永远跟着图案走（★ 2026-09-18 补骨架，原先只有文字描述）
process (i_pattern_sel)
begin
    case i_pattern_sel is
        when "000" =>                            -- 第一关：3 块 + 占位槽
            o_rel_mask <= (L1_P0, L1_P1, L1_P2, (others => '0'));
            o_height   <= ("011", "010", "001", "000");
            o_width    <= ("011", "010", "011", "000");
            o_count    <= "011";                 -- 3
        when "001" =>                            -- 第二关 · 向上箭头
            o_rel_mask <= (L2_P0, L2_P1, L2_P2, L2_P3);
            o_height   <= ("011", "011", "010", "001");
            o_width    <= ("011", "011", "010", "010");
            o_count    <= "100";                 -- 4
        when others =>                           -- "010" 第二关 · 向下箭头；
            o_rel_mask <= (L2B_P0, L2B_P1, L2B_P2, L2B_P3);   -- ★ 其余编码（含胜负态
            o_height   <= ("011", "011", "010", "001");       --   的 "011"/"100"）也走
            o_width    <= ("011", "011", "010", "010");       --   这套：此时 puzzle_ctrl
            o_count    <= "100";                             --   不在 S_PLAYING，不读
    end case;
end process;
```

> ⚠️ **高/宽必须用位串字面量 `"011"`，不能写整数 `3`**（2026-09-18 审查修正）。
> `o_height` / `o_width` 的类型是 `dim_arr_t = array (0 to 3) of std_logic_vector(2 downto 0)`，
> 而 `(3, 2, 1, 0)` 是**整数聚合** —— 在 VHDL-93 下**类型不匹配，照抄编译不过**
> （ERR-0020 / 报告 `piece_rom-1`）。
> 位串写法的四个读数与 §8.3 的表逐格一致。

| 要点 | 说明 |
|---|---|
| **`o_height` / `o_width` 预先列成常量而不是从掩码推** | 从 64 位掩码推导包围盒需要优先级编码器；直接列常量则**编译期折叠成 0 逻辑**，且钳位逻辑要频繁用这两个值 |
| **第一关第 4 槽填全 0** | 统一 4 槽接口，`puzzle_ctrl` 不必为两关写两套循环；由 `o_count = 3` 保证它不被读 |
| **相对掩码锚点固定在包围盒左上角** | 这样锚点加行/列偏移就是绝对位置，`place()` 只需一次平移 |
| **`when others` 映射到第二关下箭头那套** | 一举两得：`"010"` 是本意；胜负态（`"011"/"100"`）也落进这套**合法**数据，不会输出垃圾形状——虽然那时 `puzzle_ctrl` 已离开 `S_PLAYING` 不会读它 |
| **纯组合，3 个分支** | 综合成多路选择器，无 latch |

|---|---|---|

## 9. `rng_lfsr` —— 伪随机数发生器

### 9.1 职责

LFSR 伪随机数发生器

### 9.2 端口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `clk` `rst` | in | 1 | |
| `i_step` | in | 1 | 前进一拍 |
| `i_seed_load` | in | 1 | 装入种子 |
| `i_seed` | in | 8 | 种子值（**必须非零** —— LFSR 全 0 是吸收态；本模块装载时强制置 bit0，上游 `game_fsm` 另有 `or x"02"`，见 §9.4 / §12.2） |
| `o_rnd` | out | 8 | 当前随机数 |

### 9.3 内部结构与多项式

**8 位最大长度 LFSR**（Fibonacci 型，左移，反馈抽头 **bit 7/5/4/3**）：

> ⚠️ **2026-09-18 审查修正（第二版，纠正上一版）**：本节原先标注的特征多项式 `x⁸+x⁶+x⁵+x⁴+1`
> **就是抽头 `bit 7/5/4/3`（1-based 8/6/5/4）对应的标准本原多项式**（= `0x171`）——
> 上一版把它判成“与抽头不符、且非本原（周期 61）”并删去名称，**那个判断是错的，现予纠正**。
> “周期 61”只会出现在把反馈误写成 `r_lfsr(6) xor r_lfsr(5) xor r_lfsr(4)`
> （**漏掉 `bit7`**、寄存器变成非可逆）的时候，与这个多项式无关。
> **名字归名字、实现只认抽头**：下面的代码就是 `bit 7/5/4/3`，
> 该抽头组合经穷举验证**周期恰为 255**（单环覆盖全部非零状态，
> 验证方法：从 `x"01"` 出发迭代，第 255 步回到 `x"01"`，见 §9.6 验证点 1/3）。
> **实现与重建只认抽头，不要按任何多项式名称反推。**

```vhdl
-- 内部结构（按 §1.1 模板）：1 个 8 位寄存器 + 1 段时序进程 + 1 条组合输出（o_rnd 直连，不额外寄存）
signal r_lfsr : std_logic_vector(7 downto 0);   -- 全模块唯一的状态，8 个触发器
signal s_fb   : std_logic;                      -- 组合反馈（bit7 xor bit5 xor bit4 xor bit3）

-- 反馈 = bit7 xor bit5 xor bit4 xor bit3（★ 抽头以本行代码为准，见上）
s_fb <= r_lfsr(7) xor r_lfsr(5) xor r_lfsr(4) xor r_lfsr(3);

process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_lfsr <= SEED_DEFAULT;             -- ★ 不能复位成全 0
        elsif i_seed_load = '1' then
            -- ★ 防御性置 bit0（2026-09-18 审查补）：LFSR 全 0 是吸收态（§9.4），
            --   万一上游送来 x"00"，这里也把状态按回非零 —— 只多一根线，零额外逻辑。
            --   上游 game_fsm 还有一道（r_free or x"02"，§12.2），两道防线都在。
            r_lfsr <= i_seed or x"01";
        elsif i_step = '1' then
            r_lfsr <= r_lfsr(6 downto 0) & s_fb;
        end if;
    end if;
end process;

o_rnd <= r_lfsr;
```

### 9.4 设计要点

| 要点 | 说明 |
|---|---|
| ⚠️ **绝不能复位成全 0** | LFSR 的**全 0 是吸收态**——一旦进入全 0，反馈恒为 0，永远出不来。复位值必须是任意非零常量（如 `x"AC"`）。**这个 bug 表现为"随机数恒为 0，所有零片叠在一起"** |
| ⚠️ **`i_seed` 也必须非零 —— 前置条件写在两处**（2026-09-18 审查补） | 装载路径同样进不了全 0：① 本模块 `r_lfsr <= i_seed or x"01"` **主动置 bit0**（§9.3）；② 上游 `game_fsm` 采样种子时写 `r_free or x"02"`（§12.2）。**两道防线都在**——若只靠上游，将来换个调用者直接驱动 `i_seed = x"00"`，LFSR 会锁死在吸收态、`o_rnd` 恒 0，而且**不报任何错** |
| **周期 = 255** | 最大长度序列，8 位下最长的非零周期 |
| **种子来源** | `game_fsm` 在按下"开始"键时，采样一个**自由运行计数器**的低 8 位。因为按键时刻由人决定，采样值不可预测 → 每次开局不同 |
| **`i_step` 必须是脉冲** | 若接成常高，LFSR 每个时钟都前进，虽然值仍是随机的，但会丧失"每次尝试读一个新值"的可控性 |
| **抽头方向不重要，只要是最大长度多项式** | 写反了只是序列不同，随机性不变 |

### 9.5 "每次尝试必须步进"——本项目最隐蔽的坑 ⚠️

`puzzle_ctrl` 散落零片时，若写成：

```vhdl
-- ✗ 错误写法：一次 i_step，内部读多次同一随机数
if i_step = '1' then
    for try in 0 to 7 loop
        if overlap(...) = 0 then anchor <= rnd(5 downto 3) & rnd(2 downto 0); end if;
    end loop;
end if;
```

则**同一个零片的所有 8 次尝试读到的是同一个 `o_rnd`**，
8 次尝试结果完全相同——要么第 1 次就成功，要么 8 次全失败。

**正确写法**：`puzzle_ctrl` **每做一次尝试就输出一个 `o_rnd_step` 脉冲**，
LFSR 前进后再读新值。

> **为什么这个 bug 危险**：它**不会让游戏崩溃**，也不会报错。
> 只是"随机"这个特性**静默失效**——所有零片落到同一位置（因为读的是同一个数），
> 于是频繁走回退路径，零片位置看起来"很规律"。
> 而"零片位置随机"恰恰是提高要求③，是本项目要拿的分。

### 9.6 仿真验证点

| # | 激励 | 期望 |
|---|---|---|
| 1 | `i_seed_load` 装 `x"01"`，然后连续 `i_step` 300 次 | 第 255 次时**回到 `x"01"`**（验证周期 255） |
| 2 | 全程 `i_step` | `o_rnd` **永远不为 0**（验证没落入吸收态） |
| 3 | 从 `x"01"` 开始跑 255 拍 | 255 个值**两两不同**（最大长度序列的定义） |
| 4 | 复位后立即观察 | `o_rnd` = `SEED_DEFAULT` ≠ 0 |
| 5 | 统计 255 个值中每个 bit 为 1 的次数 | 各 bit 均恰好 = **128**（255 态不含全零，故每 bit 恒为 128） |
| 6 | `i_seed_load` 故意装 `x"00"`，随后连续 `i_step` 若干拍 | `o_rnd` **仍非 0** ← 2026-09-18 审查补：证明装载路径的第二道防线在，不依赖上游 |

> **验证点 1/3 需要在 Python 侧维护一个参考 LFSR 模型逐值比对**
> （见 `scripts/vwf.py` 的用法，以及 `docs/03-仿真验证方案.md`）。

### 10.3 内部状态（唯一数据源）

```vhdl
type anchor_t is array (0 to 3) of std_logic_vector(5 downto 0);  -- {行[2:0], 列[2:0]}

signal r_anchor : anchor_t;                     -- 4×6 = 24 个触发器
signal r_locked : std_logic_vector(3 downto 0); -- 4 个
signal r_sel    : std_logic_vector(1 downto 0); -- 2 个

-- ★ 散落序列器自身的状态（2026-09-18 审查补 —— 原先这三样**没有任何声明处**，
--   而本节却声称"30 个触发器就是全部状态"，见 ERR-0020 / 报告 INT-4）
type seq_state_t is (ST_IDLE, ST_STEP, ST_TRY);
signal r_seq   : seq_state_t;                   -- 2 个（3 个状态）
signal r_piece : std_logic_vector(1 downto 0);  -- 2 个（当前在摆第几块，0~3）
signal r_try   : std_logic_vector(2 downto 0);  -- 3 个（本块已试第几次，0~7）
```

> **合计 37 个触发器**（24 + 4 + 2 + **2 + 2 + 3**）就是本模块的全部状态。
> ⚠️ 2026-09-18 审查订正：原写"30 个"，**漏了散落序列器那 7 个**。
>
> **像素掩码不存储**——由锚点 + 形状**组合计算**。
> 若存掩码需要 4×64 = 256 个触发器，且会引入"锚点与掩码不一致"这类最难查的 bug。

> ⭐ **「已放置零片的并集」也不存寄存器** —— 它由 **`r_anchor(0 .. r_piece−1)` +
> 对应形状组合计算**得出，随序列器推进而增长（与"掩码不存储"同一原则）。
>
> ⚠️ **它与 `s_union` 不是同一个东西，绝对不能复用**（这是 `INT-4` 点名的坑）：
>
> | 名字 | 含义 | 用在哪 |
> |---|---|---|
> | **已放置并集** | **前 `r_piece` 块**的绝对掩码之或 | 散落时的**求交参照**（只跟已摆好的比） |
> | `s_union` | **全部 4 块**的绝对掩码之或 | 判定"拼对了吗"（§10.8） |
>
> **拿 `s_union` 当散落时的求交参照，后果是静默的**：它把"还没摆的块"也算进去了，
> 求交**恒非空** → 每次都判重叠 → 8 次尝试全废 → **每块都走回退表** →
> **位置随机静默退化成固定布局**。游戏照常能玩，只是提高要求③永远不生效。

**组合中间量**（不是状态，只为把 §10.5 的判定写成一行）：

```vhdl
signal s_valid_mask : std_logic_vector(3 downto 0);   -- 本关哪几块存在
signal s_union      : std_logic_vector(63 downto 0);  -- 4 块掩码的并集
signal s_sel_idx    : integer range 0 to 3;           -- r_sel 的整数形式，★ 见下
```

> ⚠️ **`s_sel_idx` 是必须的，不是可选的美化**（2026-09-17 补）：
> **`std_logic_vector` 不能用作数组下标**。VHDL 规定数组下标的类型必须是**离散类型**
> （`integer` 或枚举），`std_logic_vector` 不是。
> 而 §10.7 / §10.8 有 **8 处**要拿"当前选中的块号"去索引 `r_anchor` / `r_locked` /
> `i_height` / `i_width`，写成 `r_anchor(r_sel)` 会直接编译不过。
>
> ```vhdl
> s_sel_idx <= to_integer(unsigned(r_sel));   -- 一行组合转换，代价是几个 LUT
> ```
>
> 之后凡是要拿"当前选中块"当**下标**的地方一律用 `s_sel_idx`；
> 只在**比较**（如 §10.5 的 `unsigned(r_sel) = to_unsigned(i, 2)`）
> 或**赋值**（如 §10.8 的 `r_sel <= ...`）时才直接用 `r_sel`。

```vhdl
-- 由 i_piece_count 展开：piece_count = 3 → "0111"，= 4 → "1111"
-- ⚠️ i_piece_count 是 std_logic_vector，**不能直接和整数字面量比大小**，
--    必须先 to_integer(unsigned(...))。写法与 docs/01 §5.8 完全一致。
s_valid_mask(0) <= '1';
s_valid_mask(1) <= '1' when to_integer(unsigned(i_piece_count)) > 1 else '0';
s_valid_mask(2) <= '1' when to_integer(unsigned(i_piece_count)) > 2 else '0';
s_valid_mask(3) <= '1' when to_integer(unsigned(i_piece_count)) > 3 else '0';
```

> ⚠️ **不要写成 `(others => '1') sll (count-1)` 之类的移位**：`count = 0` 时会算错，
> 而上面的比较器写法在**任何** `count` 下都对。4 个 1 位比较器的代价可以忽略。
>
> **`s_valid_mask` 的作用**是把 §10.8 的"全部锁定"从
> **"第 4 块恰好没锁"这种巧合**，变成一条**显式的、可读的条件**。

### 10.4 核心函数：`place()` 平移

```vhdl
-- 把相对掩码按锚点 (ar, ac) 平移到 8×8 绝对坐标
-- ★ 逐行逐列搬运，越界直接跳过（不写入 → 天然不回绕）
-- ★ ar/ac 参与加法（r + ar），必须带 range，否则 32 位加法器
function place(rel : std_logic_vector(63 downto 0);
               ar  : integer range 0 to 7;
               ac  : integer range 0 to 7) return std_logic_vector is
    variable v : std_logic_vector(63 downto 0) := (others => '0');
begin
    for r in 0 to 7 loop
        for c in 0 to 7 loop
            if rel(8*r + c) = '1' then
                if (r + ar) <= 7 and (c + ac) <= 7 then
                    v(8*(r+ar) + (c+ac)) := '1';
                end if;
                -- 越界：什么都不做（不写入 → 不产生回绕）
            end if;
        end loop;
    end loop;
    return v;
end function;
```

> **这是要求 7「零片不得移出 8×8」的最终保障**：
> 即使钳位逻辑失效、锚点越界，`place()` 也**只会丢弃**越界的格子，
> **绝不会**把格子搬到别处。**双保险。**

### 10.5 像素输出（组合）

```vhdl
process (r_anchor, r_locked, r_sel, i_piece_count, i_rel_mask)
    variable v_union : std_logic_vector(63 downto 0);
    variable v_piece : std_logic_vector(63 downto 0);
    variable v_red   : std_logic_vector(63 downto 0);
    variable v_green : std_logic_vector(63 downto 0);
    variable v_ar    : integer range 0 to 7;    -- 当前块的行锚点
    variable v_ac    : integer range 0 to 7;    -- 当前块的列锚点
begin
    v_union := (others => '0');
    v_red   := (others => '0');
    v_green := (others => '0');

    for i in 0 to 3 loop                                        -- ★ 循环界是常量
        if i < to_integer(unsigned(i_piece_count)) then         -- ★ 信号比较，不是循环界
            -- 拆锚点：r_anchor(i) = {行[2:0], 列[2:0]}
            v_ar := to_integer(unsigned(r_anchor(i)(5 downto 3)));
            v_ac := to_integer(unsigned(r_anchor(i)(2 downto 0)));

            v_piece := place(i_rel_mask(i), v_ar, v_ac);        -- ★ 形状来自 piece_rom
            v_union := v_union or v_piece;

            -- 配色：锁定黄 > 选中绿 > 普通红（★ 逐块优先级：仅对"不与别的块重叠"的格子成立）
            -- ⚠️ 2026-09-18 审查（puzzle_ctrl-7）：下面是**逐块 or** 累加，不是按格仲裁。
            --   选中块与未锁定块重叠的格 = 选中块的绿 或 另一块的红 = **红+绿 = 黄**，
            --   看上去像已锁定 —— 而重叠是设计**允许**的（docs/00 §6）。
            --   按格仲裁要多一个 4 选 1 小多路器；本设计**保留 OR 混合**、把这条口径明写，
            --   期望写在 §10.10 验证点 11。
            if r_locked(i) = '1' then
                v_red   := v_red   or v_piece;
                v_green := v_green or v_piece;                  -- 红+绿 = 黄
            elsif unsigned(r_sel) = to_unsigned(i, 2) then      -- ★ 不能写 r_sel = i
                v_green := v_green or v_piece;                  -- 绿
            else
                v_red   := v_red   or v_piece;                  -- 红
            end if;
        end if;
    end loop;

    o_px_red   <= v_red;
    o_px_green <= v_green;
    s_union    <= v_union;          -- ★ 组合中间量，供 §10.8 的判定用
end process;

-- ⚠️ `o_all_locked` 与 `o_solved` 的定义在 §10.8 —— 本处不再重复给出。
--    一个信号在两处各赋值一次 = **双驱动**，Quartus 会报 `Error: ... has multiple
--    drivers`（或按"最后一条胜出"处理），是必须避免的写法。
```

> ⚠️ **上面那句 `unsigned(r_sel) = to_unsigned(i, 2)` 在 2026-09-17 又改了一次** ——
> 因为上一版按 ERR-0012 改成的 `r_sel = to_unsigned(i, 2)` **本身仍是类型错**：
> `numeric_std` **没有** `(std_logic_vector, unsigned)` 的 `=` 重载
> —— 它只提供 `(unsigned, unsigned)`、`(unsigned, natural)`、`(signed, integer)` 这几组。
> 左边 `r_sel` 是 `std_logic_vector`、右边是 `unsigned`，**没有一个重载能匹配**。
> 正确写法有两种，等价的：
> ```vhdl
> elsif unsigned(r_sel) = to_unsigned(i, 2) then                  -- 两边都转成 unsigned
> elsif r_sel = std_logic_vector(to_unsigned(i, 2)) then          -- 两边都留 slv
> ```
> **不能写 `r_sel = i`**（`slv` 与 `integer` 更不可能比），
> 也**不能写 `r_sel = to_unsigned(i, 2)`** —— 这是 ERR-0012 那一批的同族错误，
> 看着"只差一个转换"，实际编译不过。

> ⚠️ **本段在 2026-09-17 修正了 6 处，全部是"文档里的代码根本无法编译"级别的问题。**
> 记在这里是因为它们**恰好都是写 VHDL 时最容易顺手写错的地方**：
>
> | # | 原来写成 | 问题 | 改成 |
> |---|---|---|---|
> | 1 | `process (all_inputs)` | VHDL-93 **没有 `all`**（那是 VHDL-2008） | 逐个列出实际读到的信号 |
> | 2 | `PIECE_MASK(i)` | **全项目从未定义过**这个符号 | `i_rel_mask(i)`（新补的端口） |
> | 3 | `ANCHOR_ROW(i)` / `ANCHOR_COL(i)` | 同上，未定义 | `r_anchor(i)(5 downto 3)` / `(2 downto 0)` 拆分 |
> | 4 | `r_sel = i` | **`std_logic_vector` 不能直接和 `integer` 比** | `unsigned(r_sel) = to_unsigned(i, 2)` ⚠️ **本次又修一次**：上一版写的 `r_sel = to_unsigned(i, 2)` 是 `(slv, unsigned)`，`numeric_std` 没有这个 `=` 重载 |
> | 5 | `o_union` | **未声明**的信号名 | `s_union`（在 §10.3 声明） |
> | 6 | `r_locked and VALID_MASK = VALID_MASK` | ⭐ **运算符优先级错**，见下 | `(r_locked and s_valid_mask) = s_valid_mask` |
>
> ⭐ **第 6 处值得单独说**：VHDL 的优先级里 **关系运算符（`=`）比逻辑运算符（`and`）高**，
> 所以 `a and b = c` 会被解析成 `a and (b = c)` —— 左边是向量、右边是布尔，
> **类型不匹配**。这与 C 语言里 `==` 优先于 `&` 是**同一个坑**，
> 但方向相反（C 里 `a & b == c` 是 `a & (b == c)`，VHDL 里 `a and b = c` 也是 `a and (b = c)`，
> 其实方向相同 —— **两种语言都要求你加括号**）。
> **写"全 1 判定"时一律加括号**，不要指望记对优先级。
> 这个错误会被综合器报出来（不是静默的），但**报错位置指向那一行，
> 原因却藏在优先级规则里**，不熟悉的同学会反复改那一行却改不对。

### 10.6 随机散落（有界尝试 + 确定性回退）

**核心难点**：硬件里没有"重试到成功"，必须保证**有限步内一定终止**。

> ⚠️ **下面这段是伪代码，不可照抄。** 它只描述**算法**（`:=`、`成功 := true`、中文变量名
> 都不是 VHDL）。**本项目里它还没有对应的可综合实现** —— §10.3~§10.5 给的是
> 状态、`place()` 和像素输出的实现，**散落序列器本身留到阶段 3 写 `puzzle_ctrl` 时落笔**
> （`PROGRESS.md` 阶段 3）。写的时候必须注意两点：
> ① `for i in 0 to piece_count-1` 这种"**循环上界来自信号**"的写法在本项目是**禁止**的
> （`CLAUDE.md` §10.2 ①）：综合器只能按该信号的完整位宽去展开。
> **正确写法是循环界取常量 4，在里面用 `if i < to_integer(unsigned(i_piece_count))` 过滤**
> —— 也就是 §10.5 已经在用的写法。
> ② 每轮尝试必须发 `o_rnd_step`，见 §9.5 那个静默失效的坑。

```
for i in 0 to piece_count-1 loop          -- 逐块摆放（★ 伪代码：循环界不得来自信号）
    成功 := false
    for try in 0 to 7 loop                -- 每块最多 8 次尝试
        ① o_rnd_step ← '1'                -- ★ 每次尝试都必须步进 LFSR
        ② 行 = i_rnd(5 downto 3) 钳位到 [0, 8 − i_height(i)]
           列 = i_rnd(2 downto 0) 钳位到 [0, 8 − i_width(i) ]
           -- ★ 原先写 [0, 7−h]，与「不变量 行+高 ≤ 8」（§10.7、docs/01 §6.3）
           --   差 1：散落会永远贴不到下边缘/右边缘，而方向键却能贴到。
           --   正确来源只有一处：锚点上限 = 8 − 高。
        ③ 算绝对掩码，与已放置零片的并集求交
        ④ 交集为 0 → 记下锚点，成功 := true，跳出
    end loop
    未成功 → 回退：从回退表第 i 项起顺序取第一个「不越界且与已放置并集不相交」的锚点（四行表见本节下文）
end loop
```

**为什么是有穷的**：

| 环节 | 保证 |
|---|---|
| 外层循环 | 固定 `piece_count` 次（≤ 4） |
| 内层循环 | 固定 8 次 |
| 回退表 | **最多顺序检查 4 项**，取第一个「不越界且与已放置并集不相交」的锚点（2026-09-18 审查订正：原为"无条件给位置、不再判断"——那会让回退锚点压在先前的随机落位上） |
| **总计** | **≤ 4 × (8 + 4) = 48 步，必定终止**（回退至多试 4 个候选锚点，其中必有 1 个可用 —— 论证见下文『为什么回退也不会重叠』） |

**序列器的可实现规格**（⭐ 2026-09-18 审查补：原先只有伪代码，
`o_rnd_step` 的脉冲纪律与握手时序未定义，是随机性静默失效的最后一个缺口）：

> **每次尝试占两拍**，小状态机 `ST_STEP → ST_TRY`：
>
> | 拍 | 动作 |
> |---|---|
> | **ST_STEP** | `o_rnd_step <= '1'`（**单周期脉冲**，本拍 LFSR 在时钟沿前进） |
> | **ST_TRY** | 读 `i_rnd`（**已是新值**）→ 钳位到 `[0, 8−h] / [0, 8−w]`（与不变量同一把尺子） → 算绝对掩码求交 → 成功：记锚点、进下一块；失败：尝试数 +1 |
>
> - ⚠️ **两拍结构不能合并成一拍**：`rng_lfsr` 在 `i_step` 的那个时钟沿才更新 `r_lfsr`，
>   **同一拍内读 `i_rnd` 读到的是旧值** —— §9.5 那个"每次同值"的坑会换一副面孔重现；
> - ⚠️ **`i_rnd` 只用低 6 位**（`(5 downto 3)` → 行、`(2 downto 0)` → 列），`bit7/6` 弃用；
>   钳位使边界锚点轻微过采样（如 3×3 块的行 5/6/7 都钳到 **5**，列同理），**上界都是 8−h / 8−w** —— 原先写 7−h 且举例「钳到 4」，比不变量紧一格，与 §10.7 的移动钳位、docs/01 §6.3、验证点 5 三处对不上账，属已知可接受偏差，不影响"位置随机"的验收；
> - **节拍预算**：≤ 4 块 ×（8 次随机 + 4 次回退候选）× 2 拍 = **96 拍 @50MHz ≈ 1.9µs**（按每次检查 2 拍的上界估），
>   由 `i_round_start` 触发，远在预览结束后第一个 `tick_1hz`（1 秒）之前完成，
>   玩家看到画面时散落早已就绪；
> - 序列器只在 `i_round_start` 脉冲后运行一次，完成后静止，`o_rnd_step` 恒 '0'。

**回退表**（预置的、两两不冲突的锚点，**两关共用一张**）：

| idx | 回退锚点 (行, 列) | 对应角 |
|---|---|---|
| 0 | (0, 0) | 左上 |
| 1 | (0, 5) | 右上 |
| 2 | (5, 0) | 左下 |
| 3 | (5, 5) | 右下 |

> ⭐ **这张表不分关卡** —— 原先按关卡列了 7 行，但**两关的前 3 项完全相同**，
> 只有第 4 项是第二关才用得到。而"用不用第 4 项"已经由 `i_piece_count` 决定了，
> 所以**按关卡分表是多余的**。
> 这同时是 `puzzle_ctrl` **不需要 `i_level` 端口**的第三处证据（另两处见 §10.2）。
>
> **为什么不会重叠**：四块的包围盒分别落在左上、右上、左下、右下四个角，
> 零片最大 3×3 —— 上排锚点行 0 → 占第 0~2 行，下排锚点行 **5** → 占第 5~7 行，
> **行方向 0~2 与 5~7 不交**；左排列 0 → 占列 0~2，右排列 5 → 占列 5~7，**列方向也不交**。
> 四个锚点同时满足 §6.4 的不变量「行 + 高 ≤ 8、列 + 宽 ≤ 8」（对高/宽 ≤ 3 的块都成立）。
> **这是逐项代进去算过的**（四个锚点 × 各块高/宽的组合，逐个验「行 + 高 ≤ 8」与「列 + 宽 ≤ 8」）。
>
> ⚠️ **下排两个锚点原先是 (6,0) / (6,5)**（2026-09-18 审查改正，ERR-0020 / 报告 `iface-04`）：
> 回退表是"**无条件**给一个位置、**不再判断**"的（见上表），**不经过 §10.7 的钳位** ——
> 锚点行 6 对高 3 的块要占第 6/7/**8** 行，而第 8 行根本不存在；
> 越界的那一格会被 `place()` **静默丢弃**（§10.4「越界：什么都不做」），
> 表现是"零片缺一行"，不报错、也很难联想到回退表。
> 当时没出事，只是因为第二关的 idx 2/3 恰好是高 2 与高 1 的块（§8.3 的 `o_height` 表），
> 而第一关只用前 3 项 —— **"恰好如此"不是不变量**：零片次序/高度一变（加第三关、
> 或把 3×3 的块排到 idx 2/3），回退落下的零片立刻缺行。
> 改成 **(5,0) / (5,5)** 后，**任意高/宽 ≤ 3 的块都落在界内**，与块序无关。
> **防复发**：`scripts/verify_tiling.py` 里应加一条断言，把这四个回退锚点与各块高/宽
> 一起代入上面的两个不等式（锚点 + 尺寸 ≤ 8 且两两不交）—— 图案/零片表一变就先跑它。

### 10.7 移动与钳位（要求 7）

```vhdl
signal s_new_anchor : std_logic_vector(5 downto 0);   -- 候选新锚点 {行[2:0], 列[2:0]}

-- 组合：由「当前选中块的锚点 + 方向脉冲」算出候选新锚点
-- ★ 下标一律用 s_sel_idx（整数），不能用 r_sel（slv 不能作数组下标，见 §10.3）
process (s_sel_idx, r_anchor, r_locked, i_dir, i_height, i_width)
    variable v_row  : integer range 0 to 7;
    variable v_col  : integer range 0 to 7;
    variable v_h    : integer range 0 to 7;
    variable v_w    : integer range 0 to 7;
    variable v_maxr : integer range 0 to 8;    -- 行锚点上限 = 8 − 高
    variable v_maxc : integer range 0 to 8;    -- 列锚点上限 = 8 − 宽
begin
    v_row := to_integer(unsigned(r_anchor(s_sel_idx)(5 downto 3)));
    v_col := to_integer(unsigned(r_anchor(s_sel_idx)(2 downto 0)));
    v_h   := to_integer(unsigned(i_height(s_sel_idx)));
    v_w   := to_integer(unsigned(i_width (s_sel_idx)));
    v_maxr := 8 - v_h;      -- 不变量：行锚点 + 高 ≤ 8
    v_maxc := 8 - v_w;

    case i_dir is
        when "1000" =>                                  -- 上：★ 先判 0，再减
            if v_row > 0      then v_row := v_row - 1; end if;
        when "0100" =>                                  -- 下：★ 先判上限，再加
            if v_sel < to_integer(unsigned(i_piece_count))      -- ★ 本块必须真的存在
               and v_row < v_maxr then
                v_row := v_row + 1;
            end if;
        when "0010" =>                                  -- 左
            if v_col > 0      then v_col := v_col - 1; end if;
        when "0001" =>                                  -- 右
            if v_col < v_maxc then v_col := v_col + 1; end if;
        when others => null;                            -- 无方向 → 不动
    end case;

    s_new_anchor <= std_logic_vector(to_unsigned(v_row, 3)) &
                    std_logic_vector(to_unsigned(v_col, 3));
end process;

-- 时序：有方向脉冲、且该块未锁定时才真正更新锚点
-- ⭐ 本进程是 r_anchor 的**唯一写者**（见下方 ⚠️）
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_anchor <= (others => (others => '0'));
        elsif i_dir /= "0000" and r_locked(s_sel_idx) = '0' then
            r_anchor(s_sel_idx) <= s_new_anchor;
        end if;
    end if;
end process;
```

> ⚠️ **`r_anchor` 必须只有一个写者**（2026-09-18 审查明确，ERR-0020 / 报告 `puzzle_ctrl-3`）。
>
> 本进程现在是它**唯一的写者**。但阶段 3 写 §10.6 的**散落序列器**时，
> 序列器也要改 `r_anchor`（把 4 块零片摆到随机位置）——
> **若另起一个进程去写，就是多重驱动，Quartus 直接报错**（课件 p58）。
>
> **正确做法：把散落写进本进程，按优先级排序**：
>
> | 优先级 | 条件 | 动作 |
> |---|---|---|
> | 1（最高） | `rst = '1'` | 全部锚点清零 |
> | 2 | 散落序列器给出"本拍写第 i 块" | `r_anchor(r_piece_idx) <= <序列器算出的位置>` |
> | 3 | `i_dir /= "0000" and r_locked(s_sel_idx) = '0'` | `r_anchor(s_sel_idx) <= s_new_anchor` |
>
> 三者在时间上互斥（散落只在 `S_PREVIEW` 期、移动只在 `S_PLAYING` 期），
> 写成 `if / elsif / elsif` 不会互相干扰，**但物理上必须是同一个进程**。
>
> ⚠️ **同类风险还有一处**：`r_locked` 与 `r_sel` 也同时被散落器与"选择/确认"逻辑写 ——
> 落笔时一并按"**一个信号一个进程**"的原则归并。

> ⭐ **本段的写法在 2026-09-17 改了策略，值得说明。**
>
> **原先的写法**是"先无条件加减，再把越界值修补回来"：
> ```vhdl
> s_new_row := s_new_row - 1;                        -- 0 会回绕到 7！
> if s_new_row > (8 - height) then ... end if;       -- 补上下界
> if 减过头        then s_new_row := 0; end if;      -- 补上回绕 ← 伪代码，无法实现
> ```
> 这个写法有 **3 个问题**：
> ① **「减过头」无法用 VHDL 表达** —— 减完就回绕了，"过没过"这个信息已经丢了；
> ② 变量越界的瞬间会**触发 `range` 检查失败**（仿真直接报错）；
> ③ 那个 `height` / `width` **是未定义符号**（与 §10.5 同一毛病）。
>
> **现在的写法**是"**先判断，再决定改不改**"：`v_row` 全程被 `range 0 to 7` 约束，
> **越界的中间值根本不会被算出来**。
>
> > **这与 §6.4 的思路是同一条**："不是移出去再拉回来，而是**让非法移动根本不发生**"。
> > 要求 7 的边界正确性靠的是**不变量 + 构造**，不是事后修补。
> >
> > 顺带解决"钳位 vs 拒绝"的手感问题：贴着上边界时再按上，`v_row` 保持 0 ——
> > **表现就是"贴边停住"**，而非"整个移动被忽略"。
> > 斜向移动（若将来支持）时一个方向越界也不影响另一个方向。
>
> ⚠️ **锚点上界要求「本块真的存在」（2026-09-18 审查补，本处 `v_sel` 是 `place()` 那个索引参数）**：
> 只有存在块的 `v_h ≥ 1` 才保证 `v_maxr = 8 − v_h ≤ 7`，「先判断再改」才真的够用。
> 若选中的是**不存在的块**（第一关的占位槽：`i_height = "000"`），
> `v_maxr` 会算出 **8** —— 于是 `v_row = 7` 时 `v_row < 8` 成立、`v_row + 1 = 8`：
> 仿真直接报 `range` 检查失败并中断，综合后 `to_unsigned(v_row, 3)` 把 8 **截断成 "000"**，
> 零片从第 7 行**跳回第 0 行** —— 正是要求 7 明令排除的回绕。
> 所以策略二（只把 `v_maxr` 声明到 8）在这里是**不够的**：
> 上限声明放到 8 只是让上界算得出来，**真正防住越界写的是「块存在」这条守卫**。
> **依赖别处的保证（`i_piece_count` 保证占位槽不会被选中）不算数** ——
> 这正是下面那条注对 `v_maxr` 立的规矩，`v_row` 的写入侧必须同样遵守。
>
> ⚠️ **`v_maxr` / `v_maxc` 的 `range` 必须到 8**：`v_h` 最小可能取到 0
> （第一关那个占位槽），此时 `8 − 0 = 8`，**若声明成 `range 0 to 7` 会越界报错**。
> `i_piece_count` 保证这种块不会被选中，但**声明的范围不该依赖别处的保证**。
>
> **"已锁定的零片不可移动"在这里实现**：`r_locked(r_sel) = '0'` 是更新锚点的前提（要求 8）。

### 10.8 选择 / 锁定 / 判定

**"选择"键**（要求 6）：

```vhdl
process (clk)
    variable v_next : integer range 0 to 3;
    variable v_last : integer range 0 to 3;    -- 本关最后一块的序号
begin
    if rising_edge(clk) then
        if rst = '1' or i_round_start = '1' then
            r_sel <= "00";                     -- ★ 新一局也归零：块数可能变少（4 块 → 3 块）
        elsif i_sel = '1' then
            v_next := to_integer(unsigned(r_sel));
            v_last := to_integer(unsigned(i_piece_count)) - 1;
            for k in 0 to 3 loop               -- ★ 循环界是常量
                -- 循环切换，且跳过已锁定的块
                if v_next >= v_last then       -- ★ 用 >= 而不是 =，见下
                    v_next := 0;               -- 绕回第 0 块
                else
                    v_next := v_next + 1;
                end if;
                exit when r_locked(v_next) = '0';  -- 找到未锁定的就停
            end loop;
            r_sel <= std_logic_vector(to_unsigned(v_next, 2));
        end if;
    end if;
end process;
```

> ⚠️ **`>=` 与 `i_round_start` 归零是 2026-09-17 补的两处收口**（原先都写的是 `=`）：
> `v_next` 声明为 `range 0 to 3`，**若判断写成 `v_next = v_last`，一个陈旧的
> `v_next = 3` 在 `v_last = 2` 时（第二关打完、回到第一关）会跳进 `else` 分支
> 执行 `v_next := 4` → 越界，仿真报错、综合出错误逻辑**。
> 改成 `>=` 后它自己就把自己夹住了：`3 >= 2` 成立 → 归零，**任何入口值都安全**。
> 同时让 `i_round_start` 也把 `r_sel` 归零 —— 新一局零片全部重新散落，
> 选中块回到第 0 块是唯一没有歧义的选择。
>
> **不用 `mod`**：`v_next := (v_next + 1) mod piece_count` 看着更短，
> 但 `piece_count` 是**信号**，会综合出一个**除法器**（`CLAUDE.md` §10.2 ④：
> 本项目应当完全不出现 `*` `/` `mod`），而 `if/else` 版本只多几个 LUT。
>
> ⚠️ **`v_last` 的下溢前提**（2026-09-18 审查注）：`v_last = count − 1` 在 `count ≥ 3`
> 的设计前提下不会取负；若将来允许 `count = 0` 需加守卫（声明 `range 0 to 3`，`-1` 会越界报错）。

> ⭐ **本段在 2026-09-17 重写。原先写的是一个死循环**：
> ```vhdl
> loop
>     r_sel <= r_sel + 1;
>     exit when r_sel < 0;          -- ← r_sel 是 2 位无符号，永远不可能 < 0
> end loop;
> ```
> `r_sel` 是 `std_logic_vector(1 downto 0)`，**`r_sel < 0` 恒为假**，这个 `loop` 退不出来。
> 而且它在里面给**信号**赋值（`r_sel <= ...`）却指望立刻读到新值 —— 进程里读信号读到的是旧值，
> 循环体每一轮算的都是同一个数。
>
> **现在的写法**用**变量** `v_next` 做迭代（变量赋值立即生效），
> `for k in 0 to 3` 给出固定的上界，**最多转 4 圈必定停下**。
> **"至少有一个未锁定"由 §10.8 的判定语义保证**：全部锁定就立即判胜/判负、离开 `S_PLAYING`，
> 不会有"全部锁定还在选"的状态。

**"确认"键**（要求 8）与判定时序：

```vhdl
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_locked <= (others => '0');
        elsif i_round_start = '1' then
            r_locked <= (others => '0');           -- 新一局：清锁定（重新随机散落）
        elsif i_conf = '1' and r_locked(s_sel_idx) = '0' then
            r_locked(s_sel_idx) <= '1';            -- 锁定当前零片
        end if;
    end if;
end process;

-- 全部锁定 → 立即判定（组合输出）
o_all_locked <= '1' when (r_locked and s_valid_mask) = s_valid_mask else '0';
```

> ⚠️ **`s_valid_mask` 的来历**：原先这里写的是 `VALID_MASK` —— **一个从未定义的符号**
> （与 §10.5 里那 5 个同类）。现在它有了正式定义（§10.3）：
> **"本关存在的块"**，由 `i_piece_count` 展开。
> 少了它，第一关只有 3 块却要求 `r_locked = "1111"`，**永远等不到 `o_all_locked`**。

> ✅ **"确认"键的语义决策（2026-09-17 已定稿）**：本设计采用**"锁定"语义**——
> 每次按"确认"锁住当前零片，**不立即判定对错**；等**全部零片都锁定后**才用 `o_solved` 判定。
> 全部锁定但 `o_solved = '0'` → **立即判失败**（不等倒计时耗尽）。
>
> **为什么不每按一次就判一次**：要求 5 规定零片**初始位置随机**，
> 若每锁定一块就检查它是否在"正确位置"，**第一块几乎一定不在正确位置**，
> 游戏会立即判失败、无法进行。详见 `docs/00-需求分析.md` §2 要求 9。
>
> **为什么不做"可解锁重摆"**：要求 8 明确规定确认后零片"**不可再选择及移动**"，
> 允许解锁与该条冲突。**保持与要求 8 严格一致。**

**判定准则**（要求 9）⭐：

```vhdl
o_solved <= '1' when s_union = i_target_mask else '0';     -- s_union 见 §10.3 / §10.5
```

> ⚠️ **这里原先写的是 `o_union` —— 全项目从未声明过这个信号**
> （与 §10.5 表里的第 5 条是同一处笔误，一并改成 `s_union`）。
> `s_union` 是 §10.3 声明的**内部信号**，在 §10.5 的组合进程里算出。
> **并集是内部中间量，不该做成端口** —— 端口每多一个，
> 顶层就多一组 `component` 声明与 `port map`，而每多一个 `port map` 就多一个静默悬空的机会。

> ⚠️ **本判据只在 `S_PLAYING` 态有效（2026-09-18 审查补）**：`o_solved` 是**纯组合**输出，
> 而 `puzzle_ctrl` **不知道当前是什么状态**（它连 `state` 端口都没有）。
> 进 `S_WIN` / `S_FAIL` 后，`game_fsm` 把 `pattern_rom.i_sel` 改成 `"011"` / `"100"`，
> `i_target_mask` 随之**变成胜负显示图案** —— 此时 `s_union`（= 本关目标）不可能等于它，
> `o_solved` 恒为 `'0'`；而 `r_locked` 要等下一局的 `i_round_start` 才清（§10.3），
> `o_all_locked` 仍是 `'1'`。两组输出**恰好凑成“全锁但没拼对”**。
> 因此**判失败那条边必须写在 `game_fsm` 的 `S_PLAYING` 分支里**
> （§12.6、§12.9 验证点 8），否则一进 `S_WIN` 就立刻跳 `S_FAIL`，**胜利图案永远画不出来**。
> 这是 `pattern_rom` ↔ `puzzle_ctrl` ↔ `game_fsm` 三方的静默耦合，也是答辩抽到本模块的必答点。

**为什么是"并集 == 目标"而不是"逐块比对初始位置"**：
`scripts/verify_tiling.py` 穷举证明三块零片**恰好有 2 种合法铺法**，
两种都拼出正确的 4×3 矩形。逐块比对会**把其中一种正确解误判为失败**。
本判定与铺法无关，**自动接受全部合法解**。

### 10.9 设计要点汇总

| # | 要点 | 后果 |
|---|---|---|
| 1 | **掩码不存储，组合计算** | 省 256 个触发器；结构上杜绝"锚点与掩码不一致" |
| 2 | **`place()` 逐格搬运，越界丢弃** | 要求 7 的最终保障 |
| 3 | **移动时先判断边界再减** | 防止 `0-1` 回绕到 7 |
| 4 | **每次尝试都发 `o_rnd_step`** | 否则随机散落静默失效（§9.5） |
| 5 | **散落有界（≤48 步）+ 回退表** | 保证有限终止，不会死锁；回退锚点也**过一遍求交**，故"不重叠"在回退路径上同样成立（§10.6） |
| 6 | **判定基于并集** | 接受全部合法铺法 |
| 7 | **已锁定的零片不响应方向键** | 要求 8 |
| 8 | **资源大头是 4 路 `place()` 组合逻辑，不是 37 个触发器** | 4×64 逐格搬运 + 64 位 OR 树，预估 **~300 LE**。<br>⚠️ **这个数不再单独成篇** —— 它是 `docs/01` §9「LE 分解」表的**第一行**，全芯片总量 ~600 LE 由该表三行相加得出（2026-09-18 审查 `INT-5`：此前本节写 ~300、`docs/01` 写总量 ~450，**两者不自洽**）。**改这个数请回 `docs/01` §9 一并改。** |

## 11. `disp_format` —— 显示格式化（纯组合）

### 11.1 职责

**游戏状态 → 两路显示内容**：数码管的 8 位 BCD ＋ 熄灭掩码，**以及点阵的红/绿像素掩码**。

> ⭐ **点阵这一路是 2026-09-17 补进来的**（原职责只有数码管）。理由：
> "自检时全黄闪烁"（要求 1）和"预览时显示完整目标图案"（要求 4）这**两件事
> 全项目没有任何模块能做** —— `dot_matrix_scan` 只有 `i_px_red/green` 一个来源，
> 而 `puzzle_ctrl` 在预览期间给出的只能是零片初始位置，**给不出完整图案**。
> 补的成本是 5 个端口，不补则这两条要求**只能靠顶层拼线，没法独立仿真**。

### 11.2 端口

**权威定义在 `docs/01` §5.9**，此处只作索引与补充说明（两份必须逐字一致）：

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `i_state` | in | 3 | 当前状态 |
| `i_level` | in | 1 | 关卡（0 = 第一关） |
| `i_preview_cnt` | in | 3 | 预览倒计时值 |
| `i_game_cnt_bcd` | in | 8 | 拼图倒计时值，**BCD**：`(7 downto 4)` = 十位，`(3 downto 0)` = 个位 |
| `i_blink` | in | 1 | **2Hz 方波**，自检闪烁用（来自 `game_fsm.o_blink`） |
| `i_pattern_mask` | in | 64 | 图案掩码（来自 `pattern_rom`）：预览图案与胜负图案 |
| `i_px_red` `i_px_green` | in | 64 | 来自 `puzzle_ctrl` 的零片像素 |
| `o_disp_val` | out | 32 | 8 位 BCD |
| `o_blank` | out | 8 | 熄灭掩码 |
| `o_px_red` `o_px_green` | out | 64 | **最终**上点阵的红 / 绿像素掩码 |

> ⚠️ **本端口在 2026-09-17 由 6 位二进制改为 8 位 BCD**，与 `docs/01` §5.9 对齐。
> 原先写成 6 位二进制（0~63 秒），需要在本模块里做 `/10` 与 `mod 10`；
> 改成 BCD 后本模块退化为**纯接线**，一个除法器都不需要。理由见 §11.4。

### 11.3 状态 → 显示映射

| 状态 | DISP7 | DISP6..5 | DISP4 | DISP3 | DISP2..1 | DISP0 |
|---|---|---|---|---|---|---|
| `S_SELF_TEST (0)` | `8` | `8` | `8` | `8` | `8` | `8` |
| `S_IDLE (1)` | `5` | 灭 | 灭 | 灭 | 灭 | 关卡号 |
| `S_PREVIEW (2)` | 预览倒计时 | 灭 | 灭 | 灭 | 灭 | 关卡号 |
| `S_PLAYING (3)` | 灭 | 灭 | 十位 | 个位 | 灭 | 关卡号 |
| `S_WIN (4)` / `S_FAIL (5)` | 灭 | 灭 | 灭 | 灭 | 灭 | 关卡号 |

**设计依据**：

- **DISP7 显示"5"**：要求 2 规定待机时最左位数码管显示数字 5；
- **DISP0 显示关卡号**：要求 3；要求 9 原文的 "DISP2" 为笔误（见 `docs/00` §6）；
- **DISP4/DISP3 显示倒计时**：要求 5，两位十进制；
- **倒计时用**两位**而不是一位**：30/40 秒需要两位。

**点阵显示什么**（同一张状态表的另一半，管的是 `o_px_red` / `o_px_green`）：

| 状态 | 点阵上的内容 | 来源 |
|---|---|---|
| 自检 | 64 点**全黄**（红+绿同时亮），受 `i_blink` 通断 | `(others => i_blink)` |
| 待机 | 全灭 | 常量全 0 |
| 预览 | **完整目标图案**（红） | `i_pattern_mask`（要求 4） |
| 游戏中 | 零片像素 | `i_px_red` / `i_px_green`（透传） |
| 胜负已分 | 胜利 / 失败图案 | `i_pattern_mask` |

```vhdl
-- 点阵内容选择（纯组合，与上面的数码管映射同一个 case）
process (i_state, i_blink, i_pattern_mask, i_px_red, i_px_green)
begin
    case i_state is
        when S_SELF_TEST =>                       -- 自检：全黄，2Hz 通断
            o_px_red   <= (others => i_blink);    -- ★ 64 位全等于 i_blink
            o_px_green <= (others => i_blink);    --   红+绿同亮 = 黄
        when S_IDLE =>                            -- 待机：全灭
            o_px_red   <= (others => '0');
            o_px_green <= (others => '0');
        when S_PREVIEW =>                         -- 预览：完整目标图案（红）
            o_px_red   <= i_pattern_mask;
            o_px_green <= (others => '0');
        when S_PLAYING =>                         -- 游戏中：透传零片像素
            o_px_red   <= i_px_red;
            o_px_green <= i_px_green;
        when others =>                            -- S_WIN / S_FAIL：胜负图案
            o_px_red   <= i_pattern_mask;
            o_px_green <= (others => '0');
    end case;
end process;
```

> ⭐ **`(others => i_blink)` 是这一段的巧劲**：它把 64 位一次性全赋成 `i_blink` 的当前值，
> **一行完成"全黄 + 2Hz 闪烁"，不需要 64 位常量、也不需要 `and` 掩码**。
> 等价写法是 `o_px_red <= ALL_ONES and (63 downto 0 => ...)`，但那要额外定义一个 64 位常量。
>
> ⚠️ **`i_blink` 必须是方波，不能是 `tick_2hz` 使能**：
> 单周期使能只在一个 `clk` 内为 1，点阵根本来不及扫到 —— 详见 `docs/01` §5.10 的说明。
>
> ⚠️ **`case` 的所有分支都给了两个输出赋值**（`when others` 兜住 S_WIN/S_FAIL）→
> **不会产生 latch**（`CLAUDE.md` §10.2 ⑤ 红线 3）。
> 胜负图案显示为**红色**（`o_px_red <= i_pattern_mask`、`o_px_green <= 0`，2026-09-18 审查明确）。

**数码管这一路**（⭐ 2026-09-18 审查补：原先本节**只有点阵进程，数码管进程完全缺失**——
自检态"8 位数码管 2Hz 闪烁"的机制与极性无从实现，是要求 1 的硬判据缺口）：

```vhdl
-- 数码管内容选择（与点阵同一个状态维度，纯组合）
-- ★ 默认全灭，各分支只覆盖要点亮的位；进程内一律 if/else（VHDL-93）
process (i_state, i_level, i_preview_cnt, i_game_cnt_bcd, i_blink)
begin
    o_disp_val <= (others => '0');
    o_blank    <= (others => '1');               -- 默认：8 位全灭
    case i_state is
        when S_SELF_TEST =>
            o_disp_val <= x"88888888";           -- 8 位全 "8"
            o_blank    <= (others => not i_blink);   -- ★ 与点阵同相：blink=1 亮、=0 灭
        when S_IDLE =>
            o_disp_val(31 downto 28) <= x"5";    -- DISP7 = 5（要求 2）
            o_blank(7) <= '0';
            o_disp_val(3 downto 0) <= std_logic_vector(unsigned("000" & i_level) + 1);
            o_blank(0) <= '0';                   -- DISP0 = 关卡号（★ level 0/1 → 显示 1/2）
        when S_PREVIEW =>
            o_disp_val(31 downto 28) <= '0' & i_preview_cnt;  -- DISP7 倒计时（★ 零扩展）
            o_blank(7) <= '0';
            o_disp_val(3 downto 0) <= std_logic_vector(unsigned("000" & i_level) + 1);
            o_blank(0) <= '0';
        when S_PLAYING =>
            o_disp_val(19 downto 16) <= i_game_cnt_bcd(7 downto 4);   -- DISP4 = 十位
            o_disp_val(15 downto 12) <= i_game_cnt_bcd(3 downto 0);   -- DISP3 = 个位
            if i_game_cnt_bcd(7 downto 4) = x"0" then
                o_blank(4) <= '1';               -- ★ 前导零熄灭（0x09 显示 "9" 不是 "09"）
            else
                o_blank(4) <= '0';
            end if;
            o_blank(3) <= '0';                   -- 个位恒亮（"30" 的 0 是有效数字）
            o_disp_val(3 downto 0) <= std_logic_vector(unsigned("000" & i_level) + 1);
            o_blank(0) <= '0';
        when others =>                           -- S_WIN / S_FAIL：只保留关卡号
            o_disp_val(3 downto 0) <= std_logic_vector(unsigned("000" & i_level) + 1);
            o_blank(0) <= '0';
    end case;
end process;
```

> **三个容易写错的点**（审查补注）：
> ① 自检闪烁的极性是 `o_blank <= (others => not i_blink)` —— 写反了数码管会与点阵**反相闪烁**，
>   仿真不查视觉效果，只能在上板时暴露；
> ② `i_level`（0/1）显示关卡号必须 **+1**（`'0'` → "1"、`'1'` → "2"）；
> ③ DISP7 的预览倒计时是 3 位二进制，放入 4 位 BCD 半字节要**零扩展**（`'0' & i_preview_cnt`），
>   与 `seg_scan` 的 `(4k+3 downto 4k)` 抽取对齐。

### 11.4 本模块不做二进制 → BCD 转换 ⭐

**一个"假想的除法器"如何被设计掉：**

倒计时值要显示成两位十进制，最直觉的写法是"存二进制、显示时转换"：

```vhdl
-- ✗ 不采用：会综合出除法器
--   （端口名是 i_game_cnt_bcd —— 这里故意写成"存二进制"的假想版本，才需要除）
s_tens := i_game_cnt / 10;
s_ones := i_game_cnt mod 10;
```

`/ 10` 与 `mod 10` 在 `numeric_std` 里是**真正的除法运算**，
Quartus 会为它生成一个通用除法器网络（实测同类设计约 **30~60 LE**），
而 EPM1270 一共只有 1270 个 LE。**这是一笔纯粹为"存法"付出的代价。**

> **关键认识：秒数本来就不该用二进制存。**
> `100` 这个数在二进制里是 `1100100`，除了"能加减"之外没有任何好处；
> 而我们**只需要它每秒钟减 1、减到 0 停下**，从来不需要拿它做算术。
> 换成 BCD 后，"逢十借位"变成一次 4 位比较，除法器自然消失。

**本设计的做法**：`game_fsm` 的倒计时器**直接就是两位 BCD**
（十位 4 位 **0~4**、个位 4 位 0~9，见 §12.5；最长的第二关限时是 40 秒，十位到不了 5），
以 `o_game_cnt_bcd` 整字（8 位）送到本模块。
于是本模块里 `i_game_cnt_bcd(7 downto 4)` 直接就是十位、
`(3 downto 0)` 直接就是个位——**没有除法器**（前导零熄灭与关卡号 +1 是两个 4 位比较/加法，
见 §11.3 的数码管进程，量级可忽略；"零逻辑"仅指 `/10` 这类运算消失）。

| 方案 | 代价 | 结论 |
|---|---|---|
| 二进制存储 + `/10` `mod10` | 一个通用除法器（30~60 LE） | ✗ |
| 二进制存储 + 双 dabble（加 3 移位） | 一个移位累加状态机 + 时序控制 | ✗ 需要节拍、要等 |
| **BCD 存储 + 直接接线** ⭐ | **0**（十进制计数本来就是 BCD 的天然形态） | ✅ **本设计** |

> **这条也适用于 `preview_cnt`**：预览倒计时只数到 5（3 位二进制足够），
> 不走 BCD —— **不是为了省逻辑，而是 5 以内的数不存在"两位十进制"的问题**。
> **省逻辑要省在真有开销的地方，别为省而省。**

### 11.5 设计要点

| 要点 | 说明 |
|---|---|
| **纯组合，无时钟** | 给输入立刻出输出，最容易仿真（100% 覆盖） |
| **倒计时用 BCD 而非二进制** | 省掉除法器（见 §11.4） |
| **所有输出在任何状态下都被赋值** | 防 latch |
| **`o_blank` 与 `o_disp_val` 分离** | "显示 0"与"熄灭"语义不同 |

-- 连发（§12.7）
signal r_repeat_cnt  : integer range 0 to REPEAT_DELAY;  -- 3 位
-- 自检计时（要求 1）
signal r_self_cnt    : integer range 0 to 2 * T_SELFTEST;  -- 3 位（0~4，纯 2 的幂不用比较器）

-- ★ 进程内部的迭代量 v_* 是 variable，不占寄存器、不在此列
```

> **合计 45 个触发器**（3+1+3+4+4+**1**+8+8+1+5+1+3+**3**），**全部带 `range` 或明确位宽**
> （★ 2026-09-18 审查加 `r_cnt_load` 1 位、加 `r_self_cnt` 3 位，原为 41；
> ⚠️ 自检 2 秒计时那个计数器此前**不在清单里** —— 注记①（§12.4）用 `i_tick_2hz`
> 数 4 个脉冲，却没有对应的寄存器，正是"信号用着却没有出生地"的同型缺口 / `game_fsm-06`）
> —— 本项目最大的一笔隐性浪费就是裸 `integer`（`CLAUDE.md` §10.2 ①）。
> ⚠️ **这一节是被"漏"出来的**：原先 §12 从头到尾**没有寄存器声明**
> （§10.3 给 `puzzle_ctrl` 列了、§12 却一直没列），
> 于是 `r_state` / `r_cnt_tens` / `r_seed` 这些信号**在代码里用着、却没有出生地**。
> **列在这里的另一个用处**：写 `game_fsm` 时可以照着数一遍总触发器数，
> 与本模块的资源预算对账。

**输出接线（★ 2026-09-18 审查补）**：下面 4 个状态类输出原先在 §12 全节**没有任何赋值行**
（`o_game_cnt_bcd` 的拼接方向甚至只在**消费侧**写明），写码时无处可抄。现逐行定死：

```vhdl
o_state        <= r_state;
o_level        <= r_level;
o_preview_cnt  <= r_preview_cnt;
o_game_cnt_bcd <= r_cnt_tens & r_cnt_ones;   -- ★ 十位在 (7..4)、个位在 (3..0)，与 docs/01 §5.9 一致
```

> ⚠️ **拼接顺序写反（`r_cnt_ones & r_cnt_tens`）同样"自然"**，但会让 DISP4/DISP3 显示互换
> —— 30 秒显示成 "03"；而 `disp_format` 自己的 TB 直接注入 `i_game_cnt_bcd`、天然查不出
> 这个错，只有 §12.9-4 以 0x30 整字作期望才兜得住。**位序是生产侧的契约，写反即静默错。**

> ⭐ **本模块没有 `i_rnd` 端口 —— 随机数在本模块内部产生**（2026-09-17 删除该端口）。
> `game_fsm` 内部有一个 **8 位自由运行计数器**（除 `rst` 外从不停止，每个 `clk` 加 1），
> 在**"开始"键按下那一拍采样一次**：
>
> ```vhdl
> -- 自由运行计数器（8 个触发器，不停）
> process (clk)
> begin
>     if rising_edge(clk) then
>         if rst = '1' then
>             r_free <= (others => '0');
>         else
>             r_free <= r_free + 1;            -- ★ 无条件自增，没有使能
>         end if;
>     end if;
> end process;
>
> -- 采样：按"开始"那一拍把当前值锁进种子寄存器
> process (clk)
> begin
>     if rising_edge(clk) then
>         if rst = '1' then
>             r_seed       <= (others => '0');
>             r_seed_load  <= '0';
>         else
>             r_seed_load <= '0';              -- 默认：装载脉冲只有一拍
>             if i_key_press = '1' and s_act_start = '1' then
>                 -- ★ 防全零：LFSR 全 0 是吸收态（§9.4）。
>                 --   2026-09-18 审查修正：原先写 `or x"01"`，把 **bit0 恒置 1**，
>                 --   而 §12.6 的图案选择恰好读 r_seed(0)（`"001" when r_seed(0)='0'`）
>                 --   → o_pattern_sel 恒为 "010"，**上箭头永远选不到，提高②静默失效**。
>                 --   改置 bit1：同样保证非全零，且**所有位仍然随机**
>                 --   （ERR-0020 / 报告 pattern_rom-1）。
>                 r_seed      <= r_free or x"02";
>                 r_seed_load <= '1';          -- 通知 rng_lfsr 装种子
>             end if;
>         end if;
>     end if;
> end process;
>
> o_seed      <= r_seed;
> o_seed_load <= r_seed_load;
> ```
>
> **为什么不用 `rng_lfsr.o_rnd` 当种子**：`rng_lfsr` 只在 `puzzle_ctrl` 请求时步进
> （`docs/01` §2.1 连线表第 4 条），复位后的值由种子决定 —— **拿它的输出当种子是循环论证**；
> 而且那会在 S3 与 S5 之间造出**第二个回环**，
> 破坏 §2.1"本设计只有一条反馈回路"那条结论（§2.1.1 第 4 处）。
> 自由运行计数器与采样时刻无关：**采到哪个值完全取决于人按"开始"的时机**，
> 代价只有 8 个触发器。
>
> ⚠️ **`o_blink` 必须由 `i_tick_100` 分频得到，不能直接把 `i_tick_2hz` 送出去**：
> 本项目所有节拍都是**单周期使能**（一个 `clk` 宽），不是方波；
> 把使能当方波送给 `disp_format`，会得到"每个 clk 亮一下"的不可见闪烁。
> 正确做法是 `i_tick_100` ÷ 25 得 4Hz，再二分频 → **2Hz 方波**（占空比 50%）：
>
> ```vhdl
> -- 100Hz ÷ 25 = 4Hz，再每来一次翻转 → 2Hz 方波
> process (clk)
> begin
>     if rising_edge(clk) then
>         if rst = '1' then
>             r_blink_div <= 0;
>             r_blink     <= '0';
>         elsif i_tick_100 = '1' then
>             if r_blink_div = CNT_BLINK then   -- 0~CNT_BLINK 共 25 个数（★ 常量在 §2.6）
>                 r_blink_div <= 0;
>                 r_blink     <= not r_blink;   -- ★ 翻转，不是置 1
>             else
>                 r_blink_div <= r_blink_div + 1;
>             end if;
>         end if;
>     end if;
> end process;
>
> o_blink <= r_blink;
> ```
>
> **为什么是"翻转"而不是"计数到一半置 1、再置 0"**：翻转写法只需要 1 个触发器
> 表达状态本身，占空比天然 50%，也不会因为改分频比而出现"亮 2 秒灭 1 秒"。
> ⚠️ **`i_blink` 只在 `S_SELF_TEST` 期间被 `disp_format` 用**（§11.3），
> 其他状态下它照样在跑，只是没人看 —— **代价是 1 个触发器，不值得为它加使能条件**。

> ⚠️ **为什么删掉 5 个 `i_key_*` 换成 2 个原始信号**：
> 原方案让 `keypad_scan` 自己判断"哪个键号是方向键"，
> 那等于**把游戏规则写进了器件驱动模块** —— 换一种游戏就得重写键盘驱动。
> 现在 `keypad_scan` 只回答"**按了哪个键**"（键号 1~16），
> "**这个键意味着什么**"由本模块回答。职责边界因此干净：
> `keypad_scan` 是纯器件驱动（`docs/01` §1.1.2），本模块是游戏规则。

**键号译码表**（本模块内的第一段组合逻辑，也是"游戏规则"的一部分）：

| 动作 | 键号 | 按键位置（`docs/01` §4.6） |
|---|---|---|
| 上 | **2** | ROW3 · COL1 |
| 开始 | **4** | ROW3 · COL3 |
| 左 | **5** | ROW2 · COL0 |
| 下 | **6** | ROW2 · COL1 |
| 右 | **7** | ROW2 · COL2 |
| 选择 | **8** | ROW2 · COL3 |
| 确认 | **12** | ROW1 · COL3 |

```vhdl
-- 键号 → 动作的一对多译码，只写在这一个进程里
-- ⭐ 译码结果必须是【信号】s_act_*，不能是进程内 variable（2026-09-18 审查修正）：
--   它们还要被 §12.2 的种子采样进程、§12.7 的连发进程、以及下方的并行转发引用，
--   variable 出不了进程 —— 原骨架在另一个进程里引用 v_act_start，根本编译不过。
signal s_act_up, s_act_start, s_act_left, s_act_down : std_logic;
signal s_act_right, s_act_sel, s_act_conf            : std_logic;

process (i_key_code)
begin
    -- 默认值先行，防 latch（§1.2 规范）
    s_act_up    <= '0';  s_act_start <= '0';
    s_act_left  <= '0';  s_act_down  <= '0';
    s_act_right <= '0';  s_act_sel   <= '0';
    s_act_conf  <= '0';
    -- ⚠️ 选择表达式是 **5 位**（i_key_code : std_logic_vector(4 downto 0)，键号 1~16），
    --    所以每个 choice **必须也是 5 位**。2026-09-18 审查修正：原写 4 位字面量
    --    （"0010"…"1100"），与选择表达式长度不符 → 编译不过或恒不匹配、七个键全失效
    --    （ERR-0020 / 报告 INT-3）。
    case i_key_code is
        when "00010" => s_act_up    <= '1';   -- 键 2  上    （2  = 0b00010）
        when "00100" => s_act_start <= '1';   -- 键 4  开始  （4  = 0b00100）
        when "00101" => s_act_left  <= '1';   -- 键 5  左    （5  = 0b00101）
        when "00110" => s_act_down  <= '1';   -- 键 6  下    （6  = 0b00110）
        when "00111" => s_act_right <= '1';   -- 键 7  右    （7  = 0b00111）
        when "01000" => s_act_sel   <= '1';   -- 键 8  选择  （8  = 0b01000）
        when "01100" => s_act_conf  <= '1';   -- 键 12 确认  （12 = 0b01100）
        when others  => null;                 -- 空白键位与"无键"都不产生动作
    end case;
end process;

-- ⭐ "选择" / "确认"脉冲转发（2026-09-18 审查补：原先这两个端口没有任何赋值逻辑）
--   只在 S_PLAYING 转发；i_key_press 本身就是一拍脉冲，所以这里用并行赋值即可
o_sel_out  <= '1' when (i_key_press = '1' and s_act_sel  = '1' and r_state = S_PLAYING) else '0';
o_conf_out <= '1' when (i_key_press = '1' and s_act_conf = '1' and r_state = S_PLAYING) else '0';
```

> ⭐ **为什么用 `case` 而不是七个比较**：键号取值只有 7 个有意义，
> `case` 综合成**一个译码器**（§10.2 ④ 的"共享运算资源"思路）；
> 而且在语法上**强制覆盖全部 16 种取值**（`when others`），
> 不会出现"漏了某个键"这种查不出来的 bug。

> **两个输入的配合方式**（决定单次脉冲与连发，见 §12.7）：
> `i_key_press` 是**一拍脉冲**，用于"新按下"这类一次性动作（开始 / 选择 / 确认）；
> `i_key_code /= 0` 是**电平**，用于"还按着"的判定（方向键连发）。
> 两者都来自 `keypad_scan` 同一个消抖状态，**天然同步，不会有竞争**。

### 12.3 状态编码

**常量定义在 `puzzle_pkg` §2.7**（唯一真值源），本表只作说明：

| 状态 | 编码 | 含义 | 进入时的动作 |
|---|---|---|---|
| `S_SELF_TEST` | `"000"` | 开机自检 | 点阵全黄 2Hz 闪烁（`o_blink` 驱动 `disp_format`） |
| `S_IDLE` | `"001"` | 待机 | 点阵灭，DISP7 显 5 |
| `S_PREVIEW` | `"010"` | 图案预览 | 点阵显示完整目标图案，`preview_cnt` ← 5 |
| `S_PLAYING` | `"011"` | 拼图中 | **无动作** —— 零片**早已在进入本状态之前散落完毕**（见 §12.8 要点 6 的时刻契约） |
| `S_WIN` | `"100"` | 胜利 | 点阵显示胜利图案 |
| `S_FAIL` | `"101"` | 失败 | 点阵显示失败图案 |

> **为什么用 3 位编码而不是 one-hot**：6 个状态用 3 位足够；
> one-hot 在 CPLD 上未必更快，且状态译码逻辑更多。
>
> ⚠️ **点阵内容由 `disp_format` 按本节这张表决定**（§11.3 的"点阵显示什么"）——
> `game_fsm` 只输出 `o_state`，**不碰像素**。这是"只管时间、不做空间"那条分界的又一处体现。

#### 12.3.1 本状态机属于哪一类 ⭐（答辩必问，课件 p30–32）

课件 p30–32 明确要求能说清"**Moore 还是 Mealy**"与"**三进程/双进程/单进程**"。
本设计一次说清，**不要到答辩现场临时判断**：

| 分类轴 | 本设计 | 依据 |
|---|---|---|
| **输出类型** | **Moore 型**（带两处 Mealy 例外） | 全部输出（`o_state` · `o_level` · `o_pattern_sel` · `o_blink` …）**只由当前状态与内部计数器决定**，不直接由输入组合产生。<br>输入只影响**次态**（`i_key_press` → 迁移），不影响当拍输出。<br>⚠️ **带 Mealy 成分的例外是 `o_sel_out` / `o_conf_out`**：它们由 `i_key_press`（输入）**直接组合**产生（§12.2 末尾的并行赋值）—— 答辩时主动说明这两处，而不是被问出来。<br>⚠️ **2026-09-18 审查 `pdf-2` 更正**：原先列的例外是 `o_dir_out`，但它写在 `rising_edge(clk)` 进程里（§12.7），是**寄存输出**、不是组合路径，已从例外名单移除 |
| **进程描述方式** | **双进程 · 形式 2** —— 进程 1 = 次态逻辑 + 状态寄存器；进程 2 = 输出逻辑 | 进程 1 = §12.4 的主时钟进程：`case r_state` 判定迁移、**同一进程内装载 `r_state`**（§12.6 的片段即此写法）；进程 2 = 输出逻辑，本设计用**并行条件赋值**实现（`o_pattern_sel` §12.6、`o_sel_out`/`o_conf_out` §12.2）—— 与"纯组合输出进程"等价，只是不套 `process` 壳。<br>与课件 p32 原表逐字对应："**形式 2：进程1 描述次态逻辑、状态寄存器；进程2 描述输出逻辑**"。<br>⚠️ **2026-09-18 审查 `pdf-2` 更正**：原写"形式 1"（进程 1 = 次态**组合**逻辑 + 输出），与本设计骨架不符 —— 形式 1 必须有次态信号（组合算 `s_next`、时钟沿装载），而本设计没有（迁移分支直接写 `r_state <= …`）。`o_dir_out` 因"每拍清零、单拍脉冲"另有一个寄存进程（§12.7），属连发逻辑、不计入状态机本体的进程数 |
| **为什么不用三进程** | — | 三进程把"次态逻辑"与"状态寄存器"再拆成两个进程，**要多一根次态信号**（组合算次值、时钟沿装载）；本设计（形式 2）让迁移分支**直接写 `r_state`**（§12.6），少一层信号、少一处"忘赋值"的隐患 |
| **为什么不用单进程** | — | 单进程要求**输出逻辑也写进那唯一一个时钟进程**（次态 + 寄存器 + 输出全在一起），**仿真时状态跳变与显示的因果关系看不出来**，而评分项③要的就是波形可判读；本设计把状态相关输出留在并行赋值里（见"进程描述方式"行），状态进程只装"迁移 + 寄存器 + 事件类输出" |

> ⚠️ **另有若干与状态机并行、但不属于状态机的时序进程**（倒计时 §12.5、连发 §12.7、
> 闪烁分频 §12.2）—— 它们各管一个计数器，**不参与状态编码**。
> 课件说的"三/双/单进程"是**状态机本体**的描述方式，别把这些并行计数器算进去。

### 12.5 倒计时器（BCD）

> ⭐ **本节在 2026-09-18 审查后改正了「多重驱动」**（ERR-0020 / 报告 `pdf-1`）：
> 原先**装载**写在状态进程（§12.6）、**递减**写在本进程 ——
> **同一对寄存器被两个进程赋值**，Quartus 报 multi-driver，**照抄编译不过**，
> 而且违反课件 **p58「多重驱动」**（项目对照表原先把这条标成"✅ 已规避"，标错了）。
>
> **改正后的分工（一个信号只有一个写者）**：
>
> | 谁 | 做什么 | 写什么 |
> |---|---|---|
> | **状态进程**（§12.4/§12.6） | 决定**何时**装载 | 只写 **`r_cnt_load`**（1 个 clk 宽的脉冲） |
> | **本节进程** | 真正**装载与递减** | **独占** `r_cnt_tens` / `r_cnt_ones` |
>
> `r_cnt_load` 是**模块内部信号**（不是端口），**唯一写者是状态进程**、**唯一读者是本节**。

```vhdl
-- 两位 BCD 倒计时：装载与递减都在本进程内，避免多重驱动与除法器
signal r_cnt_load : std_logic;      -- 装载请求脉冲（由状态进程给，1 个 clk 宽）

process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_cnt_tens <= (others => '0');
            r_cnt_ones <= (others => '0');
        elsif r_cnt_load = '1' then
            -- ★ 装载：按当前关卡选 30 / 40（常量折叠，不产生除法器）
            if r_level = '0' then
                r_cnt_tens <= to_unsigned(T_LEVEL1 / 10, 4);
                r_cnt_ones <= to_unsigned(T_LEVEL1 mod 10, 4);
            else
                r_cnt_tens <= to_unsigned(T_LEVEL2 / 10, 4);
                r_cnt_ones <= to_unsigned(T_LEVEL2 mod 10, 4);
            end if;
        elsif r_state = S_PLAYING and i_tick_1hz = '1' then
            if r_cnt_ones = 0 then
                if r_cnt_tens = 0 then
                    null;                       -- 已到 0，保持不变
                else
                    r_cnt_tens <= r_cnt_tens - 1;   -- 借位
                    r_cnt_ones <= 9;
                end if;
            else
                r_cnt_ones <= r_cnt_ones - 1;
            end if;
        end if;
    end if;
end process;
```

> **`r_cnt_tens = 0 and r_cnt_ones = 0` 时必须保持不变**，
> 否则会从 00 回绕到 99。
> **这是又一处"无符号减法回绕"**——本项目有三处同类陷阱：
> ① 像素跨行移位（§2.4）、② 锚点上移越界（§10.7）、③ 倒计时 00→99（本节）。
> **三者都要在仿真中专门验证**，这也是报告"故障及问题分析"的好素材。

> ⚠️ **`r_cnt_load` 的契约（漏了就会踩两个坑）**：
> ① **状态进程必须给它一个默认值 `'0'`**（每拍先赋 0、只在迁移分支赋 1），
> 否则它会一直保持高 → **倒计时永远在装载、永不递减**；
> ② **宽度 1 个 clk**，与 `CLAUDE.md` §10.1 的脉冲类契约一致。
>
> 装载的触发点是 **`S_PREVIEW → S_PLAYING` 迁移**（不是 `S_PLAYING` 期间每拍）。
> 阶段 4 装配主状态进程时（§12.4 末尾）**这条装载是必写项，漏了倒计时恒为 00**。

### 12.5A 预览倒计时（3 位二进制）⭐ 2026-09-18 审查补

> **为什么单独列**：§12.4 全部只写"预览 5 秒"与"装载"，**从 5 减到 1 的规则从来没有落笔**
> （全库 grep `r_preview_cnt` 只有声明与两处装载）。照现文实现，"预览几秒""DISP7 显不显示 0"
> 全靠实现者猜 —— 装载与递减还是**同一信号的写者**，正是 §12.5 多重驱动陷阱的另一半。

```vhdl
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_preview_cnt <= (others => '0');
        elsif r_state = S_PREVIEW and i_tick_1hz = '1' and
              r_preview_cnt /= 0 then
            r_preview_cnt <= r_preview_cnt - 1;
        end if;
    end if;
end process;
```

> **迁移规则（与 §12.4 的主状态进程配套，规则写死、不留猜的空间）**：
> 每个 `i_tick_1hz` 递减一次；**`r_preview_cnt = 1` 的那拍递减为 0 并同拍迁入 `S_PLAYING`** ——
> 即从装载计起 `5→4→3→2→1→0` 恰好 5 秒，DISP7 **不显示 0**（归档 `disp_format-2`）。
>
> **一个信号一个写者**：装载仍是 §12.2 的"开始"采样与 §12.6 的关卡切换分支里的单点赋值，
> 递减归本进程 —— 两处合起来仍只有一个写者；**不要把递减并进别的进程**。

### 12.6 关卡切换与图案选择

```vhdl
-- ★ 这是状态进程里"全锁 + 拼对"分支的一段，不是完整进程。
--   完整的状态进程（case r_state 的骨架）留到阶段 4 写，见 §12.4 末尾的说明。
if i_all_locked = '1' and i_solved = '1' then
    if r_level = '0' then
        r_level       <= '1';                       -- 进第二关
        r_state       <= S_PREVIEW;
        r_preview_cnt <= to_unsigned(T_PREVIEW, 3);
        -- ★ 倒计时**不在这里写**（会与 §12.5 的进程构成多重驱动）：
        --   这里只发一个装载请求，由 §12.5 的进程独占那对寄存器。
        --   下一关的 30/40 由 §12.5 按 r_level 选，此处不必知道是哪个常量。
        r_cnt_load    <= '1';
    else
        r_state <= S_WIN;                           -- 第二关通过 → 胜利
    end if;
end if;
-- ⚠️ 进入 S_PLAYING 的那条迁移分支同样要发 `r_cnt_load <= '1';`（见 §12.4 的边表）。
-- ⚠️ 本进程**开头必须有默认值** `r_cnt_load <= '0';` —— 否则它会一直为高。

-- 提高要求②：多图案随机 —— 第二关在"向上箭头 / 向下箭头"里二选一。
-- ★ 这是并行赋值（不在进程里），所以 "when ... else" 是合法的 VHDL-93。
--   它的输入 r_seed 在按"开始"那一拍就锁定了（见 §12.2 的自由运行计数器），
--   换句话说：**图案在开局时就定了**，而不是进第二关时才摇一次。
-- ⭐ 2026-09-18 审查修正：原先只按 r_level 输出 "000"/"001"/"010"，
--   S_WIN / S_FAIL 时 "011"(胜利) / "100"(失败) 永远不可达 —— 胜负图案画不出来。
--   现在状态优先：胜负态直接选对应图案（此时 r_level 的值已无关紧要）。
--   ⚠️ 副作用（2026-09-18 审查补）：本信号同时是 pattern_rom.i_sel，于是
--   pattern_rom.o_mask（→ puzzle_ctrl.i_target_mask）在胜负态**变成了显示图案**；
--   而 r_locked 尚未清（§10.3）、puzzle_ctrl.o_all_locked 仍为 1 —— 凑出“全锁 + 没拼对”的假象。
--   **判失败那条边必须限定在 S_PLAYING 分支里检查**（§10.8 / §12.9 验证点 8），
--   否则进 S_WIN 的下一拍就被自己判成失败、胜利图案永远画不出来。
o_pattern_sel <= "011" when r_state = S_WIN  else   -- 胜利图案
                 "100" when r_state = S_FAIL else   -- 失败图案
                 "000" when r_level = '0'     else   -- 第一关：固定 4×3 矩形
                 "001" when r_seed(0) = '0'   else   -- 第二关：向上箭头
                 "010";                              -- 第二关：向下箭头
```

| 关卡 | `o_level` | `o_pattern_sel` | 限时 |
|---|---|---|---|
| 第一关 | `'0'` | `"000"`（固定 4×3 矩形） | 30 秒 |
| 第二关 | `'1'` | `"001"` 或 `"010"`（**随机二选一**） | 40 秒 |

> **提高要求②「多种拼图图案随机选择」在此实现**：
> 第二关的图案取自**开局的种子**（`r_seed(0)`）—— 向上箭头或向下箭头，
> 两种图案格数相同（18 格）、零片分解相同（6+6+4+2），但目标不同。
>
> ⚠️ **铁律（2026-09-18 审查新增）：图案选择位不得取"被防全零强制置 1 的那一位"。**
> 本条与 §12.2 的种子采样是**配套约束** —— 那边写 `r_seed <= r_free or x"0X"`，
> `X` 是哪一位，这边就**不能**用哪一位。
> 违反它的后果是**静默的**：代码能编译、能跑、波形"看着正常"，
> 只是**永远只出现一种图案**（ERR-0020 / 报告 `pattern_rom-1`）。
> **改任一处时必须同时看另一处。**
>
> ⚠️ **原先这里写的是 `r_pattern_sel <= "001" when i_rnd(0) = '0' else "010";`，两处都有问题**：
> ① `i_rnd` **端口已删**（§12.2），随机源改成本模块内部的自由运行计数器；
> ② 它写在**进程内**，而条件信号赋值的 `when/else` 形式
>    **在进程里是 VHDL-2008 才允许的**（`CLAUDE.md` 硬约束 7 要求 VHDL-93）。
>    改成**并行赋值**后两个问题一起消失 —— 既不需要 `i_rnd`，语法也在 VHDL-93 内。
>
> **为什么用 `r_seed(0)` 而不是"进第二关时再摇一次"**：
> 用的是**同一笔已经采到的随机数**，**零额外硬件**（`r_seed` 本来就要存），
> 也**不用在状态迁移里多做一件事**。玩家看不出图案是开局定的还是进关时定的 ——
> 因为第一关的预览显示的始终是固定矩形，第二关的图案在进关前根本不会出现。

> ⭐ **`T_LEVEL2 / 10` 和 `T_LEVEL2 mod 10` 不产生除法器。**
> 它们是**常量表达式**（`T_LEVEL2` 是 `puzzle_pkg` 里的 `constant`），
> 在 **elaboration 阶段就被折叠成字面量** —— `T_LEVEL2 = 40` 时
> 这两行等价于 `to_unsigned(4, 4)` 和 `to_unsigned(0, 4)`，
> **综合器看到的只是两个常数**，硬件上什么都没有。
>
> **判断标准很简单：除法器只在"被除数是信号"时才会生成。**
> 被除数是常量 → 编译期算完；被除数是信号 → 真的要搭一个除法器网络。
> 这条同样适用于 `puzzle_pkg` 里那 6 个 `CNT_* = CLK_HZ / xxx - 1`
> （见 §2.6）—— **整个项目一处硬件除法器都不该出现**。
>
> **反过来说**：如果哪天写成 `to_unsigned(i_rnd / 10, 4)`，
> 那就是真的除法器了 —— **`docs/02` §11.4 开头那个 ✗ 例子正是这种**。

### 12.7 方向键连发

**行为**：按下的**那一拍立即响应一次**（不能有延迟感），
之后"**按住 500ms → 每 100ms 重复一次**"（对应键盘的 typematic 行为）。

```vhdl
-- ★ REPEAT_DELAY / REPEAT_PERIOD 两个常量在 §2.6 单点定义
-- ★ r_repeat_cnt 的声明在 §12.2 的寄存器清单里（必须带 range：0~5 → 3 位）

-- 连发计时：只在"方向键被按住"时走
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_repeat_cnt <= REPEAT_DELAY;
        elsif i_key_press = '1' and s_is_dir = '1' then
            -- ★ 重置必须放在 tick_100 闸门**外**（2026-09-18 审查改，game_fsm-04）：
            --   原先它写在 `elsif i_tick_100 = '1' then` 之内，而 i_key_press 是
            --   1 个 clk 宽的脉冲（CLAUDE.md §10.1），与每 10ms 才出现一拍的
            --   tick_100 基本不可能同拍 —— 重置形同废弃：计数器从**上一次的值**
            --   继续递减，只要它已减到 0，玩家一按住就立刻连发（想微调一格，
            --   零片却自己滑走），"按住 500ms 才开始连发"名存实亡。
            r_repeat_cnt <= REPEAT_DELAY;              -- 新按下：立刻重置为 500ms
        elsif i_tick_100 = '1' then
            if s_is_dir = '1' and r_repeat_cnt > 1 then
                r_repeat_cnt <= r_repeat_cnt - 1;      -- 还按着：每 100ms 减 1
            end if;
        end if;
    end if;
end process;

-- 方向脉冲：新按下 或 连发到期，都出一拍
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            o_dir_out <= "0000";
        elsif r_state /= S_PLAYING then
            o_dir_out <= "0000";                       -- 非拼图状态：方向键无效
        else
            o_dir_out <= "0000";                       -- 默认每拍清零（保证是脉冲）
            if i_key_press = '1' and s_is_dir = '1' then
                o_dir_out <= s_dir_code;               -- 首次：立即响应
            elsif i_tick_100 = '1' and s_is_dir = '1' and r_repeat_cnt = 1 then
                -- 连发：★ 判据用 `= 1`（到期拍），同时把计数**清零**。
                --   输出进程在"递减到 1 的那一拍"读到的正是沿前的 1，脉冲宽 1 个 clk；
                --   清零与出拍同拍发生，于是**首次连发恰好落在 500ms**。
                --   原先判 `= 0`：计数器要 5 拍才减到 0、输出进程还要再等一拍读到 0，
                --   首次连发实际是第 6 拍 = 600ms，与 §12.9-10 的"1 + 5"对不上（game_fsm-04）。
                r_repeat_cnt <= 0;
                o_dir_out <= s_dir_code;
            end if;
        end if;
    end if;
end process;
```

其中 `s_dir_code` 由 §12.2 的译码结果打包而成（★ 与译码输出同为**信号**，见 §12.2 的修正说明）：

```vhdl
-- 上/下/左/右 → 4 位独热，与 puzzle_ctrl.i_dir 的编码一致（docs/01 §5.8）
s_dir_code <= s_act_up & s_act_down & s_act_left & s_act_right;
s_is_dir   <= s_act_up or s_act_down or s_act_left or s_act_right;
```

**为什么用 `i_key_code` 而不是"方向键脉冲"做连发的门控** ⭐：

| | 旧写法（已废弃） | 现写法 |
|---|---|---|
| "还按着"从哪来 | 需要 `keypad_scan` 再输出一路 `i_key_down`(4) | `i_key_code /= 0` **已经包含了这个信息** |
| 多出来的信号 | **+4 位输出 +4 位输入 + 顶层 4 根线** | **0** |
| 会不会不一致 | 会 —— 两路信号描述同一件事，就有不同步的可能 | 不会 —— **只有一份事实** |

`i_key_press` 只在"新按下"那一拍为 1，**按住不放时它一直是 0**，
所以它不能用来判断"是否还按着" —— 那正是 `i_key_code` 的职责。
**两个输入各回答一个问题，没有冗余**（`docs/01` §5.2 的 `o_key_down` 删除理由与此相同）。

**参数与计时精度**：

| 常量 | 值 | 依据 |
|---|---|---|
| `REPEAT_DELAY` | 5（× 100ms = **500ms**） | 约半秒的"按住"阈值，手感自然 |
| `REPEAT_PERIOD` | 1（× 100ms = **100ms**） | 每秒 10 格，8×8 的盘面横穿一次 0.7 秒，够快 |

> ⚠️ **`r_repeat_cnt` 的 `range` 必须给全**（声明见本节开头）：
> 它从 `REPEAT_DELAY`（=5）递减到 0，所以范围是 `0 to REPEAT_DELAY`。
> **裸 `integer` 在 Quartus 里是 32 位**（§1.2、`CLAUDE.md` §10.2 ①）——
> 3 位 vs 32 位，这一个 `range` 省 29 个触发器。
>
> ⚠️ **`REPEAT_PERIOD` 取 1，所以代码里没有出现它**：
> 减到 0 即到期，**"倒计时到零"本身就是那个周期**，不需要第二个计数器。
> 若哪天要把连发调慢到每 200ms 一次，`REPEAT_PERIOD` 改成 2，
> 那时上面"方向脉冲"进程里的判据 `r_repeat_cnt = 1` 就要改成再串一级周期计数器 ——
> **这个常量留着，是为了让"想调快调慢"这件事有一个名字**。

### 12.7A 音效触发点（`o_sound_sel` / `o_sound_trig`）⭐ 2026-09-18 审查补

> **补入原因**：`o_sound_sel` / `o_sound_trig` 两个端口原先**全节没有任何赋值逻辑**
> （与 ERR-0011 的 `i_trigger` 无驱动源是同族缺口，本次审查在"内容完整性"维度暴露）。
> 音效全是**本模块产生的事件**，触发点必须在这里逐个定义（提高要求①）。

| 事件 | `o_sound_sel` | 触发条件（各出 1 个 `clk` 的 `o_sound_trig` 脉冲） |
|---|---|---|
| 按键 | 1 | `i_key_press='1'` 且译码命中（`s_act_*` 任一为 1），任意状态 |
| 移动 | 2 | `o_dir_out /= "0000"` 的那一拍（含连发） |
| 锁定 | 3 | `S_PLAYING` 且 `i_key_press='1'` 且 `s_act_conf='1'` |
| 预览倒计时每秒 | 4 | `S_PREVIEW` 且 `i_tick_1hz='1'` 且 `r_preview_cnt > 0` |
| 拼图倒计时最后 5 秒 | 5 | `S_PLAYING` 且 `i_tick_1hz='1'` 且倒计时 ≤ 0x05 且 > 0x00 |
| 胜利 | 6 | 状态迁入 `S_WIN` 的那一拍 |
| 失败 | 7 | 状态迁入 `S_FAIL` 的那一拍 |

- `o_sound_trig` 一律是**单周期脉冲**（与 `o_round_start` 同类，§12.8 要点 6/9）；
- `o_sound_sel` 是电平，**`buzzer_ctrl` 在 `i_trigger` 那一拍把它锁存**（`docs/02` §13.4 的
  `r_play`），因此播放期间本模块把它改成别的值也不影响本次播放；
- 装载到状态进程里时，每个触发点对应主 `case r_state` 的一个分支动作，
  **不新增状态、不改变任何迁移**。

### 12.8 设计要点

| # | 要点 | 说明 |
|---|---|---|
| 1 | **完全不含坐标运算** | 与 `puzzle_ctrl` 的职责分离（`01-系统设计.md` §1.2 原则一） |
| 2 | **倒计时用 BCD** | 省掉除法器（§11.4）；**"哪个键是什么动作"也在这里译码**（§12.2） |
| 3 | **倒计时 00 后保持不变** | 防回绕到 99 |
| 4 | **"开始"键在任意 6 个状态都生效** ⭐ | **直接进 `S_PREVIEW`**（不经过 `S_IDLE`），等于"重开一局"：`r_level`←`'0'`、重新采样种子、清锁定、`r_preview_cnt`←`T_PREVIEW`。详见 §12.4 的边表 |
| 5 | **种子在按下"开始"时采样** | 采样自由运行计数器低位；因为按键时刻由人决定，采样值不可预测 |
| 6 | **`o_round_start` 是单周期脉冲 —— 且触发时刻已定死** ⭐ | **宽度 1 个 clk**；**触发时刻 = 进入 `S_PREVIEW` 的那一拍**（不是进入 `S_PLAYING` 时）。<br>⚠️ **2026-09-18 审查定死**（ERR-0020 / 报告 `puzzle_ctrl-1`）：此前文档里有**两个互斥说法** —— §12.3 写"进 `S_PLAYING` 时发"，而 §12.9 验证点 12 与 §10.6 的节拍预算（"远在预览结束后第一个 `tick_1hz` 之前完成"）都按"进 `S_PREVIEW` 时发"写。<br>**为什么必须是 `S_PREVIEW` 入口**：散落序列器要跑若干拍才完成（§10.6），若在 `S_PLAYING` 入口才启动，**倒计时会边散落边走**，玩家一进游戏就少掉开头的时间；而 `S_PREVIEW` 有整整 5 秒可用。<br>**两条边都要发**：① 任意状态按"开始"→ `S_PREVIEW`；② 第一关拼对 → `关卡←2` → `S_PREVIEW` |
| 7 | **方向键只在 `S_PLAYING` 状态转发** | 其他状态下按方向键无效果 |
| 8 | **键号译码只写一处** | `keypad_scan` 只回答"按了哪个键"，"这个键意味着什么"是游戏规则，在本模块（§12.2） |
| 9 | **`o_sound_trig` 是单周期脉冲** | 与 `o_round_start` 同类；**音效是"事件"，不是电平**，必须有人产生触发沿 |

## 13. `buzzer_ctrl` —— 蜂鸣器音效

### 13.1 职责

蜂鸣器音效产生

### 13.2 端口

| 端口 | 方向 | 宽度 | 说明 |
|---|---|---|---|
| `clk` `rst` | in | 1 | |
| `i_tick_8k` | in | 1 | 8kHz 时基 |
| `i_sound_sel` | in | 3 | 音效选择 |
| `i_trigger` | in | 1 | 触发脉冲（**单周期脉冲 + 电平装载**；脉宽 1 个 `clk` 由 `game_fsm` 保证，见 §13.5） |
| `o_buzz` | out | 1 | 方波输出 |

### 13.3 音效表（提高要求①）

| `i_sound_sel` | 场合 | 频率 | 时长 | 半周期 N（拍） | 时长（拍） |
|---|---|---|---|---|---|
| 0 | 静音 | — | — | — | 0 |
| 1 | 按键 | 2 kHz | 30 ms | 2 | 240 |
| 2 | 移动 | 1 kHz | 20 ms | 4 | 160 |
| 3 | 锁定 | 500 Hz | 80 ms | 8 | 640 |
| 4 | 预览倒计时每秒 | 1 kHz | 50 ms | 4 | 400 |
| 5 | 拼图倒计时最后 5 秒 | 4 kHz | 60 ms | 1 | 480 |
| 6 | 成功 | 2kHz↔4kHz 交替 | 400 ms | 2 / 1 | 3200（4 段 × 800） |
| 7 | 失败 | 500Hz↔250Hz 交替 | 600 ms | 8 / 16 | 4800（4 段 × 1200） |

**频率推导**：`f = 8000 / (2 × N)`，其中 `N` 是"每隔 N 个 `i_tick_8k` 翻转一次 `o_buzz`"。

- `N=1` → `8000/2` = **4 kHz**
- `N=2` → `8000/4` = **2 kHz**
- `N=4` → `8000/8` = **1 kHz**
- `N=8` → `8000/16` = **500 Hz**
- `N=16` → `8000/32` = **250 Hz**

**时长推导**：时长（拍） = 时长（ms） × 8（8kHz → 每拍 0.125ms）。

> ⚠️ **本节整张表有一个上板才能验的硬件前提（`buzzer_ctrl-4`）**：
> **板载蜂鸣器必须是无源的（方波频率决定音高）**，否则本表 7 种音效的音高全部相同，
> 提高要求①退化为"一声哔"。**首次上板必须确认**：自检阶段 8 放两个差别明显的音
> （500 Hz ↔ 2 kHz，见 `docs/01` §8.2），**判据是能听出高低**，而不是"有声音"。
> 另一半前提"静音电平 = `'0'`"（§13.5 `r_dur = 0` 时输出 '0'）由 `docs/04` §4 的极性总表登记。

### 13.4 关键逻辑

**查表常量**（声明在本模块内，模块私有——§2.6 的单点定义管的是**全局**分频/时间常量，
音效表只有本模块用，放包里反而制造不必要的耦合）：

```vhdl
type int_arr8_t is array (0 to 7) of integer;

-- ★ 存的是 N-1：计数器从 N-1 数到 0 共 N 拍，恰为半个周期
constant HALF_A : int_arr8_t := (0, 1, 3, 7, 3, 0, 1,  7);   -- 主音（交替音的第一段）
constant HALF_B : int_arr8_t := (0, 1, 3, 7, 3, 0, 0, 15);   -- 交替音的第二段（仅 6/7 用）
constant DUR    : int_arr8_t := (0, 240, 160, 640, 400, 480, 3200, 4800);  -- 总时长（拍）
constant SEG    : int_arr8_t := (0, 0, 0, 0, 0, 0, 800, 1200);             -- 交替段长（拍）

signal r_half : integer range 0 to 15;               -- 半周期计数（最大 N-1 = 15）
signal r_dur  : integer range 0 to 4800;             -- 剩余时长（13 位）
signal r_seg  : integer range 0 to 1200;             -- 当前交替段剩余
signal r_alt  : std_logic;                           -- 交替相位
signal r_play : std_logic_vector(2 downto 0);        -- ★ 触发时锁存的音效号
signal r_buzz : std_logic;                           -- ★ 方波内部寄存器（out 端口不可读，
                                                     --   见下方 ⚠️；2026-09-18 审查补）
```

```vhdl
process (clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            r_half <= 0;  r_dur <= 0;  r_seg <= 0;
            r_alt  <= '0';  r_play <= "000";  r_buzz <= '0';
        elsif i_trigger = '1' then
            -- ★ 触发那一拍：锁存音效号并装载三张表，之后 i_sound_sel 变化不影响本次播放
            r_play <= i_sound_sel;
            r_dur  <= DUR   (to_integer(unsigned(i_sound_sel)));
            r_seg  <= SEG   (to_integer(unsigned(i_sound_sel)));
            r_half <= HALF_A(to_integer(unsigned(i_sound_sel)));
            r_alt  <= '0';
            r_buzz <= '0';
        elsif i_tick_8k = '1' and r_dur /= 0 then
            -- 半周期翻转：r_half 从 N-1 数到 0，共 N 拍（★ 不是 N+1 拍，见下方注记）
            if r_half = 0 then
                r_buzz <= not r_buzz;      -- ★ 翻转内部寄存器，不是 out 端口
                if r_alt = '0' then
                    r_half <= HALF_A(to_integer(unsigned(r_play)));
                else
                    r_half <= HALF_B(to_integer(unsigned(r_play)));
                end if;
            else
                r_half <= r_half - 1;
            end if;
            -- 交替段推进（仅 sel 6/7 的 SEG 非零，其余音效 r_seg 恒 0、本段不动作）
            if r_seg /= 0 then
                if r_seg = 1 then
                    r_alt <= not r_alt;
                    r_seg <= SEG(to_integer(unsigned(r_play)));
                    -- ★ 段边界同步重载半周期计数（2026-09-18 审查补）：
                    --   否则新段的首个半周期沿用旧计数，产生相位毛刺
                    if r_alt = '0' then
                        r_half <= HALF_B(to_integer(unsigned(r_play)));  -- 即将进入 B 段
                    else
                        r_half <= HALF_A(to_integer(unsigned(r_play)));  -- 即将回到 A 段
                    end if;
                else
                    r_seg <= r_seg - 1;
                end if;
            end if;
            r_dur <= r_dur - 1;
            if r_dur = 1 then
                r_buzz <= '0';                  -- 播完静音（覆盖同拍的翻转赋值）
            end if;
        end if;
    end if;
end process;

-- ★ 端口只是内部寄存器的"出口"
o_buzz <= r_buzz;
```

> ⚠️ **为什么要多一个 `r_buzz`**（2026-09-18 审查，ERR-0020 / 报告 `buzzer_ctrl-1`）：
> 原骨架写的是 `o_buzz <= not o_buzz;` —— **读了 `out` 模式的端口**。
> **VHDL-93 不允许读 `out` 端口**，照抄**编译不过**；而且 `o_buzz` 一旦接上
> `sys_en` 输出级门控（`CLAUDE.md` §10.1），读到的会是门控后的值而不是内部状态，
> **逻辑本身也是错的**。正确写法就是本节这样：**内部寄存器翻转，端口只做出口**。

> ⚠️ **本节在 2026-09-18 审查时修了两处会让频率全错的缺陷**：
> ① 原骨架 `r_toggle_cnt <= HALF_PERIOD(sel)` 装载 **N** 再数到 0 —— 那是 **N+1 拍**，
>   实际频率变成 `8000/(2(N+1))`（2kHz 变成 1.33kHz），**每种音效全错，且仿真听感上不易察觉**。
>   现改为表里存 **N-1**；
> ② `HALF_PERIOD` / `DURATION` 两张查表**只有名字、没有定义**，
>   且"交替音用 r_dur_cnt 高位切换"只有一句话、无可综合的实现 —— 现补全三张表
>   （`HALF_A`/`HALF_B`/`DUR`/`SEG`）与交替段计数器。

### 13.5 设计要点

| 要点 | 说明 |
|---|---|
| **`i_trigger` 是「单周期脉冲 + 电平装载」，不是边沿检测** ⭐ | **2026-09-18 审查更正口径**（ERR-0020 / 报告 `buzzer_ctrl-3`）：本节代码写的是 `elsif i_trigger = '1' then`，**电平敏感、没有边沿检测电路**。<br>在**脉冲宽度 = 1 个 clk** 的契约下（`CLAUDE.md` §10.1）**行为正确**：脉冲只有一拍，装载只发生一次。<br>⚠️ **但若上游给出的脉冲宽于 1 拍**（例如老版本的 `keypad_scan` 给 1ms），它会在**每一拍重新装载** → 计时器永不推进 → **完全无声**（不是"重触发"，是"没声音"）。<br>**所以这条契约是双向的**：发出方保证 1 拍，接收方按 1 拍设计。若要更鲁棒，可照 `keypad_scan` 的写法加一级边沿检测（多 1 个触发器）|
| **触发时锁存 `i_sound_sel`** | 播放期间（最长 600ms）上游的 `o_sound_sel` 可能已变，不锁存会让音调中途跳变 |
| **半周期表存 N-1 不是 N** | 计数器数到 0 含 0 共 N 拍；存 N 会多数一拍，频率全错（§13.4 注记） |
| **时基用 `i_tick_8k` 而不是 `clk`** | 8kHz 已提供 125µs 分辨率，4kHz 音只需 N=1，正好够用；且省一个 26 位计数器 |
| **`r_dur = 0` 时输出 '0'** | 保证静音时蜂鸣器不响 |
| **交替音用独立的段计数器 `r_seg`** | 非交替音效 `SEG = 0`，同一段代码自动退化为单音，不为 6/7 写特例 |

### 13.6 仿真验证点

| # | 激励 | 期望 |
|---|---|---|
| 1 | `i_sound_sel=2`，给一个 `i_trigger` 脉冲 | `o_buzz` 输出 1kHz 方波，持续 20ms，然后恒 '0' |
| 2 | 数 `o_buzz` 在 20ms 内的翻转次数 | 恰好 `20ms / 0.5ms` = **40 次** |
| 3 | `i_sound_sel=0` | `o_buzz` 恒 '0' |
| 4 | 连续两个 `i_trigger` 脉冲 | 第二个中断第一个，重新开始计时 |
| 5 | 每一种 `i_sound_sel` 都测一遍 | 频率与 §13.3 表格一致 |
| 6 | **交替音的段结构**（`i_sound_sel=6`）：触发一次后按 `i_tick_8k` 数翻转节奏 | 0~799 / 1600~2399 拍**每 2 拍翻转**、800~1599 / 2400~3199 拍**每 1 拍翻转**，共 **4 段**；简化记法：100ms 分 4 个窗口数翻转次数 = **400 / 800 / 400 / 800**。`i_sound_sel=7` 同理（`SEG = 1200` 拍一段，4 段 × 1200 = 4800 拍，150ms 窗口 = **150 / 75 / 150 / 75**）。<br>⚠️ **为什么要这一条**：把 `SEG(6)` 误写成 1600（或 400）时，总时长仍是 400ms、2kHz↔4kHz 仍交替，**上面 5 条全绿**，只有交替次数从 4 段变 2 段 —— 与 ERR-0016 修的"频率/时长都对、结构错"是同一复现路径（2026-09-18 审查 / `buzzer_ctrl-2`） |

          --    （★ 系统级是 4 条：clk / sw7 / btn / kp_row —— 2026-09-18 审查更正，
          --       原写"2 条"、后补到 3 条；kp_row/kp_col 两条是本次补入的）
          -- ⚠️ 别名：同一根线上游叫 o_xxx、下游叫 i_xxx，中间必须有一个 s_xxx
          --    漏建一条 → 下游输入悬空，综合不报错（CLAUDE.md §10.3）
          -- ⚠️ **系统级四线不必建 s_*** ：`clk` 顶层直连各模块；`sw7` → `clk_gen.sys_en`；
          --    `btn` → `clk_gen.i_btn_rst`；`kp_row` → `keypad_scan.i_kp_row`。它们**都是顶层端口名
          --    直接进 port map**，没有"上游/下游改名"问题（但名字仍以 `.qsf` 的 `-to` 为准）。

begin

    -- ========== 例化（顺序同上面的声明块）==========

    -- 1. 时钟与节拍
    u_clk_gen : clk_gen
        port map (
            clk        => clk,
            sys_en     => sw7,
            i_btn_rst  => btn,          -- ★ 顶层端口 btn（不带 i_/o_ 前缀，见 docs/01 §5.12）
            o_rst      => s_rst,
            o_tick_8k  => s_tick_8k,
            o_tick_1k  => s_tick_1k,
            o_tick_100 => s_tick_100,
            o_tick_2hz => s_tick_2hz,
            o_tick_1hz => s_tick_1hz
        );

    -- 2. 键盘输入
    -- u_keypad_scan : keypad_scan port map ( ... );

    -- ... 其余 9 个例化 ...

    -- 12. 输出级 sys_en 门控（01-系统设计.md §1.2 原则三，见下方 §14.2）
end architecture;
```

#### 14.1.3 五条写法要求

| # | 要求 | 为什么 |
|---|---|---|
| 1 | **声明块与例化块同序**，都按「子系统 S1→S7 分组、组内按 DWG-02 从上到下」 | 组号可数（老师按 S1~S7 数框）；组内照图序，代码与图上下对应 |
| 2 | **例化标签统一 `u_<实体名>`** | 仿真波形与综合报告的层次名可读 |
| 3 | **端口关联一律具名**（`名字 => 信号`），**不用位置关联** | 位置关联在位宽/顺序变化时会静默连错 |
| 4 | **每个声明块上方一行中文注释**：职责 + 所属子系统 | 评分项⑧ 的现成素材 |
| 5 | ⭐ **端口一律照 `docs/01` §5 抄，不许凭印象写**；写完后从"线"这一侧反向核一遍 | 凭印象写必错；**反向核才查得出"没人驱动"**（`CLAUDE.md` §10.3 的可数动作） |

**⚠️ 顶层文件必须有完整中文注释**（评分项⑧ 10 分）。

#### 14.1.4 阶段 4 工程迁移三步（⭐ 2026-09-18 审查补）

当前 `quartus/puzzle.qsf` 为阶段 2 服务：**顶层 = `board_test_top`，源文件只有 6 个，
且含 16 行 `ld[15:0]` 引脚约束**。阶段 4 集成 `puzzle_top` 时**必须按序做这三步，缺一步编译必败**：

| # | 步骤 | 具体内容 |
|---|---|---|
| 1 | **追加 8 个源文件** | `pattern_rom` / `piece_rom` / `rng_lfsr` / `puzzle_ctrl` / `disp_format` / `game_fsm` / `buzzer_ctrl` / `puzzle_top`（`set_global_assignment -name VHDL_FILE`） |
| 2 | **切换顶层** | `TOP_LEVEL_ENTITY` 由 `board_test_top` 改为 `puzzle_top` |
| 3 | **删除 16 行 `ld` 引脚约束** | `puzzle_top` 没有 `ld` 端口，留着会得到"分配给不存在端口的引脚"错误（`ld[15:0]` 只属于 `board_test_top`，见 `docs/04` §2） |

> **不能用 `scripts/build.tcl --top puzzle_top` 代替这三步**：
> `--top` 只切换顶层名，源文件与 `ld` 约束的缺口它一个都补不了
> （且 `set_global_assignment` 会写回 `.qsf`，脚本内部已做"先存原值、关工程前还原"，2026-09-18 修正）。

### 14.2 输出级门控（唯一实现，见 `01-系统设计.md` §1.2 原则三）

```vhdl
-- 要求 1：SW7='0' 时所有显示器件不显示（严格零延迟）
dot_row  <= s_dot_row  when sw7 = '1' else (others => '1');   -- 低有效 → 全灭
dot_colr <= s_dot_colr when sw7 = '1' else (others => '0');
dot_colg <= s_dot_colg when sw7 = '1' else (others => '0');
seg      <= s_seg      when sw7 = '1' else (others => '0');
cat      <= s_cat      when sw7 = '1' else (others => '1');   -- 低有效 → 全灭
buzz     <= s_buzz     when sw7 = '1' else '0';
```

> ⚠️ **左边的名字是「顶层器件端口」，不带 `o_` 前缀** ——
> 与子模块端口 `o_seg`／`o_cat`／`o_dot_row`… 是**两套名字**，别混。
> **顶层端口名的真值源是 `quartus/puzzle.qsf` 的 `-to`**（`docs/01` §5.12）。
> 这一条是 2026-09-18 审查抓出来的（`ERRORS.md` ERR-0020 / 报告 `hw-01`）：
> 原稿这里写的是 `o_seg` 等模块端口名，而它自称"逐字可抄" → **照抄必然连不上**。

> ⚠️ **上面没有 `ld`** —— `ld[15:0]`（LED）**不是 `puzzle_top` 的端口**，
> 它只出现在上板自检顶层 `board_test_top` 里（`docs/01` §8）。
> 早先的版本在这里多写了一条 `o_ld <= s_ld when ...`，
> 那会让 `puzzle_top` 凭空多出 16 个引脚、并引用一个不存在的内部信号 `s_ld`。

### 14.3 顶层整机仿真

按 **13 个场景**设计激励（覆盖 11 条基本要求与提高项，详见 `docs/03-仿真验证方案.md`）：

> ⚠️ **第 13 条是 2026-09-18 审查补的**（ERR-0020 / 报告 `顶层与集成-3`）：
> 原表 12 条的"覆盖要求"列并集只到要求 1~10 与提高①② ——
> **要求 11「任意状态重开」与提高③「零片位置随机」一个顶层场景都没有**，
> 而顶层整机仿真正是"按用户视角把 11 条要求串起来跑"的唯一机会（评分项③要逐条给波形证据）。
> 这两条在第 13 条里一次跑掉：三个状态各按一次开始，重开多次看零片落点是否变化。

| 场景 | 覆盖要求 |
|---|---|
| 上电 → 自检闪烁 → 待机 | 1、2 |
| 待机显示 "5" 与关卡号 | 2、3 |
| 按"开始" → 预览 5 秒 → 游戏开始 | 4 |
| 倒计时递减、30 秒耗尽 → 失败 | 5 |
| 按"选择"循环切换，选中零片变绿 | 6 |
| 方向键移动、走到边界停住 | 7 |
| 按"确认"锁定变黄、锁定后不可移动 | 8 |
| 拼对 → 判定成功 → 进第二关 | 9、10（第一关） |
| 第二关拼对 → 胜利 | 10 |
| 第二关图案随机（重开多次，两种箭头都出现） | 提高② |
| 每次按键 / 锁定 / 胜负都有蜂鸣器音效 | 提高① |
| SW7=0 → 全部熄灭、蜂鸣器无声 | 1 |
| **预览 / 拼图中 / 失败态各按一次「开始」→ 均立即回到第一关预览，且零片重新随机散落** | **11**、提高③ |
