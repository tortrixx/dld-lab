## 1. 建立工程（路径 B；路径 A 可跳过）

### 1.1 新建工程向导

1. 启动 Quartus II 9.1：开始菜单 → **Quartus II 9.1**。
2. 菜单 **File → New Project Wizard** → Next。
3. **Directory, Name, Top-Level Entity**
   - 工作目录：选到仓库的 `quartus/` 文件夹（**不要选中文路径**）
   - 工程名：`puzzle`
   - 顶层实体名：先填 `board_test_top`（后面可改）
4. **Add Files**：把 `rtl/` 下这 14 个文件全部加入（Add → 逐个选，或直接选目录里全部 `.vhd`）：
   ```
   puzzle_pkg.vhd   clk_gen.vhd     keypad_scan.vhd   seg_scan.vhd
   dot_matrix_scan.vhd  pattern_rom.vhd  piece_rom.vhd  rng_lfsr.vhd
   puzzle_ctrl.vhd  disp_format.vhd  game_fsm.vhd     buzzer_ctrl.vhd
   puzzle_top.vhd   board_test_top.vhd
   ```
   > ⚠️ `puzzle_pkg.vhd` 是**包**不是实体，但**必须**加进工程，否则所有模块的
   > `use work.puzzle_pkg.ALL;` 都找不到定义。
5. **Family & Device**：Family = `MAX II`，Device = **`EPM1270T144C5`**
   （144 脚 TQFP、C5 速度等级 —— 选错器件会导致引脚号全部对不上）。
6. **EDA Tool Settings**：全部保持 `<None>`（仿真用 Quartus 自带仿真器）。
7. Finish。

### 1.2 必做的三项工程设置

菜单 **Assignments → Settings**（或写进 `.qsf`）：

| 项 | 位置 | 值 | 为什么 |
|---|---|---|---|
| VHDL 输入版本 | **Analysis & Synthesis Settings → VHDL Input** | **VHDL 1993** | 本工程代码是 VHDL-93 子集（不用 2008 语法） |
| 综合优化目标 | **Analysis & Synthesis Settings → Optimization Technique** | **Area** | 课件 p50 例4 明确要求；EPM1270 只有 1270 个 LE，且本设计对速度无要求。**默认是 Balanced，必须显式改** |
| 未使用引脚 | **Device → Unused Pins** | **As input tri-stated** | 避免悬空引脚意外驱动外部器件 |

> 这三项在本仓库 `quartus/puzzle.qsf` 里**已经写好**，路径 A 无需再设。

### 1.3 时序约束（可选但建议）

`quartus/puzzle.sdc` 已经写好 50MHz 时钟定义：

```tcl
create_clock -name clk -period 20.000 -waveform {0.000 10.000} [get_ports {clk}]
```

在 **Assignments → Settings → Timing Analysis Settings** 里把它加入（或 `.qsf` 里
`set_global_assignment -name SDC_FILE puzzle.sdc`）。编译后用它读 **Fmax**。

## 2. 引脚分配

### 2.1 分配依据（重要）

- **引脚号只认开发板手册**《MAXII数字实验板（LCM12864液晶版）》；
- 本仓库**已经把 68 个引脚写死在 `quartus/puzzle.qsf`**，并用手册逐条核对过
  （可读版对照表见 `docs/04-引脚分配表.md` §2）；
- ⚠️ **不要用别的旧工程抄引脚表**：本机另一个旧工程把 `col_r[0]` 接在 `PIN_11`
  （手册里的 COLR7），位序与手册相反 —— 抄它会得到**左右镜像**的点阵（ERR-0003）。

### 2.2 用 GUI 分配（路径 B 或需要临时改动时）

菜单 **Assignments → Pins**（引脚规划器）→ 在 **Location** 列填 `PIN_xx`：

| 功能 | 端口 | 引脚号 |
|---|---|---|
| 全局时钟 | `clk` | `PIN_18` |
| 系统开关 | `sw7` | `PIN_125` |
| 复位键 BTN0 | `btn` | `PIN_61` |
| 点阵行（低有效） | `dot_row[7:0]` | `PIN_8,7,6,5,4,3,2,1` |
| 点阵红列（高有效） | `dot_colr[7:0]` | `PIN_22,21,16,15,14,13,12,11` |
| 点阵绿列（高有效） | `dot_colg[7:0]` | `PIN_45,44,43,42,41,40,39,38` |
| 数码管段（高有效） | `seg[7:0]` | `PIN_62,59,58,57,55,53,52,51` |
| 数码管位选（低有效） | `cat[7:0]` | `PIN_63,66,67,68,69,70,30,31` |
| 键盘列（扫描输出） | `kp_col[3:0]` | `PIN_117,118,119,120` |
| 键盘行（读入，按下=1） | `kp_row[3:0]` | `PIN_111,112,113,114` |
| 蜂鸣器 | `buzz` | `PIN_60` |
| 16 个 LED（**仅自检顶层**） | `ld[15:0]` | `PIN_80,79,78,77,76,75,74,73,144,143,142,141,140,139,138,137` |

> ⚠️ **`ld[15:0]` 只属于 `board_test_top`**。整机顶层 `puzzle_top` 没有这个端口，
> 若此时 `.qsf` 里还留着这 16 行约束，编译会在 fitter 阶段报
> "分配到不存在端口的引脚" —— 所以 §5 切换顶层时**必须同时注释掉它们**。

### 2.3 分配后一定要做的一致性检查（本仓库自带脚本）

```bash

python scripts/check_pins.py --selftest  # 负向测试：证明这个检查器真能抓错
```

## 3. 编译（综合 → 布局布线 → 汇编）

### 3.1 GUI 方式

菜单 **Processing → Start Compilation**（快捷键 `Ctrl+L`）→ 等待
（本工程整机约 20~40 秒）→ 看提示 **Successful** 或 **Error**。

### 3.2 命令行方式（本仓库推荐，能自动打印资源与 Fmax）

```bash
# 全流程（按 .qsf 里当前顶层）
"C:/QuartusII91/QuartusII91/quartus/bin/quartus_sh.exe" -t scripts/build.tcl

# 只做综合（最快，用来查语法错）
"C:/QuartusII91/QuartusII91/quartus/bin/quartus_sh.exe" -t scripts/build.tcl --map-only

# 临时换顶层编译一次（脚本自带"用完还原"，不会污染 .qsf）
"C:/QuartusII91/QuartusII91/quartus/bin/quartus_sh.exe" -t scripts/build.tcl --top puzzle_top
```

分步执行（等价，便于定位是哪一步出错）：

```bash
quartus_map puzzle     # Analysis & Synthesis：语法/综合
quartus_fit puzzle     # Fitter：布局布线 + 引脚
quartus_asm puzzle     # Assembler：生成 .pof 烧录文件
quartus_tan puzzle     # 经典时序分析（Fmax）
quartus_sta puzzle     # TimeQuest 时序分析（Fmax，本工程用这个读数）
```

### 3.3 产物在哪 ⚠️ **9.1 不生成 `output_files/` 目录**

> ⚠️ **Quartus II 9.1 把编译产物直接写在工程目录 `quartus/` 下**；
> `output_files/` 是 **10.x 之后**才成为默认的。找不到 `quartus/output_files` 是**正常的**，
> 不是编译没成功 —— 看编译日志最后一行是不是
> `Info: Quartus II Full Compilation was successful. 0 errors, … warnings`。

| 文件（都在 `quartus/` 下） | 是什么 | 用途 |
|---|---|---|
| **`puzzle.pof`** | **编程文件** | **烧录用它**（MAX II 是非易失器件，`.pof` 写进片内配置闪存，掉电不丢） |
| `puzzle.fit.summary` | 资源利用率摘要（LE / 引脚） | **实验报告评分项④** 直接抄这个 |
| `puzzle.tan.summary` | 时序摘要（Fmax） | 同上，回填 `docs/04` §5.2 |
| `puzzle.fit.rpt` / `map.rpt` / `tan.rpt` | 详细报告 | 需要截图时打开 |
| `puzzle.pin` | 引脚汇总表 | 与 `docs/04` 对账 |
| `puzzle.done` / `puzzle.dpf` | 编译流程标记 | 不用管 |
| `db/` `incremental_db/` | 中间数据 | **不要删**（删了下次全量重编），但也**不要提交进 git** |

> ⚠️ **每次编译后 Quartus 会往 `quartus/puzzle.qsf` 末尾追加约 3 行**
> （`RESERVE_ALL_UNUSED_PINS_NO_OUTPUT_GND`、`LL_ROOT_REGION`、`LL_MEMBER_STATE`），
> 并把文件末尾的换行去掉。**这是正常现象**，不是配置被改坏了。
> 想做提交就把这几行一起提交，不必手工回退（回退了下一次编译又会加上）。
>
> ⚠️ **用 Programmer 下载过一次之后，Quartus 还会追加一行**
> `set_global_assignment -name MISC_FILE "<本机绝对路径>/puzzle.dpf"` ——
> 这行**要删掉再提交**：它带本机用户名与绝对路径（与 `ERRORS.md` ERR-0025 同类，
> 对别人零价值）。`*.dpf` 本身是 Programmer 生成的中间文件，已在 `.gitignore` 里忽略。

> 📌 **本工程实测（2026-09-23 用户本机编译）**：
> `board_test_top` → `Total logic elements : 439 / 1,270 ( 35 % )`、`Total pins : 68 / 116`，
> `Clock Setup: 'clk' … 64.79 MHz`；日志末行 `0 errors, 5 warnings`（5 条均为无害告警）。

### 3.3.1 想看"是否满足 50MHz 的余量"，要用 TimeQuest

编译日志里跑的是**经典时序分析器**（`quartus_tan`），它**不读 `.sdc` 约束** ——
所以它的报告里是 `Required Time: None`、`Slack: N/A`，**只有一个 Fmax 数值，没有合格判定**。

要看带约束的余量（报告更硬气）：

- GUI：**Tools → TimeQuest Timing Analyzer**（它读 `quartus/puzzle.sdc`），
  看 `Report → Timing → Clock Setup: 'clk'` 的 Slack；
- 命令行：`quartus_sta puzzle` → 结果在 `quartus/puzzle.sta.rpt` 的 `Fmax Summary`。

> 本工程实测（整机 `puzzle_top`）：**Fmax 63.66 MHz、最差裕量 +4.06 ns**（约束 20 ns）✓

## 4. 下载烧录（把配置写进板子）

### 4.1 硬件连接

1. 把 **USB-Blaster 下载线**一头插电脑 USB、另一头插开发板 **JTAG 口**
   （板子在实验室内使用，**不要带出实验室**）。
2. 开发板**接通电源**（电源指示亮）。
3. 用**右上角 `USER_BTN`** 把板载时钟档位切到 **7（50MHz）**（档位指示灯确认）。

### 4.2 Quartus 里打开编程器

菜单 **Tools → Programmer** → 自动弹出 Programmer 窗口。

1. 点 **Hardware Setup...** → 选 **USB-Blaster** → Close。
   - 若列表里没有：先装 USB-Blaster 驱动（设备管理器 → 未知设备 → 更新驱动 →
     指向 `C:\QuartusII91\QuartusII91\quartus\drivers\usb-blaster`）。
2. 点 **Auto Detect** → 应识别出 **EPM1270**。
   - 识别不到：检查 JTAG 排线方向、板子电源、有没有别的人占用下载线。
3. 点 **Add File...** → 选 **`quartus/puzzle.pof`**（⚠️ 9.1 就在工程目录下，没有 `output_files/`）。
   - ⚠️ 用 **`.pof`** 而不是 `.sof`：MAX II 是非易失器件，`.pof` 写进片内配置闪存，
     掉电不丢，教师验收时重新上电即用；`.sof` 只写 SRAM，掉电就没了（本工程也不生成它）。
4. **勾选项按同一张表定**（Programmer 里一行 `puzzle.pof`，下挂 `CFM` / `UFM` 两行）：

   | 勾选项 | 选不选 | 理由 |
   |---|---|---|
   | **Program/Configure** | ✅ **勾** | 真正"把配置写进去"的那一项，不勾等于什么也没做 |
   | **Verify** | ✅ **勾**（可留） | 写完后读回逐字节校验，几秒钟，白得一个"确实写进去了"的凭据 |
   | Blank-Check | ⬜ **取消** | 烧录前先测器件是否为空白。**板子里本来就有程序，它只会报 "not blank" 并白等一会儿** |
   | Examine | ⬜ 不勾 | 只读回器件当前配置检验，调试用 |
   | **Security Bit** | ⬜ **绝不勾** | 置保密位后 JTAG 读回/擦除会被阻断（须全片擦除才可能恢复）—— **实验室公用板子千万不要勾** |
   | **Erase** | ⬜ **不勾** | 单独勾会把配置闪存擦掉。本工程不需要"先擦后写"，`Program/Configure` 自己会覆盖 |
   | ISP CLAMP | ⬜ 不勾 | 在系统编程时对引脚做钳位，用于多器件 JTAG 链上保护其他器件；本场景是单器件，用不到 |

   - `CFM`（配置闪存）跟着上面 `puzzle.pof` 那行的 `Program/Configure` 走，**不用单独动**；
     `UFM`（用户闪存）本工程完全没用，**保持不勾**。
   - 一句话：**只留 `Program/Configure` + `Verify`，其余五个全部取消。**
5. 点 **Start** → 进度条到 100%、显示 **Successful** 即完成。
6. 把 **SW7 拨到 "1"（开）** —— 现象**取决于当前烧进去的是哪个顶层**，
   先确认再判断，别把正常现象当成故障（2026-09-24 实测时踩过这个坑）：
   - 顶层 = **`board_test_top`**（第一次进实验室默认烧这个）：进入 **9 阶段自动轮播自检**，
     每阶段约 2 秒，`ld[15:8]` 显示当前阶段号（1~9）；阶段 7 的键盘项**按满 16 键或超时
     20 秒**就往下走（`docs/01` §8.2 订正 2）。
     逐条现象见 `docs/01` §8.2 的表。
     ⚠️ **`ld[7:0]` 除阶段 1 外一直在变**（那是子步号，每 0.25 秒 +1）——
     整排灯"看起来很乱"是**正常的**，2026-09-24 首次上板时正是被这一条误判成故障。
   - 顶层 = **`puzzle_top`**（整机）：显示**要求 1 的开机自检** ——
     点阵全黄 2Hz 闪烁、8 位数码管全显 "8" 且闪烁（`docs/02` §12 的 `S_SELF_TEST`）。
     ⚠️ **它只持续 2 秒**（**要求 2 明文**："**2 秒后**系统进入待机状态"；
     `T_SELFTEST = 2`，`game_fsm` 在 `tick_2hz` 上数 4 拍 = 4 × 0.5 s = **2 s**）
     → 之后**自动进待机**：点阵全灭、**DISP7 显 "5"、DISP0 显关卡号 "1"**。
     ⚠️ **看不到自检画面 ≠ 故障**，绝大多数情况是"**那 2 秒已经过去了**"（见 §6.1 判读表）。
     **想看到它，三个办法（任选）**：
     ① **先把眼睛盯住板子，再拨 SW7 由 0 → 1**（拨完再看就来不及了）；
     ② **按住最右按键（BTN0）再松开** —— 松手即从自检态重新开始 2 秒（同样要盯住板子）；
     ③ **最稳：手机开录 → 拨 SW7 → 回放前 3 秒**（顺手就把工作视频录了）。
   > ⚠️ 两种现象都没有时，按顺序查两件事：**SW7 是否在 "1"**（它是 `clk_gen.sys_en`
   > 的输入，同时门控顶层输出 —— 拨到 0 则数码管/点阵全灭、蜂鸣器无声，这是**正常**的；
   > ⚠️ **但 `board_test_top` 的 LED 不在门控之列**，SW7=0 时 LED 会停在阶段 1 的画面
   > = **只有 LD8 亮**，见 §6.1 与 `ERRORS.md` ERR-0030），
   > 以及**板载时钟档位是否为 7（50MHz）**。

### 4.3 命令行烧录（等价操作，便于脚本化）

```bash
quartus_pgm -c USB-Blaster -m jtag -o "p;quartus/puzzle.pof"
```

参数含义：`-c` 下载线型号 · `-m jtag` 模式 · `p;文件` = program + 文件名。

## 5. 在"硬件自检"与"整机拼图"之间切换顶层

`.qsf` 里**源文件已经全部登记**，切换只需要改两处：`TOP_LEVEL_ENTITY`，
以及 16 行 `ld[…]` 引脚约束（`puzzle_top` 没有 `ld` 端口，留着会让 fitter 报错）。

**一条命令搞定**（建议用这个，手工要改 17 处很容易漏）：

```bash
python scripts/set_top.py check            # 看当前是哪个顶层、ld 约束是否一致
python scripts/set_top.py board_test_top   # 切到硬件自检（默认状态，含 16 个 LED）
python scripts/set_top.py puzzle_top       # 切到整机拼图（自动注释 ld 约束）
```

脚本只动这两处、幂等、**不写任何引脚号**（按 `-to ld[` 匹配，引脚号的唯一真值源仍是 `.qsf`）。
切换后**必须重新编译**（`quartus/` 下的 `.pof` 才会变成新顶层的）。

> 手工等价操作（不想用脚本时）：
> ① `quartus/puzzle.qsf` 里 `set_global_assignment -name TOP_LEVEL_ENTITY <顶层名>`；
> ② 文件末尾「16 个 LED」那 16 行：切 `puzzle_top` 时注释掉，切回 `board_test_top` 时放开。
>
> ⚠️ **不能用 `scripts/build.tcl --top` 代替这两步**：`--top` 只改顶层名，
> 解决不了 `ld` 约束悬挂的问题（fitter 会报"引脚分配给不存在的端口"）。
> ⚠️ 改 `.qsf` 前先关掉 Quartus 里的工程（或改完选 Reload），否则可能被它写回覆盖。

## 6. 常见报错与处置（本工程实际遇到过的）

### 6.1 上板现象判读（先看这张表，再动板子）

| 现象 | 原因 | 处置 |
|---|---|---|
| 上板后**不像自检序列，而是慢动作/乱斑/像卡住** | **板载时钟档位不是 7**：全套分频比都按 50MHz 定死（`clk_gen` 串行级联 `CNT_8K=6249 → ÷8 → ÷10 → ÷50 → ÷100`），档位一变所有节拍**等比**变慢 | 用秒表数**阶段 1 的 16 个 LED**：<br>**1 秒一闪 → 档位 7（对）**；约 **10 秒一闪 → 档位 6（1MHz）**；约 **500 秒一闪 → 档位 5（1kHz）**<br>→ 按 **`USER_BTN`** 切档位，看档位指示 LED 到 **7** 再重试 |
| 数码管/点阵全灭、蜂鸣器无声，**但 LED 里只有 LD8 亮** | **SW7 在 "0"**（`clk_gen.sys_en` + 顶层门控） | 拨到 **"1"**。这是**正常设计**，不是故障 —— ⚠️ **只有 LD8 亮也是对的**：`ld` **不在**门控之列，此时系统停在自检阶段 1（`ld[15:8]="0000_0001"`）。见 `ERRORS.md` ERR-0030 |
| 点阵整屏只亮**一行**、约几十秒才换一行 | 同第 1 条（档位远低于 50MHz，行扫描节拍被等比拉长） | 同上 |
| 完全静止、一点变化都没有 | 档位 **0（NO CLOCK）**：器件没有时钟 | 切到档位 7 |
| **按住 BTN0 没有出现"16 灯全亮"** | ⭐ **先怀疑按错了键**：只有 **BTN0（8 个按键里最右边那个）** 接进了自检逻辑 | ① 确认按的是**最右边**那个；② 逐个试其余 7 个 —— 若某个键能让 16 灯亮，说明丝印次序与手册相反；③ **8 个键都不行**才查 `btn`/`PIN_61` 通路。**该路是直读、不受 SW7 门控，所以 SW7=0 也能验**（见 `docs/04` §7.3） |
| **不按键时已 16 灯全亮，一按反而只剩 LD8** | `btn` 极性反了（`ld <= all'1' when btn='1'`） | 手册写"平时输出低电平、按下高电平"；若实测相反，改 `clk_gen.i_btn_rst` 的极性（**一处集中改**） |
| 自检时**低 8 个 LED 一直在变**、看着"乱" | `ld[7:0]` 是**子步号**（阶段 1 除外，那是 1Hz 齐闪） | **不是故障**。⭐ 现场口径（2026-09-24 实测）：整排灯"**没有规则地闪烁，但有周期**"就是**正常** —— 有周期 = 时钟在走且分频链在动；完全静止 = 无时钟，慢动作 = 档位低 |
| **16 个灯全都在动**，找不到"`LD8` 常亮 + `LD0~LD7` 齐闪" | ⭐ **正常，且是大概率画面**：**阶段 1 只占 36 秒里的 2 秒（≈5.6%）**，其余 34 秒是阶段 2~9（`ld[15:8]`=阶段号、`ld[7:0]`=子步号）→ 16 个灯本来就都在动 | **不是故障，是"没撞上阶段 1"**。看**最左边那位数码管 DISP7** 的读数（= 当前阶段号，**阶段 5/6/7 除外**，见下）；或**松开最右按键后的 2 秒内**看。见下方「30 秒判据」与 `ERRORS.md` ERR-0031 |
| 阶段 6 数码管**从左到右读是 `8 7 6 5 4 3 2 1`**，不是 `1 2 3 4 5 6 7 8` | **正常**：`board_test_top` 写的是 `s_disp_val <= x"87654321"`，而 **DISP7 在最左**（`o_cat(0)` = DISP0 最右）→ 最左那位显示的是最高位 nibble = `8` | **不是故障，是位序测试**（顺带验段码）。⚠️ 别照 `docs/01` §8.2 那句"依次显示 1 2 3 4 5 6 7 8"的**字面方向**去判 —— 见 `ERRORS.md` ERR-0032 |
| 烧 `puzzle_top`、拨 SW7=1 后**看不到**"点阵全黄闪 + 数码管全 8 闪"，**直接就是待机**（DISP7 显 "5"） | ① **开机自检只持续 2 秒**（**要求 2 明文**"2 秒后系统进入待机状态"；`T_SELFTEST = 2`）—— 很可能只是没抓住；② ⚠️ 若**按住 BTN0 松开也一样**，则要查"复位是否真的送到" | **先做测试 A**：**按住最右按键不松**，看数码管/点阵是否**全灭**。<br>**全灭** → 复位通路正常 → 用**录视频**（开录 → 拨 SW7 → 回放前 3 秒）复核；<br>**仍显示 "5"（不变）** → **BTN0 没接进复位** → 按 `docs/05` §1.6.2 排查。见 `ERRORS.md` ERR-0034 |
| **按住最右按键（BTN0）时，数码管与点阵应"全灭"** | 复位期间 `r_state = S_SELF_TEST` 且 `r_blink` 被钳在 `'0'` → `o_blank = 全 1`（全灭）、点阵 `px = 0`（全灭） | ⭐ **这是"复位通路真的通了"的直接证据**，1 秒可判。⚠️ **`board_test_top` 上的"按住 BTN0 → 16 灯全亮"证明不了这条** —— 那行是组合直读，**绕过了同步器、消抖与 `o_rst`**，只证明引脚通 |
| 整机待机画面：**DISP7 显 "5"、DISP0 显 "1"**、其余全灭、点阵全灭 | **要求 2 的原文画面**（`disp_format` 的 `S_IDLE` 分支） | **正常**。`DISP0` 是关卡号（`i_level + 1`，第一关 = "1"） |

> ⭐ **判读顺序**：先 **SW7** → 再 **时钟档位（用 LED 的 1Hz 节奏反推，不用猜）** → 最后才怀疑逻辑。
> 阶段 1 的 LED 节奏是**唯一能把"时钟问题"与"逻辑问题"一刀切开的观测点**：
> 节奏准 → 时钟没问题，毛病在显示/扫描逻辑 → 回电脑做仿真定位（`docs/03`）。

> ⭐ **30 秒判据（2026-09-24 首次上板后补；同日第二次订正，见 `ERRORS.md` ERR-0031）**：
> ① `FREQ` 指示灯 = 第 7 格 → ② **SW7 由 0 拨到 1** → ③ 按住**最右**按键（应在 `SW7=0/1` 下都让
> **16 灯全亮**）→ ④ **松手，并在接下来 2 秒内看**：应 `LD8 常亮 + LD0~LD7 齐闪 1Hz`、
> **`LD9~LD15` 全灭**。
> 四步里任一步不符，照上表对号入座；**四步全对就说明时钟、复位、LED 通路与轮播全通**，
> 剩下的点阵/数码管/键盘项按 `docs/01` §8.2 逐阶段过。

> ⚠️ **别用"随便看几秒"来判断阶段 1**（ERR-0031 的教训）——
> **阶段 1 只占完整轮播 36 秒里的 2 秒（≈5.6%）**，撞上的概率很低；
> 看到的绝大多数是阶段 2~9 的"**16 个灯都在动**"，那不是故障。
>
> **要精确对准阶段 1，只有下面三个时刻，任选其一：**
>
> | # | 时刻 | 为什么必然在阶段 1 |
> |---|---|---|
> | 1 | **松开最右按键（BTN0）之后的 2 秒内**（最省事） | 按住期间 `o_rst='1'` 把 `r_stage` 按在 1，松手即从头开始 |
> | 2 | **SW7 由 0 拨到 1 之后的 2 秒内** | `o_rst` 释放的那一拍，`r_stage` 从 1 开始 |
> | 3 | **最左数码管 DISP7 显示 "1" 时** | 该位就是**当前阶段号**的读数，最可靠（见下） |
>
> ⭐ **DISP7 是阶段号的现成读数**（2026-09-24 补记）：`board_test_top` 把 `r_stage` 写进
> `s_disp_val(31 downto 28)`，而 `seg_scan` 的映射是 `i_disp_val(4k+3..4k) → DISPk`，
> `o_cat(0)` = DISP0（最右）→ **最左边那位数码管显示的就是当前阶段号**。
> **不用猜、不用数秒表，看它就够了**（阶段 5/6 验过数码管之后）。
>
> ⚠️ **但它只覆盖 6 个阶段**（2026-09-24 订正，`ERRORS.md` ERR-0032）：那条
> `when others` 只接住 **阶段 1/2/3/4/8/9**；**阶段 5、6、7 的数码管另有内容**
> （5 = 一个 "8" 逐位移动；6 = `8 7 6 5 4 3 2 1`；7 = 当前键号的十进制两位）。
> **在这三个阶段里，DISP7 不再显示阶段号** —— 判"现在是不是阶段 1"不受影响
> （阶段 1 在覆盖范围内），但**别拿它当"永远准确的阶段表"**。
>
> **阶段 1 的准确画面**（`rtl/board_test_top.vhd` L451~456）：`LD8` 常亮、`LD0~LD7` 齐闪 1Hz、
> **`LD9~LD15` 全灭**。

## 8. 中文注释显示成乱码怎么办（Quartus 9.1 必读）

**现象**：在 Quartus 里打开 `rtl/*.vhd`，**代码标识符正常，只有中文注释变成火星文**
（如 `-- 50MHz 系统时钟` 变成一串看不懂的字符）。**编译不受影响**，只是看不懂、没法给报告截图。

**根因**：**Quartus II 11.0 及以下版本的编辑器固定按系统 ANSI（简体中文 = GBK/CP936）
解码源文件**（12.0 起才改用 UTF-8），而且**没有"以指定编码打开"的选项**。
而 `rtl/*.vhd` 原先存的是 UTF-8 无 BOM，被按 GBK 解读 → 整段注释乱码。
——这与本项目 `CLAUDE.md` §5.4 记的"PowerShell 5.1 按 ANSI 读 UTF-8 文档"是**同一个坑**。

**修复（一条命令）**：

```bash
python scripts/encoding.py check   # 先看当前编码（应列出 14 个文件）
python scripts/encoding.py gbk     # 全部转成 GBK —— 之后 Quartus 里就正常了
```

**操作顺序很重要**：

1. **先关掉 Quartus 里已打开的那个 `.vhd`**（或直接退出 Quartus）。
   否则它会提示"文件已被外部修改"，此时**选"是 / Reload"**；
   **千万不要选"保存"**——那会用编辑器里那份旧内容把转换结果覆盖回去。
2. 执行 `python scripts/encoding.py gbk`。
3. 重新打开工程 / 文件 → 中文注释正常显示。
4. 脚本自带校验：既保证"GBK 能完整表示原文"，又把 GBK 装不下的装饰符号
   （`⚠️` `⭐` `µ` `−` `↔` `⟺` `⑪` `⑫`）替换成等价写法（`※` `★` `μ` `-` `<->` `当且仅当` `(11)` `(12)`），
   **绝不静默写成 `?`**；有表外字符时会**拒绝转换并打印码位**。

**还要注意两条**：

- ⚠️ **用 AI 工具改完 `.vhd` 之后要再转一次** —— AI 工具写出的是 UTF-8：
  「改代码 → `python scripts/encoding.py gbk` → 再看/编译」。
- ⚠️ **不要打开 Windows 的 "Beta: 使用 Unicode UTF-8 提供全球语言支持"**
  （控制面板 → 区域 → 管理 → 更改系统区域设置）。打开后系统 ANSI 代码页变成 65001，
  Quartus 又会按 UTF-8 读，**已转好的 GBK 文件反而乱码** —— 两种方案只能选一种。
  本机实测 `ACP = 936`（正确，符合"源文件用 GBK"这一方案）。

**已验证（本次实测）**：转换后重新全流程编译，两个顶层的 **LE 数与 Fmax 完全不变**
（`puzzle_top` 1226/1270、63.66 MHz；`board_test_top` 439 LE）——
**编码只影响注释的显示，不影响综合**。另逐行核对过两条安全项：
① 所有中文都在 `--` 注释内（非注释部分无非 ASCII 字节）；
② 无 GBK 尾字节为 `0x5C` 的字符，不涉及 VHDL 扩展标识符风险。

**替代方案（不改编码）**：代码用 VS Code / Notepad++（按 UTF-8）看与改，Quartus 只负责编译与烧录。
代价是**在 Quartus 里看代码、给报告截"带注释的顶层代码"图时仍是乱码**
（实验报告评分项⑧要的正是"顶层文件的 HDL 代码（有注释）"）—— 所以本项目采用"转 GBK"这一条。
