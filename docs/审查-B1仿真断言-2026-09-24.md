## §3 自证式断言清单（期望值是否与 RTL 同源）

> 判据：若 tb 的期望值**只可能**来自 RTL 的公式/常量（RTL 错则 tb 同错），即为自证；若来自需求、标准表或手算，则独立。

### 3.1 `clk_gen`

| 断言 | 期望值来源 | 判定 |
|---|---|---|
| r01 ③④⑤⑥⑦（各 tick 频率） | `TICK_8K=125000ns` 等 = **1/8kHz 等需求频率**，与 `CLK_HZ` 无关 | **独立**（需求文档）。若 RTL 分频比错，窗口内脉冲数就会变 → 会失败 |
| r02 ①②（6250/6249） | `6250 = 50MHz/8kHz` = **需求推导**，非 RTL 的 `CLK_HZ/8000-1` 表达式 | **独立**（spec）。RTL 若写成 `CLK_HZ/8000`（无 -1）会失败 |
| r01 ⑧（20ms 断言） | 20ms = `T_BTN_MS` 需求 | **独立** |
| r01 ⑨（第 3 个 clk 沿） | 3 = `docs/02` §3.6-7 订正后的 spec | **独立**（文档值） |
| **r03 ②（`por_top == 9`）** | 9 = **RTL 的 `T_POR_MS-1`** | ⚠️ **轻度自证**：期望值直接取自 RTL 常量。其"计数器不被 `o_rst` 停住"的行为确有验证价值（被停住则到不了 9），但"9"本身不独立 |
| r01 ②（`t_fall ∈ [8,10.6]ms`） | 区间来自"~10ms" | **独立但过宽**（见 P1-1） |

### 3.2 `keypad_scan`

| 断言 | 期望值来源 | 判定 |
|---|---|---|
| ①（列极性 `_colpat`） | `选中列驱有效电平` = **spec**（一热）；RTL 若位号/多列错会失败 | **独立** |
| ②⑧（键号 = `(3-ROW)*4+COL+1`） | 公式来自 `docs/02` §4.4/§4.6-4（**spec**），tb 用的是其**逆映射** `ROW=3-(KEY-1)//4` | **独立（但共享同一 spec 公式）**：这是"驱动逆映射→RTL 正映射→比对"的往返测试。RTL 若镜像/换向会失败；仅当 RTL 与 tb 同时用同一个错误映射时才漏网，而该映射是文档化的物理布局，故可接受 |
| ⑨（80~87ms）、⑤（1 clk 宽） | spec（`docs/02` §4.6-6 / `CLAUDE.md` §10.1） | **独立** |

### 3.3 `seg_scan`

| 断言 | 期望值来源 | 判定 |
|---|---|---|
| ④（`SEG_TABLE` 0~9） | tb 表 = **标准共阴 7 段码**（0x3F/0x06/0x5B…），逐值可离线验证 | **独立**（标准码）。⚠️ 但 tb 注释自认"与 rtl/seg_scan.vhd 逐条一致"——**写法是照抄**；当前值正确故无害，将来若 RTL 被改成非标准值再照抄，则会共漂 |

## §4 单向断言与恒真式断言清单

### 4.1 单向断言（缺哪一边）

| 模块 | 断言 | 缺的方向 |

### 4.2 恒真式 / 近似恒真断言

| 模块 | 断言 | 为什么近似恒真 |
|---|---|---|
| `keypad_scan` | ⑤ 脉冲宽度 | `all(... for w in widths)` 在 **`widths` 为空集时恒真**（RTL 一个脉冲都不出也"通过"）。仅因 ④⑥⑩ 另有非空要求才不致命 |

## §6 对 `clk_gen` 两条发现的独立验算

### 6.1 发现一：POR 实为 **9.156ms** 而非 10ms —— **成立 ✅**

直接读 `rtl/clk_gen.vhd` 的计数边界手算：

- `puzzle_pkg.vhd:115` `T_POR_MS := 10`；`clk_gen.vhd:53` `r_por_cnt : range 0 to T_POR_MS-1`（= **0..9**）。
- `clk_gen.vhd:158-165`：
  ```
  if r_por_cnt = T_POR_MS-1 then  r_por_rst <= '0';      -- 释放
  else  r_por_rst <= '1'; if r_tick_1k='1' then r_por_cnt <= r_por_cnt+1; end if;
  ```
- **关键**：释放判定 `= 9` 在**每个 clk 沿**都求值（不在 `i_tick` 分支内）；`r_por_cnt` 只在 `r_tick_1k='1'` 时 +1。
- 计数序列：`0 →(tick1) 1 →(tick2) 2 … →(tick9) 9`，**共 9 个 `tick_1k`**；`cnt` 一旦为 9，**下一个 clk 沿**即释放。
- ⇒ 复位时长 = **9 × 1ms + 相位偏移 ≈ 9.156ms**（与 r01 ② 实测 `9156250 ns` 吻合）。

**结论**：`T_POR_MS=10` 名实不符（**off-by-one**，同 ERR-0016 一族），原文档"10ms"错误。**发现一成立。**

### 6.2 发现二：§3.6-9 的"`o_rst` 恒为 '1'" **不成立** —— **成立 ✅**

- 按键通路 `clk_gen.vhd:178-197`：`DEBOUNCE_BTN := T_BTN_MS-1 = 19`（`puzzle_pkg.vhd:127`）。
- 断言判定 `if r_btn_cnt = DEBOUNCE_BTN then r_btn_rst <= '1'` **在 `i_tick` 分支内**：
  - `cnt: 0 →(tick1) 1 … →(tick19) 19`，**第 20 个 tick** 上 `cnt=19` 才 `r_btn_rst<='1'`。
  - ⇒ 按键认定 ≈ **20 × 1ms = 20.094ms**（与 r03 ③ 实测 `20093750 ns` 吻合）。
- POR 于 **9.156ms** 释放，按键要 **20.094ms** 才认定 → 中间 **`20.094 − 9.156 ≈ 10.94ms`** 窗口内 `r_por_rst=0`、`r_btn_rst=0`、`sys_en=1` ⇒ `o_rst = 0`。
- ⇒ 原文"`i_btn_rst` 全程=1 时 `o_rst` 恒为 '1'"**不成立**（POR 窗短于消抖窗）。**发现二成立。**

> 附带发现（供文档修正）：**POR 与按键的"计满"约定并不一致**——POR 的释放判定在时钟沿上无条件求值（9 个 tick 即释放），按键的认定判定在 tick 分支内（第 20 个 tick 才认定）。这正是"POR≈9ms 而按键=20ms"的根因，`docs/02` §3.6-9 的订正文字（"上电后**前 ~10.9ms** 内 `o_rst` 是 '0'"）措辞有误（前 9.16ms 其实是 '1'），建议改写为"POR 释放(9.16ms)与消抖认定(20.09ms)之间存在约 10.9ms 的 '0' 窗口"。

## §7 优先级排序的问题清单

### P0 —— 必须改

1. **`keypad_scan` 的"双极性回归"无效，未复现 ERR-0035。**
   `tb_keypad_scan.py:66-67` 令 `IDLE = 1 - KP_ACTIVE`，因此第 2 轮（`KP_ACTIVE=1`）把**未按下行驱成 0**（下拉板模型）。而真实板是**上拉**（无键读 '1'，见 ERR-0035 / `rtl/keypad_scan.vhd:48-54`）。→ 高有效 RTL 在真实板上会**每相误报**，但 tb 用 `IDLE=0` 把它"喂"成了无键，断言 ③ 照样全绿。
   **修正**：`IDLE` 必须**固定为真实板电平（1）**，只翻转 RTL 的 `KP_ACTIVE`；这样第 2 轮应**如期变红**，才证明"两种极性都测"有意义。
   （注：现行 tb 对**当前默认低有效**配置的回归是**有效**的——r01 用 `IDLE=1` 且若 RTL 被改回 '1' 会被 ③ 抓到；问题在于第 2 轮的"高有效也通过"是**假绿**。）

### P1 —— 建议改

1. **`clk_gen` r01 ② POR 释放区间过宽**（`8.0e6 ≤ t_fall ≤ 10.6e6`）：**10.0ms 也会通过**，无法钉住订正后的 9.156ms。这正是本轮"发现一"的那条断言——**结论靠人读 detail 字符串得出，断言本身对 9 vs 10 是盲的**。建议收紧到 `[9.0, 9.3]ms`（或按 `T_POR_MS-1` 独立推导）。
2. **`clk_gen` 缺 `sys_en` 释放（0→1）方向**：三源或的 `(not sys_en)` 项只验了断言侧。补一条"`sys_en` 回高且其余两源为 0 → `o_rst` 释放"。
