第一层 · 为什么分成这七块

自顶向下的第一刀：按信号流切

从需求出发先问「一个玩家看到什么、按什么」——于是得到 输入 → 控制 → 逻辑 → 输出 四条链。七块里 游戏控制 是枢纽，拼图核心 与 图案与随机数据 是它的下游，显示子系统 汇聚两路数据。

第二刀才是分模块

每一块在 DWG-02 里再展开成一个或多个 .vhd 实体。 例如「显示子系统」拆成格式化、数码管扫描、点阵扫描三个实体—— 它们职责不同、时钟相同、可以各自独立仿真。

为什么要分两层画

十一个实体平铺在一张图上，读不出结构，答辩时也讲不出主线。 分两层后：DWG-01 讲系统怎么组织（一页看懂）， DWG-02 讲每个模块怎么实现（老师抽问用）。

DWG-02 图例 · 按职责分类着色

时序与调度
只管时间——状态、倒计时、节拍。不含任何坐标运算。
器件驱动
与外部器件的电气特性强相关，与游戏规则无关。

纯逻辑与查表。不等时钟，给输入立刻出输出。

两条失败路径

① 拼错

全部零片都按下「确认」锁定后，若零片掩码的并集 ≠ 目标图案，立即判失败， 不等倒计时走完。判据是并集而不是逐块比对——因为三块零片恰好有 2 种合法铺法，逐块比对会把其中一种正确解误判为失败。

② 超时

倒计时归零时仍有零片未锁定。第一关 30 秒、第二关 40 秒， 倒计时器直接用两位 BCD 递减，因此综合结果里不会出现十进制除法器。

拿去 draw.io 用

导入方式

浏览器打开本文件 → 右键图形 → 另存为 SVG，或在 draw.io 里选 File ▸ Import 直接导入这个 HTML 里的 SVG 源码。 导入后每个矩形框、每条箭头都是独立可编辑对象，不是一张位图。

为什么不做成深色

两张图在明暗两种主题下都画在白纸上。这些图最终要导出 PNG 贴进实验报告， 而报告是要打印的——白底深线才印得清楚。

改图规矩

DWG-02 里：一个矩形框 = 一个 .vhd 文件 = 一个实体。 DWG-01 里：一个矩形框 = 一个功能子系统，可含多个实体， 框内已列出所含实体名。 改了模块接口必须同时改两张图和 docs/01-系统设计.md 的接口表—— 老师会照着图抽模块提问。
