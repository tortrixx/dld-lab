## 1. 仿真策略

### 1.1 工具链（已实测，2026-09-17）

**本机没有 ModelSim / GHDL**，使用 **Quartus II 9.1 内置仿真器**。它的三条硬限制
（全部实测确认，不是推测，详见 `CLAUDE.md` §5.3）：

1. 仿真的是**综合后网表**，不是 RTL → **不支持 VHDL testbench、不支持 `assert`**；
2. **没有任何 Tcl 命令接口** → 驱动与判定**全用 Python**；
3. **必须有一个 `.vwf` 向量源文件**，且仿真结果会**覆盖写回**该文件。

**据此建立的自动验证闭环**（闭环机制已实测跑通；第 2/4 步的 `scripts/sim.py` 待首个模块写出后实现）：

```
quartus_map <工程> --generate_functional_sim_netlist   # 1. 生成功能仿真网表
python scripts/sim.py gen <模块>                        # 2. Python 生成激励 .vwf
quartus_sim <工程> --mode=functional --overwrite_waveform=on   # 3. 跑仿真（结果写回 .vwf）
python scripts/sim.py check <模块>                      # 4. 解析结果 + 参考模型逐点比对 + 渲染波形图
```

- 模块专属的激励与断言写在 `sim/tb_<模块>.py`；`.vwf` 读写库是 `scripts/vwf.py`（已自检通过）；
- `scripts/sim.py` 在第一个真实模块（`clk_gen`）写出后实现（避免凭空设计接口，见 `PROGRESS.md`）。

> ⚠️ **`sim/*.vwf` 会被仿真结果覆盖写回，永远不要手工编辑** —— 改 `sim/tb_*.py` 重新生成。

### 1.2 仿真时长与 `CLK_HZ` 缩放

50ms @ 50MHz = 250 万个时钟周期，内置仿真器跑不动。**实际做法**：仿真时把
`puzzle_pkg.CLK_HZ` 改小，**用比例关系验证分频比正确**，而不是验证绝对时间
（串行级联的分频比是纯比例，与时钟档位无关，见 `docs/02` §2.6 / §3.6）。

> ⚠️ **`CLK_HZ` 的合法下限是 8000**（2026-09-18 审查修正）：`CNT_8K = CLK_HZ / 8000 - 1`，
> 取 1000 会得到 `-1`，`integer range 0 to -1` 直接报错。
> ⭐ **推荐取 `CLK_HZ := 16000`（8000 的 2 倍），不要取 8000 本身**（2026-09-18 审查 `sim-02`）：
> `8000` 时 `CNT_8K = 0`，**第 1 级分频比退化为 1:1**（tick_8k 与 clk 同拍）——
> 于是 ① §3.6 验证点 4"跑 1ms 数 8 个 tick_8k"退化成**恒真式**；
> ② "第 2 级由 `tick_8k` 使能"还是"由 `clk` 使能"在波形上**不可区分**（串行级联这一设计要点失去可验证性）。
> `16000` 时第 1 级为 2:1、五级比例全部非平凡，代价只是拍数翻倍。
>
> ⭐ **`6250:1` 这一档要靠"全速短跑"单独验证**：第 1 级的 6250:1 是**唯一与板上时钟档位绑定
> 的分频比**（`CLAUDE.md` §9 风险 1），缩放仿真**永远覆盖不到它** →
> 另加一次：`CLK_HZ = 50_000_000`、tb 里 clk 周期 20ns，只跑约 **1.25 万拍（125us）**，
> 断言**两个 `o_tick_8k` 脉冲之间恰隔 6250 拍**。这一点开销换回唯一的档位相关参数。
>
> ⚠️ **tb 侧 clk 周期必须 = 1/`CLK_HZ`**（16000 → 62.5us；8000 → 125us）：`docs/02` 各验证点
> 的期望值都按 ms/s 表述，周期不跟着改，全部期望值会**整体错位**。
> 绝对时间正确性最终由 `board_test_top` 的 1Hz LED 闪烁粗判（`docs/01` §8.2）。

⭐ **容量实测登记**（2026-09-18 审查 `sim-07` 补）：全文唯一关于仿真器容量的量化是上面那句
"250 万拍跑不动"，**没有任何实测数字**。按 §5 的 12 个场景估：仅"自检 2s + 预览 5s +
倒计时 30s + 第二关 40s"就 ≈ 77s ≈ **62 万拍**（`CLK_HZ` = 8000；取 16000 则翻倍）。
第一个模块（`clk_gen`）跑完就在下表登记，之后每加一个场景补一行 —— 它是整机仿真能否开跑的前提：

| 场景 | 拍数 | 仿真耗时 | 回写 .vwf 大小 | 能跑？ |
|---|---|---|---|---|
| `disp_format`（纯组合，800→1000ns，全端口） | ~100 拍 | **< 1 s** | 11 197 行 → 回写后见文件 | ✅ 能跑（覆盖率 73.7%） |
| `dot_matrix_scan`（时序，2000ns，clk 20ns + 手工 i_tick） | 100 拍 | **< 1 s** | 见 `sim/dot_matrix_scan.vwf` | ✅ 能跑 |
| `quartus_map --generate_functional_sim_netlist` | — | **1 s** | — | ✅ |
| `quartus_sim` 单模块 | — | **< 1 s** | — | ✅ |

### 1.3 功能仿真 vs 时序仿真

| 类型 | 本项目用途 |
|---|---|
| **功能仿真**（`--mode=functional`） | **主力**。全部 12 个模块的逻辑正确性验证 |
| 时序仿真（`--mode=timing`） | 仅顶层集成后抽查一次 |
| **静态时序分析（TAN）** | ⭐ **每次全流程编译都跑，读 Fmax 回填 `docs/04` §5.2** —— 见下 |

> ⚠️ **2026-09-18 审查更正**（ERR-0020 / 报告 `CRIT-1`）：
> 本表原写"单时钟域 50MHz 下**时序裕量极大**"——**那句断言当时没有任何依据**：
> 工程里没有时钟约束、流程里没有 TAN 步骤、`docs/04` 的 Fmax 行没有数据来源。
> **"没有验证手段"不等于"一定通过"**，尤其本项目有一条**横跨三个模块、
> 中间没有寄存器**的组合路径：
>
> ```
> r_anchor → place() 平移逻辑 → disp_format 多路选择 → dot_matrix_scan → 引脚
> ```
>
> **现已补上手段**：
> ① `quartus/puzzle.sdc` 里 `create_clock -period 20ns`；
> ② `scripts/build.tcl` 编译完自动打印时序摘要；
> ③ 判据 **Fmax ≥ 50MHz**，结果回填 `docs/04` §5.2；
> ④ 不达标时的第一嫌疑就是上面那条路径，对策是在 `puzzle_ctrl → disp_format` 之间打一拍。
>
> **在这条 Fmax 数据拿到之前，不许再写"裕量极大"。**

## 2. 每个模块的标准验证循环

**一步都不能省**（与 `HANDOFF.md` §3 一致）：

```
写 rtl/<模块>.vhd  →  写 sim/tb_<模块>.py  →  生成 .vwf  →  跑仿真
→ 解析结果与参考模型逐点比对（⚠️ 先断言中间信号清单全部有 TRANSITION_LIST，缺一即报错，见 §3.1 第 5 条）  →  渲染波形图存 docs/图/
→ 把原始数据写进本文档对应小节  →  单独 commit
```

**提交门槛**：该模块的参考模型比对**全部通过**才允许 commit（`CLAUDE.md` §6）。

### 2.1 ⚠️ 循环里还缺两个「绑定」步骤（2026-09-18 审查补）

上面那条链路看起来完整，但**工程只有一个顶层、一个向量源设置** ——
要真的按模块逐个仿真，中间必须**改两次工程设置**。`sim-03` 之前没人提过，
阶段 2 第一次跑就会撞上（ERR-0020 / 报告 `sim-03`）。

| # | 绑定 | 怎么做 | 不做的后果 |
|---|---|---|---|
| **A** | **把被测模块设为顶层** | `quartus_sh -t scripts/build.tcl --top <模块名>`（该脚本内部"先存原值、关工程前还原"，不会污染 `.qsf`）。**必须在第 1 步生成功能仿真网表之前做。** | 仿真网表的顶层是 `board_test_top`，**被测模块根本不在网表顶层**，加不进波形 |
| **B** | **把本次 `.vwf` 指定为向量源** | ⚠️ **2026-09-24 实测订正**：**不用** `.qsf` 设置 —— Quartus 9.1 **不认** `VECTOR_SOURCE_FILE` 这个名字，实测报 `No valid vector source file specified and default file "puzzle.cvwf" does not exist`。正确做法是 **`quartus_sim <工程> --mode=functional --overwrite_waveform=on --vector_source=../sim/<模块>.vwf`**（见 `quartus_sim --help`）。**所以 B 不需要改工程、也就不需要还原** —— 只有 A 要还原。 |

> ⭐ **A、B 都要"用完还原"** —— 与 `build.tcl` 的 `--top` 同一套路数，
> **`set_global_assignment` 会在关工程时写回 `.qsf`**，不还原就会把工程改成上一次仿真的样子。
> 这条坑 `build.tcl` 的注释里已经记过一次，别在 `sim.py` 里重犯。

⚠️ **还有一件配套的事**：新写的模块要**加进 `.qsf` 的 `VHDL_FILE` 列表**。
`.qsf` 现只列了 6 个文件，**其余 8 个模块（`pattern_rom` / `piece_rom` / `rng_lfsr` /
`puzzle_ctrl` / `disp_format` / `game_fsm` / `buzzer_ctrl` / `puzzle_top`）尚未在册** ——
不加进去，综合时它们根本不会被读。

## 3. 波形判读与数据记录规范

每个模块的小节必须包含以下五样（缺一样等于没做，`CLAUDE.md` §13.2）：

| # | 内容 | 要求 |
|---|---|---|
| 1 | **激励条件** | 时钟频率（或缩放后的 `CLK_HZ`）、复位时刻、各输入在哪些时刻取什么值 |
| 2 | **观测点** | 看了哪些信号、为什么看它们（对应 `docs/02` 的验证点编号） |
| 3 | **实测值 vs 期望值** | 具体数字或波形截图，**逐项比对**，不是"符合预期"四个字 |
| 4 | **波形图** | PNG/SVG 存 `docs/图/`，命名 `SIM-<模块>-<场景>.png` |
| 5 | **结论** | 通过 / 不通过；不通过 → 同时写 `ERRORS.md` 五段式 |

> **反面例子**：只写"仿真通过"。25 分的评分项，素材就是这张表里的原始数据。

### 3.1 ⭐ 波形里必须含"中间信号"（课件 p59 的硬要求）

> **课件《数字系统设计2026》p59 原文**：
> *"（八）仿真：加入中间信号，便于查看电路状态变化"*。
> 该页配图是 Quartus 的 **`Node Finder`** 对话框，
> 圈出的过滤条件是 **`Filter: Pins: all & Registers: post-fit`** —— 怎么找，课件也给了。

**为什么这不是可选项：只给端口的波形，看不出电路"为什么"这么动。**

| 现象 | 只看端口 | 加了中间信号 |
|---|---|---|
| 按了方向键，零片不动 | 三个可能**波形上完全一样**：① 键盘消抖没过 ② 状态机没在 `S_PLAYING` ③ 钳位把移动吃掉了 | 看 `keypad_scan.r_stable` / `game_fsm.r_state` / `puzzle_ctrl.r_anchor`，**一眼定位** |

**落实方式**：

1. `scripts/vwf.py` 生成的 `.vwf` **除端口外必须加入本模块的中间信号**，
   清单写在各模块的 `sim/tb_<模块>.py` 里；
2. 信号名**以"被仿真的那版网表"为准**（2026-09-18 审查 `sim-04` 修正）：
   功能仿真仿的是**综合后网表** → 名字取 **`Node Finder` 里 `Registers: post-synthesis`**
   （或直接看 `quartus_map` 输出网表里的名字）；课件 p59 截图圈的是 **`Registers: post-fit`**，
   那是**全编译（fit）之后**才存在的名字 —— 本项目功能仿真阶段**工程从未 fit**，
   照截图去过滤会一个都找不到。另：综合器可能改名或优化掉某些寄存器，
   **RTL 里的名字不一定还在**；
3. **每个模块至少要看得见这三样**（如存在）：
   **状态寄存器**、**主计数器**、**该模块的关键中间信号**
   （如 `clk_gen.r_btn_rst`、`keypad_scan.r_stable`、`puzzle_ctrl.r_anchor`）；
4. 记录时在 §4 各模块的"观测点"一栏**逐个列出**，与 `docs/02` 的验证点编号对应；
5. ⭐ **核对名字真的存在**（2026-09-18 审查 `sim-04` 补）：跑完第一遍后，
   **逐个检查清单里的中间信号在回写 `.vwf` 里都有 `TRANSITION_LIST` 且发生了预期的跳变**
   —— `sim.py check` 要把这条做成断言：**清单里的节点缺一即报错**。
   为什么必须能报错：名字对不上时的表现**不是显眼报错，而是该节点干脆没有波形**；
   若只靠人眼看波形，"素材看着齐全、实际观测点缺失"会静默发生 ——
   那恰好绕过了本节存在的目的。

> ⚠️ **中间信号被综合器优化掉怎么办**：若某个寄存器因只用于调试而被优化，
> 可在 `.qsf` 或源码中加 `keep` 属性，**或换一个功能上必须保留的等价观测点**。
> **不要因为"找不到就跳过"** —— 那是把评分项③ 的素材丢掉了。
