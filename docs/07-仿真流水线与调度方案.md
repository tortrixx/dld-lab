## 3. 调度方案：多 Agent 并行

### 3.1 核心约束 —— 已解决

**Quartus 工程是独占资源**（一个工程只有一个顶层、一个向量源）。
早期版本直接在仓库工程上改 → **既不能并行，又会互相污染**。

⭐ **隔离工程已落地**（`scripts/sim.py`）：每次仿真在 `.tmp/sim_<模块>/` 生成一份
**独立工程**（RTL 副本 + 补丁 + 自己的 `.qsf`），跑完即删。
→ **仓库只读**、**不需要还原**、**N 个模块可真并行**。

### 3.2 角色

| 角色 | 职责 | **不做什么** |
|---|---|---|
| **Orchestrator**（主会话） | 维护轮次账本、跑闸门、决定何时上板、合并提交 | **不写 tb**（避免既当运动员又当裁判） |
| **Sim-Agent × N** | 负责若干模块：写 `tb_<模块>.py`、跑到全绿、写轮次记录 | 不碰别人的模块、不改 `rtl/` |
| **Auditor-Agent** | **独立复核**：读 tb 与轮次记录，核对断言是否真的覆盖 `docs/02` 的验证点、有没有"自证式"断言（断言写错方向） | 不改代码，只出问题清单 |

### 3.3 批次（按依赖分层，同层并行）

| 批次 | 模块 | 说明 |
|---|---|---|
| **B1 基础驱动** | `clk_gen` / `seg_scan` / `keypad_scan` | `clk_gen` 需要 `CLK_HZ` 缩放；`keypad_scan` 要覆盖**极性两个方向** |
| **B2 数据** | `pattern_rom` / `piece_rom` / `rng_lfsr` / `buzzer_ctrl` | 大多纯组合，容易收敛 |
| **B3 核心（最难）** | `puzzle_ctrl` / `game_fsm` | `puzzle_ctrl` 有**数组类型端口**（`.vwf` 只能按扁平比特驱动）—— 需专门方案 |
| **B4 集成** | `puzzle_top` 13 场景 + `board_test_top` 9 阶段 | 依赖 B1~B3 |

### 3.4 「收敛」的判据（可数）

一个模块算收敛，当且仅当：

1. **最近一轮全绿**（`sim/rounds/<模块>/r<NN>.json` 的 `all_pass == true`）
2. **连续两轮全绿**（防止"改一处碰巧过"）
3. **断言覆盖 `docs/02` 该模块"仿真验证点"的全部条目**（条数可数）
4. **`OBSERVE` 清单非空**且断言里**没有"恒真式"**（Auditor 复核）

## 4. 轮次记录：可追踪 / 可对比

```
sim/rounds/<模块>/
    r01.md     人看的：断言表 + 实测值 + 波形图链接 + 时间戳 + RTL 补丁清单
    r01.json   机读的：每条断言的 ok / detail，供 diff
    r02.md / r02.json   ...
```

**命令**：

```bash
python scripts/sim.py rounds [<模块>]        # 列出所有轮次（一眼看出哪轮退步）
python scripts/sim.py diff <模块> <N1> <N2>  # 对比两轮：修好了 / 退步了 / 新增
```

> ⭐ **`diff` 的用法**：每改一次 `rtl/` 或 tb，**必跑一次 `run`**，
> 然后 `diff` 上一轮 —— **"改完有没有变好"必须是可数的，不能靠感觉。**
