> 对应实验报告评分项 **④实际实现功能及资源利用（5 分）**
> 器件：**Altera MAX II `EPM1270T144C5`**（144 脚 TQFP，C5 速度等级）

---

## 1. 本文档的可信度基础

引脚号是本项目唯一**"抄错一个数字就全盘报废、而仿真完全查不出来"**的东西：

| 环节 | 能否发现引脚错误 |
|---|---|
| 编写代码 | ✗ 代码里根本不出现引脚号 |
| 综合 / 布局布线 | ✗ 引脚号错了照样编译通过 |
| **功能仿真** | ✗ **仿的是逻辑，不是管脚**，引脚号不参与 |
| 上板 | ✓ 只有到这一步才会暴露 |
| **本机验证** | ✗ **板子只在实验室能用** |

也就是说：**引脚错误的最早暴露时机是"几周后进实验室的那一刻"**，
而那时已经写完了全部代码。这是本项目最大的单点风险。

**应对**：把"手册"与"`.qsf`"用程序钉死在一起逐条比对，
让错误在**敲完引脚号的下一分钟**就暴露，而不是几周后。

```bash
python scripts/check_pins.py
```

**当前结果**（2026-09-17 实测）：

```
权威表（手册）: 67 个引脚
实际约束(.qsf): 67 个引脚

✓ 全部一致：.qsf 与手册逐条吻合
✓ 引脚唯一性：67 个引脚无一重复
```

> **这个脚本本身也做过负向测试**：向 `.qsf` 注入三种典型错误
> （抄错单个引脚号 / 整组位序颠倒 / 漏掉一行），**三种全部被检出**。
> 详见 §6。

## 3. 位序说明 ⭐

> **本节是全项目最关键的一段约定**，详见 `docs/01-系统设计.md` §4.3。

### 3.1 点阵列位序

**手册原文**：

> COLR0~COLR7 依次使用 EPM1270T144C5 芯片的 **22、21、16、15、14、13、12 和 11** 脚。

**推导链**：

```
   硬件：COLR0 接点阵最左列
     ↓
  .qsf：dot_colr[0] = PIN_22
     ↓
   代码：puzzle_pkg 中 bitidx(0, 0) = 0，即 bit0 = 第 0 行第 0 列 = 左上角
     ↓
 驱动层：dot_matrix_scan 把 mask(8r+7 downto 8r) 直接赋给 dot_colr，无翻转
     ↓
   结论：三层天然对齐，全链路零次位序翻转
```

**为什么强调这一点**：如果在这里翻转一次，点阵图案会**左右镜像**。
镜像的图案看起来"完全正常"（就是拼图块左右反了），
**极易被误认为是零片形状设计错误而不是引脚错误**，排查方向会完全跑偏。

### 3.2 数码管位序

```
CAT0 → DISP0 → 最右位
CAT7 → DISP7 → 最左位
```

**据此确定各功能的显示位置**（`docs/02-模块详细设计.md` §11.3）：

| 位 | 显示内容 | 依据 |
|---|---|---|
| DISP7（最左） | 待机显示 `5`；预览时显示预览倒计时 | 要求 2、要求 4 |
| DISP4、DISP3 | 拼图倒计时两位十进制 | 要求 5 |
| DISP0（最右） | 关卡号 | 要求 3 |

> ⚠️ **要求 9 原文写的是 "DISP2"**，但要求 3 规定"第一关显示 1、第二关显示 2"的
> 是待机状态，与要求 9 描述的不是同一场景。经分析认定为原文笔误，
> 统一采用 **DISP0**。详见 `docs/00-需求分析.md` §6 冲突 3。

### 3.3 键盘行列位序

```
实物丝印：ROW3 在最上排，ROW0 在最下排；COL0 最左，COL3 最右

KEY号 = (3 - ROW) * 4 + COL + 1
```

展开成实物布局：

```
             COL0    COL1    COL2    COL3
ROW3:         KEY13   KEY14   KEY15   KEY16      ← 最上排
ROW2:         KEY9    KEY10   KEY11   KEY12
ROW1:         KEY5    KEY6    KEY7    KEY8
ROW0:         KEY1    KEY2    KEY3    KEY4       ← 最下排
```

**据此映射功能键**（`docs/01-系统设计.md` §4.6）：

```
             COL0    COL1    COL2    COL3
ROW3:         —       上       —      开始
ROW2:        左       下      右      选择
ROW1:         —        —       —      确认
ROW0:         —        —       —       —
```

> **方向键居中呈十字**，上下左右四个键聚集在键盘中部，手感接近游戏手柄。
> **`ROW3` 在最上排**是实物丝印确认的事实——若判断反了，方向键会上下颠倒，
> 这是 §7.2 自检清单第 2 项要确认的内容。

## 4. 引脚极性总表

| 器件 | 信号 | 极性 | 若判断错误的后果 |
|---|---|---|---|
| 点阵 | `dot_row` | **低有效** | 整片点亮或全灭 |
| 点阵 | `dot_colr` | 高有效 | 红色不显示或常亮 |
| 点阵 | `dot_colg` | 高有效 | 绿色不显示或常亮 |
| 数码管 | `seg` | 高有效 | 段码全反，显示的图形无法辨认 |
| 数码管 | `cat` | **低有效** | 全灭或多位同时亮 |
| 键盘 | `kp_row` | 按下 = **'1'** | 按键完全无响应 |
| LED | `ld` | 高有效 | 亮灭相反 |
| 开关 | `sw7` | 高 = 开 | 开关逻辑相反 |

**点阵像素点亮条件**：

| 目标颜色 | `dot_row` | `dot_colr` | `dot_colg` |
|---|---|---|---|
| 红 | 低（选中该行） | 高 | 低 |
| 绿 | 低 | 低 | 高 |
| 黄 | 低 | 高 | 高 |
| 灭 | 低 | 低 | 低 |

> **所有极性判断都集中在少数几处**，便于上板后一次改对：
> `dot_matrix_scan` 的两处 `not`、`seg_scan` 的位选取反、`keypad_scan` 的行判断。
> 这是"极性可能出错"这一风险在架构上的应对：**把不确定性关进少数几个地方**。

## 6. 引脚检查脚本的负向测试

> **一个永远通过的检查器等于没有检查器。**
> 因此必须证明它能抓到错误——以下是实测记录。

| # | 注入的错误 | 检查器反应 | 结果 |
|---|---|---|---|
| ① | 抄错单个引脚号（`dot_colr[0]` 改成 `PIN_11`） | 报"引脚号不符 1 处" + "引脚冲突" | ✓ 检出 |
| ② | 整组位序颠倒（`seg[0]` 改成 `PIN_51`） | 报"引脚号不符 1 处" + "引脚冲突" | ✓ 检出 |
| ③ | 漏掉一行（删掉 `kp_row[3]`） | 报".qsf 中缺少 1 处" | ✓ 检出 |

**结论：三类典型误配置全部被检出。**

复现方式：见 `scripts/check_pins.py` 头部注释；
检查器同时做**引脚唯一性检查**（同一引脚分配给两个信号会报冲突）。

## 8. 未使用引脚的处理

```tcl
set_global_assignment -name RESERVE_ALL_UNUSED_PINS "AS INPUT TRI-STATED"
```

**设为输入三态的理由**：未使用引脚若默认为输出，可能与其他器件（液晶、PS/2 等）
的输出脚对驱，造成大电流甚至损坏。设为输入三态是 MAX II 的安全默认值。

## 9. 引脚号的三方交叉验证记录

> **对应 `ERRORS.md` ERR-0003。**

除手册外，本机桌面上还有 9 个针对**同一块板**的历史 Quartus 工程可作旁证：

| 引脚组 | 手册 | 9 个旧工程 | 结论 |
|---|---|---|---|
| 时钟 / 开关 | 18 / 125 | 一致 | ✓ |
| 点阵行 | 8…1 | 一致 | ✓ |
| 点阵红列 | 22、21、16…11 | **其中一个旧工程恰好相反** | ✗ 见下 |
| 点阵绿列 | 45…38 | 一致 | ✓ |
| 数码管段 / 位选 | 62…51 / 63…31 | 一致 | ✓ |
| 键盘 | 117…120 / 111…114 | 一致 | ✓ |

**唯一的分歧**：`dot_matrix_pwm` 工程把 `col_r[0]` 接在 `PIN_11`（即手册的 `COLR7`），
整组红列位序与手册完全镜像。

**判断**：该工程**自身是自洽的**（它的代码里也做了对应的位序处理），
但它的引脚表**已不再对应板上丝印**。若照抄它，点阵图案会左右镜像。

**结论与规则**：

> **引脚号只认开发板手册。**
> 旧工程**只能**用来交叉验证"用到了哪些引脚"（数量、分组、是否遗漏），
> **不能**用来确定位序。

**这条规则的代价**：如果手册与实物不符，错误要到实验室才能发现。
**收益**：不会因为盲目信任一个"能跑"的旧工程而引入镜像错误。
**兜底**：§7.2 的自检工程第 3 项专门验证列序。
