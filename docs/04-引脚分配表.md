## 1. 本文档的可信度基础

引脚号是本项目唯一**"抄错一个数字就全盘报废、而仿真完全查不出来"**的东西：

| 环节 | 能否发现引脚错误 |
|---|---|
| 编写代码 | ✗ 代码里根本不出现引脚号 |
| 综合 / 布局布线 | ✗ 引脚号错了照样编译通过 |
| **功能仿真** | ✗ **仿的是逻辑，不是管脚**，引脚号不参与 |
| 上板 | ✓ 只有到这一步才会暴露 |
| **本机验证** | ✗ **板子只在实验室能用** |

也就是说：**引脚错误的最早暴露时机是"几周后进实验室的那一刻"**，
而那时已经写完了全部代码。这是本项目最大的单点风险。

**应对**：把"EXPECTED 表"与"`.qsf`"用程序钉死在一起逐条比对，
让"抄进 `.qsf` 时敲错"在**敲完引脚号的下一分钟**就暴露，而不是几周后。

> ⚠️ **这个保证的边界要说清楚**（2026-09-18 审查 `hw-02` 修正）：
> `scripts/check_pins.py` 的 `EXPECTED` 表本身是**手抄件** —— 脚本只能证明
> "`.qsf` == `EXPECTED`"，**证明不了"`EXPECTED` == 手册"**。若转录时抄错一个数字，
> 脚本照样报"✓ 全部一致"，`--markdown` 还会把同一个错数字渲染进 §2 的表：
> `EXPECTED` / `.qsf` / §2 表**三份产物互为同一错源的副本**，谁也证不了谁。
> 转录正确性目前只有三样旁证：§2 表内 COLR 组的手册原文引文、§9 的 9 个旧工程
> 交叉核对（**只可比引脚集合，不可比位序**）、§7.2 的上板自检。
> **待办**：把板手册的引脚对照页拍照存 `docs/图/`（板手册 PDF 未入库），
> 并给 `EXPECTED` 每个分组补手册原文引文 —— 让后续会话能对着原件复核，而不靠记忆。

```bash
python scripts/check_pins.py
```

**当前结果**（2026-09-18 实测，补入 BTN0 后复跑）：

```
权威表（手抄自手册）: 68 个引脚
实际约束(.qsf): 68 个引脚

✓ 全部一致：.qsf 与 EXPECTED 表逐条吻合（EXPECTED 为手抄件，见脚本头部 ⚠️ 说明）
✓ 引脚唯一性：68 个引脚无一重复
```

> **这个脚本本身也做过负向测试**：向 `.qsf` 注入三种典型错误
> （抄错单个引脚号 / 整组位序颠倒 / 漏掉一行），**三种全部被检出**。
> 详见 §6。

## 3. 位序说明 ⭐

> **本节是全项目最关键的一段约定**，详见 `docs/01-系统设计.md` §4.3。

### 3.1 点阵列位序

**手册原文**：

> COLR0~COLR7 依次使用 EPM1270T144C5 芯片的 **22、21、16、15、14、13、12 和 11** 脚。

**推导链**：

```
   硬件：COLR0 接点阵最左列   ← ⚠️ 这一句是【假设】，不是已知事实
     ↓
  .qsf：dot_colr[0] = PIN_22
     ↓
   代码：puzzle_pkg 的位序约定「bit 号 = 8×行 + 列」，故 bit0 = 第 0 行第 0 列 = 左上角
     ↓
 驱动层：dot_matrix_scan 把 mask(8r+7 downto 8r) 直接赋给 dot_colr，无翻转
     ↓
   结论：三层天然对齐，全链路零次位序翻转
```

**为什么强调这一点**：如果在这里翻转一次，点阵图案会**左右镜像**。
镜像的图案看起来"完全正常"（就是拼图块左右反了），
**极易被误认为是零片形状设计错误而不是引脚错误**，排查方向会完全跑偏。

### 3.2 数码管位序

```
CAT0 → DISP0 → 最右位
CAT7 → DISP7 → 最左位
```

**据此确定各功能的显示位置**（`docs/02-模块详细设计.md` §11.3）：

| 位 | 显示内容 | 依据 |
|---|---|---|
| DISP7（最左） | 待机显示 `5`；预览时显示预览倒计时 | 要求 2、要求 4 |
| DISP4、DISP3 | 拼图倒计时两位十进制 | 要求 5 |
| DISP0（最右） | 关卡号 | 要求 3 |

> ⚠️ **要求 9 原文写的是 "DISP2"**，但要求 3 规定"第一关显示 1、第二关显示 2"的
> 是待机状态，与要求 9 描述的不是同一场景。经分析认定为原文笔误，
> 统一采用 **DISP0**。详见 `docs/00-需求分析.md` §6 冲突 3。

### 3.3 键盘行列位序

```
实物丝印：ROW3 在最上排，ROW0 在最下排；COL0 最左，COL3 最右

KEY号 = (3 - ROW) * 4 + COL + 1
```

展开成实物布局（**按公式逐格代入**）：

```
             COL0    COL1    COL2    COL3
ROW3:         KEY1    KEY2    KEY3    KEY4       ← 最上排
ROW2:         KEY5    KEY6    KEY7    KEY8
ROW1:         KEY9    KEY10   KEY11   KEY12
ROW0:         KEY13   KEY14   KEY15   KEY16      ← 最下排
```

> ⚠️ **2026-09-18 审查修正**：原展开表与自身公式**上下颠倒**（把最上排写成了 KEY13~16）。
> 已按公式更正——更正后功能键键号（上=KEY2、开始=KEY4、左=KEY5、下=KEY6、右=KEY7、
> 选择=KEY8、确认=KEY12）与 `docs/02` §12.2 译码表、§12.9 验证点 11 完全一致。
> **物理丝印的最终确认**由 `board_test_top` 自检完成（`docs/01` §8.2）：若实测发现
> 丝印编号方向相反，则要改的是**公式与译码表**，而不是本表。
>
> ✅ **上方更正后的表已用课程课件 PDF p55 独立复核过一次**（2026-09-18 晚）：
> 课件示例表给出 `KEY1 = COL0×ROW3`、`KEY2 = COL1×ROW3`、`KEY5 = COL0×ROW2`、
> `KEY9 = COL0×ROW1`、`KEY13 = COL0×ROW0`、`KEY6 = COL1×ROW2`，
> **逐条代入本页公式全部吻合** → 公式与更正后的展开表**双双得到第三方证实**。
> 那次"上下颠倒"之所以危险，正因为**它自己也自洽**（表与公式各自都成体系，
> 只有把两者并排代入同一格才现形）。

**据此映射功能键**（`docs/01-系统设计.md` §4.6）：

```
             COL0    COL1    COL2    COL3
ROW3:         —       上       —      开始
ROW2:        左       下      右      选择
ROW1:         —        —       —      确认
ROW0:         —        —       —       —
```

> **方向键居中呈十字**，上下左右四个键聚集在键盘中部，手感接近游戏手柄。
> **`ROW3` 在最上排**是实物丝印确认的事实——若判断反了，方向键会上下颠倒，
> 这是 §7.2 自检清单第 2 项要确认的内容。

## 4. 引脚极性总表

> ⭐ **2026-09-24：本表已逐条与本板手册原文核对通过**（手册 PDF 一直在仓库根目录，
> 只是被 `.gitignore` 排除；用 `pypdf` 抽出文本后核对）。原文见本节末「手册原文摘录」。

| 器件 | 信号 | 极性 | 若判断错误的后果 |
|---|---|---|---|
| 点阵 | `dot_row` | **低有效** | 整片点亮或全灭 |
| 点阵 | `dot_colr` | 高有效 | 红色不显示或常亮 |
| 点阵 | `dot_colg` | 高有效 | 绿色不显示或常亮 |
| 数码管 | `seg` | 高有效 | 段码全反，显示的图形无法辨认 |
| 数码管 | `cat` | **低有效** | 全灭或多位同时亮 |
| 键盘 | `kp_row` | 按下 = **'1'** | 按键完全无响应 |
| 按键 | `btn` | 按下 = **'1'** | 复位逻辑相反（2026-09-18 补） |
| LED | `ld` | 高有效 | 亮灭相反 |
| 开关 | `sw7` | 高 = 开 | 开关逻辑相反 |
| 蜂鸣器 | `buzz` | 方波输出、**静音 = `'0'`** | 若相反，**SW7=0 时反而长鸣**（要求 1 的"全灭"不成立）。⚠️ 蜂鸣器是唯一"静音取决于电平选择"的器件，此前不在本表（2026-09-18 审查 / `buzzer_ctrl-4`） |

**点阵像素点亮条件**：

| 目标颜色 | `dot_row` | `dot_colr` | `dot_colg` |
|---|---|---|---|
| 红 | 低（选中该行） | 高 | 低 |
| 绿 | 低 | 低 | 高 |
| 黄 | 低 | 高 | 高 |
| 灭 | 低 | 低 | 低 |

> **所有极性判断都集中在少数几处**，便于上板后一次改对：
> `dot_matrix_scan` 的**行** `not`、`seg_scan` 的**位选** `not`（两处分属两个模块、**各一处**）、`keypad_scan` 的行判断。
> —— ⚠️ 2026-09-18 审查 `hw-05` 订正：原写"`dot_matrix_scan` 的两处 `not`"，照字面去该模块只找得到一处
> （另一处 `not` 是相位翻转 `r_blank_ph`，与极性无关）；位选那处其实在 `seg_scan`，且同一句里已单列 → 属重复计数。
> 这是"极性可能出错"这一风险在架构上的应对：**把不确定性关进少数几个地方**。

> ⚠️ **键盘扫描极性存在两份来源的矛盾**（2026-09-18 审查记录）：
> 课程 PDF p55 的示例表按**低有效**扫描（COL 驱 `1110`、ROW 读 `0111` 表示 KEY1），
> 而开发板手册的电路（列 10k 上拉、行 4.7k 下拉）对应**高有效**（驱列为高、读行为 1）。
> 本设计按**板手册**实现；PDF 示例是教学法示意，**最终以 §7.2 自检第 7/8 项的上板实测为准**
> —— 若实测相反，只需翻转 `keypad_scan` 中集中的极性判断点（§4.4 ①的 `i_kp_row(r) = '1'`）。

### 4.1 限流保护（课件 p45（二）的正式落点）

课件 p45（二）："**限流保护**：数码管、发光二极管、点阵、按键等要加限流保护电阻"

## 7. 上板前必须逐条确认的引脚相关项

> 板子只在实验室能用，**每次去实验室前把这张表打印出来**。

### 7.1 引脚连通性（用 §7.2 的自检工程一次跑完）

| # | 检查项 | 方法 | 期望现象 |
|---|---|---|---|
| 1 | 时钟档位 | 观察板上 LED 指示 | 档位 **7**（50MHz） |
| 2 | 点阵行序 | 自检程序逐行点亮 | 从上到下依次亮 |
| 3 | 点阵列序 | 自检程序逐列点亮红色 | **从左到右**依次亮 |
| 4 | 点阵红绿 | 自检程序切换红/绿 | 颜色正确不互换 |
| 5 | 数码管位序 | 自检程序逐个显示 | DISP0（**最右**）先亮 |
| 6 | 数码管段序 | 依次显示 `1 2 3 4 5 6 7 8` | 数字形状正确 |
| 7 | 键盘行列 | 按任意键，对应 LED 亮 | 键号与丝印一致 |
| 8 | 键盘极性 | 同上 | 按下有响应（不是松手才响应） |
| 9 | 蜂鸣器 | 自检程序交替发声（500 Hz ↔ 2 kHz 各 1 秒） | **能听出高低**（证明无源、频率可控）；且该阶段之前应完全无声（静音电平 = '0'） |
| 10 | **BTN0 复位键** | 按住 **BTN0**（= `btn` = **PIN_61** = **8 个按键里最右边那个**） | **16 个 LED 全亮；松开后自检从阶段 1 重来** ← 课件 p45（一）"复位必须用按键实现"的唯一实测点。<br>⚠️ **不是 16 个全亮就说明 `btn` 没读到 `'1'`** —— 这一路是**直读**，不受 SW7 门控，所以**能**在 SW7=0 时单独验（见 ERR-0030） |
| 11 | **SW7 系统开关** | 拨到 0 再拨回 1 | 拨 0 → **数码管全灭、点阵全灭、蜂鸣器无声**；拨回 1 → 从开机自检重新开始。<br>⚠️ **`ld` 不在门控之列**（`board_test_top` 的输出级只门控 `seg`/`cat`/`dot_*`/`buzz` 六项），所以 SW7=0 时 LED 会**停在阶段 1 的画面**：`ld[15:8]="0000_0001"` → **只有 LD8 亮**，其余 15 个灭。**这是预期现象**，不是"没关干净"——2026-09-24 首次上板时误报过一次，见 `ERRORS.md` ERR-0030。<br>**若相反，只需在 `clk_gen` 的 `sys_en` 与顶层门控处一并取反**（一处集中改）。<br>⚠️ **2026-09-18 审查补**：要求 1 的整机使能 + 复位第三源，此前**不在任何上板清单里**（ERR-0020 / 报告 `CRIT-3`） |

## 8. 未使用引脚的处理

```tcl
set_global_assignment -name RESERVE_ALL_UNUSED_PINS "AS INPUT TRI-STATED"
```

**设为输入三态的理由**：未使用引脚若默认为输出，可能与其他器件（液晶、PS/2 等）
的输出脚对驱，造成大电流甚至损坏。设为输入三态是 MAX II 的安全默认值。

## 9. 引脚号的三方交叉验证记录

> **对应 `ERRORS.md` ERR-0003。**

除手册外，本机桌面上还有 9 个针对**同一块板**的历史 Quartus 工程可作旁证：

| 引脚组 | 手册 | 9 个旧工程 | 结论 |
|---|---|---|---|
| 时钟 / 开关 | 18 / 125 | 一致 | ✓ |
| 点阵行 | 8…1 | 一致 | ✓ |
| 点阵红列 | 22、21、16…11 | **其中一个旧工程恰好相反** | ✗ 见下 |
| 点阵绿列 | 45…38 | 一致 | ✓ |
| 数码管段 / 位选 | 62…51 / 63…31 | 一致 | ✓ |
| 键盘 | 117…120 / 111…114 | 一致 | ✓ |
| 复位键 BTN0 | 61 | 一致 | ✓（2026-09-18 补入） |

**唯一的分歧**：`dot_matrix_pwm` 工程把 `col_r[0]` 接在 `PIN_11`（即手册的 `COLR7`），
整组红列位序与手册完全镜像。

**判断**：该工程**自身是自洽的**（它的代码里也做了对应的位序处理），
但它的引脚表**已不再对应板上丝印**。若照抄它，点阵图案会左右镜像。

**结论与规则**：

> **引脚号只认开发板手册。**
> 旧工程**只能**用来交叉验证"用到了哪些引脚"（数量、分组、是否遗漏），
> **不能**用来确定位序。

**这条规则的代价**：如果手册与实物不符，错误要到实验室才能发现。
**收益**：不会因为盲目信任一个"能跑"的旧工程而引入镜像错误。
**兜底**：§7.2 的自检工程第 3 项专门验证列序。
